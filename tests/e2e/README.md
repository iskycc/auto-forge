# AutoForge E2E coverage matrix

`coverage-matrix.json` is the machine-readable source of truth for M11 browser and production acceptance coverage. A row is only `covered` when its evidence enters through the real user, Agent, or operations boundary and observes the final business result. Unit tests, direct repository calls, readiness-only probes, and a Playwright process impersonating Runner Agent may remain useful evidence, but are marked `partial`.

The suite is divided by failure domain so each scenario can run alone with an isolated platform data directory:

`tests/e2e/platform-initialization.spec.ts` starts its own fresh Lite platform on a loopback port, with external deployment settings removed from its child environment. It exercises the grouped Full setup form: Ctrl+V / Shift+Insert, oversized-input rejection without truncation, selection replacement, a rejected connection, independent log settings, local log selection and persisted configuration. It captures light/dark screenshots at 1024px and 1536px. Build Web before running this source scenario; it is included in `pnpm test:e2e` and the source CI governance group.

Set `AUTOFORGE_E2E_SETUP_DATABASE_URL` to a test PostgreSQL connection with database-creation permission, together with the existing `AUTOFORGE_TEST_POSTGRES_URL`, `AUTOFORGE_TEST_REDIS_URL`, `AUTOFORGE_TEST_NATS_URL`, `AUTOFORGE_TEST_MINIO_ENDPOINT`, `AUTOFORGE_TEST_MINIO_ACCESS_KEY` and `AUTOFORGE_TEST_MINIO_SECRET_KEY`, to additionally verify successful checks for all five components, a real Full restart, administrator creation and active daily log registration. The test creates and drops a unique business database without overwriting the supplied database. The log maintenance connection comes from `AUTOFORGE_TEST_POSTGRES_URL`; use a maintenance database separate from business data. Optional `AUTOFORGE_TEST_NATS_TOKEN` supplies NATS authentication; `AUTOFORGE_E2E_SETUP_MINIO_BUCKET` selects an existing bucket (default `autoforge-objects`).

`packages/object-store/test/platform-infrastructure-check.integration.test.ts` uses the same `AUTOFORGE_TEST_*` services and covers actual authentication failure, a missing bucket and bounded cleanup when a service accepts a connection without responding. It is included in the Full adapter acceptance group.

CI runs the UI interaction suite in three test-level Playwright shards, each with its own data directory and one browser worker. The union retains every original UI/tab-navigation test; the primary-route traversal remains a separate scenario. UI shards build the real bundled Agent/Adapter resources before starting Web because Runner update controls require a validated resource manifest. SSH probe/update responses in the layout scenario remain deterministic fixtures; actual installation is covered separately.

Entrypoints that are not yet present remain `planned` in the JSON and must not be described as passing. High-CPU and privileged entrypoints run only in GitHub Actions. Local development is limited to formatting, static validation and explicitly selected lightweight tests. `pnpm test:distributed` is also available locally with Docker and a preinstalled Chromium. Its log fixture verifies peer transport and browser access; it does not replace real Runner Agent business recovery acceptance.
