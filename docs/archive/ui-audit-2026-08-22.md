# UI / 交互问题清单（2026-08-22 归档）

> 本文是基于提交 `074ad90` 的历史审计快照，不是当前缺陷列表，也不能据此判断现版本仍存在对应问题。
> 当前项目状态和待办以 [`project-roadmap.md`](../project-roadmap.md) 为准；需要重新处理本文条目时，应先在当前版本复现并建立新的跟踪项。

来源：2026-08-22 在本地 Lite 部署（`074ad90`，端口 3200）上用 Playwright 以管理员身份遍历全部主要页面并截图（截图存于 `test-results/ui-audit/`）。以下按页面分组，标注严重度：【高】= 逻辑矛盾/误导/高风险误操作，【中】= 明显不友好，【低】= 美观或细节。

## 全局 / 导航

- [ ] 【高】品牌主色为红色，"开始执行 / 创建任务 / 导入 JAR / 保存修改 / 批量更新"等普通主操作与"删除来源 / 撤销凭据 / 禁用"等破坏性操作同色同级，无法区分危险程度，容易误点。
- [ ] 【中】同一内容双入口：侧边栏有"执行节点"和"执行机组"两项，而"执行节点"页内还有"执行机 / 执行机组"页签；"运维计划"页内含"安全审计"页签，侧边栏也有"安全审计"。导航层级混乱。
- [ ] 【中】顶栏右侧一排无文字图标按钮（通知铃、问号、链接、紫色图标），无 tooltip、无可访问名称，功能只能靠猜。
- [ ] 【中】`/progress/[batchId]`（公开进度页）缺少 token 时直接渲染 Next 默认英文 404（"This page could not be found"），中文产品里出现裸英文错误页且无返回导航。
- [ ] 【低】未登录访问 `/landing` 直接跳 `/login`，公开落地页实际不可见；登录后先落 `/landing` 再跳 `/`，多一次跳转。
- [ ] 【低】顶栏搜索框提示"搜索用例、⌘K"，但 Ctrl/⌘K 只是聚焦该输入框，并没有命令面板，暗示与实际不符。

## 工作概览（首页）

- [ ] 【高】"执行机组"卡片自相矛盾：标题角标"在线 1/1"，正文却是"尚未配置执行机组"空状态，下方统计又显示"总执行机 1 / 在线 1 / 可用槽位 2"。Runner 与机组两个概念在同一张卡里混算。
- [ ] 【高】"失败洞察"环图中心显示"0 失败方法"，同卡下方却列出"TestNG exited with… 10 次 / 4 次 / 2 次"高频失败 Top 3——0 与非零并存。
- [ ] 【中】"本周质量 0.0/100（基于 17 次已确认执行样本）"，下方趋势区却"暂无趋势数据"，大面积空白且信息互相打架。
- [ ] 【低】"通过率 0.0% ↑ 0.0%"：零变化也渲染上升箭头，误导。
- [ ] 【低】"最近动态"条目名统一截断成"每日冒…"，且有两条完全相同的"执行失败 08/17 00:48"，无法区分；"活动执行"卡中"执行中·1 台执…"同样截断。

## 执行记录 / 批次详情

- [ ] 【高】已进入终态的批次（如 #1 "执行异常"），"已运行时长"仍显示 44h 36m 3s 并随当前时间持续增长——终态时长应定格在结束时刻；列表页"耗时 44h …"同病，且被截断。
- [ ] 【高】批次详情头部"失败 4"与轮次表"失败数 2、未执行数 2"口径不一致，用户无法判断哪个是真的。
- [ ] 【中】Runner 列显示截断的原始 UUID（"01a00…"）而非 Runner 名称；用例详情"执行历史"的 Runner 列更是直接展示完整 UUID。
- [ ] 【中】同一批次 4 行用例全部显示"CheckoutTest / com.example.CheckoutTest"，缺方法名列，无法区分（重载方法的 JVM descriptor 也未展示）。
- [ ] 【中】轮次表同时存在"总结 / 全部轮次 / 初始轮次"三行，仅 1 轮时前两行纯冗余且数值相同。
- [ ] 【中】"本轮结果分布"环图图例只有 通过/失败/超时/进行中/取消，没有"未执行"；中心"2 已执行"与表格"2 超时 + 2 未执行"的对应关系要靠用户自己心算。
- [ ] 【中】行内"查看日志 / 公开日志 / 详情"三个按钮并列，"公开日志"（生成任何人可访问的分享链接）与普通查看操作同等突出，有误点外泄风险。
- [ ] 【中】执行记录表格列宽不足："批次编…""执行机…"表头被自身截断。
- [ ] 【中】筛选区"用例 ID"、质量洞察"批次对比"的"基准批次 ID / 对比批次 ID"都要求手填原始 UUID，但列表里只展示 #1..#5 编号，ID 指代不明，普通用户无从下手。
- [ ] 【低】批次 #5 创建于 2026/08/17 仍显示"执行中"（截图时为 08/22），疑似重启后状态未恢复或恢复中无提示，界面没有任何"停滞"标识。

## 用例管理 / 任务

- [ ] 【高】同名对象无法区分：用例树中来自不同来源的多个"CheckoutTest"包路径被截断为"com.exampl…"；任务列表三个"每日冒烟测试"除用例数外完全相同（无创建时间、版本、状态等辅助区分信息）。
- [ ] 【中】"开始执行"弹窗选择任务"每日冒烟测试 · 4 个用例 · v2"后，摘要显示"执行资源：尚未配置，请先编辑任务"，而该任务详情页里明明配置了指定执行机 smoke-agent-3200——疑似读取了旧版本快照，摘要与事实不符。
- [ ] 【中】用例列表工具行把"导入用例"按钮和灰色说明"可批量加入任务"挤在一行，阅读顺序混乱；"加入任务"用红色主按钮。
- [ ] 【中】禁用态按钮是浅红色（如"扫描测试类""解析并预览"），视觉上很像可点击。
- [ ] 【中】任务详情表单极长（两屏以上），且拆成"保存修改 / 保存计划"两个互不相邻的保存按钮，改完上半部分很容易忘记下面还有独立保存。
- [ ] 【中】任务详情默认"排队超时 1440 分钟 / 领取超时 5 分钟 / 上传超时 10 分钟"，三个超时量级悬殊且无任何说明，用户难以理解各自约束什么阶段。
- [ ] 【低】用例/任务详情里"启用"与"归档"两个复选框并排、各自带长句说明，语义有重叠，分不清该勾哪个。

## 执行机

- [ ] 【高】"自动安装执行机 Agent"卡片展示"Agent 控制面 http://127.0.0.1:3200"——回环地址作为安装目标对其他主机毫无意义，应展示平台配置的外部访问地址。
- [ ] 【中】执行机卡片底部一排 7 个操作（终端浮窗 / 更新 / 排空 / 禁用 / 轮换凭据 / 撤销凭据 / 注销），破坏性操作与普通操作混排，其中两个红色，极易误触。
- [ ] 【低】能力标签被截断成"adapter:cotest-testng-…"，信息不完整。

## 质量洞察

- [ ] 【中】失败原因条目直接展示英文原始堆栈行（"TestNG exited with code 1. | Exception in thread "main" java.lang.ClassFormatError: …"），超长截断后"4 次"折行，可读性差。
- [ ] 【中】"每日趋势"标题行写"UTC · 0 个方法结果 · 17 次执行"，图区却是"当前筛选范围还没有已确认执行结果"——17 次执行与 0 结果并存，统计口径令人困惑。
- [ ] 【中】"当前层级用例执行情况"6 行全部同名"CheckoutTest"，无法区分；"最近执行时间"用 UTC ISO 毫秒格式（2026-08-17T01:41:26.564Z），与其它页面的本地时间格式不一致。

## 安全审计

- [ ] 【高】审计事件"操作者"列显示原始 UUID 而不是用户名；资源、项目列同样是 UUID——审计是最需要可读性的场景，当前需要人工对照数据库才能看懂。
- [ ] 【中】筛选条件"操作者 ID"要求手填 UUID；"动作"是自由文本（例如 auth.login），无下拉枚举。
- [ ] 【中】分页只有底部孤零零一个"下一页"按钮，没有上一页、页码或总数；单页渲染上百行，整页近 8000px 高。
- [ ] 【低】UTC 时间精确到毫秒（2026-08-21T19:58:05.203Z），列表级展示过于噪。

## 通知中心

- [ ] 【中】"执行批次已完成 每日冒烟测试：failed"——中文标题混排英文状态码，"已完成：failed"语义别扭，应译为"执行失败"。
- [ ] 【中】"Runner 已离线"通知中的时间戳是被截断的 UTC ISO 串（"2026-08-16T16:50:24.22…"），与同列表"08/17 09:41"的短格式混用。
- [ ] 【低】无"全部已读"、无分页，通知一屏堆叠。

## 平台与系统设置

- [ ] 【中】平台配置页把服务器绝对路径（/opt/auto-forge/.lite-data/config/platform.json）直接展示在浏览器端，泄露部署内部结构。
- [ ] 【中】"部署模式"做成可交互下拉框（Lite · SQLite 与本地对象），容易让人误以为可随手切换；按约定 Lite/Full 应为只读部署信息。
- [ ] 【中】用户管理页顶部"重置密码"按钮没有选中目标，不知道作用于哪个用户；用户行内直接展示 UUID。
- [ ] 【低】项目管理页"转移负责"按钮文案被截断（应为"转移负责人"）；项目行展示完整项目 UUID。

## 日志 / 终端弹窗

- [ ] 【中】attempt 日志窗标题"attempt 01a001e4 · stdout"使用截断 ID + 技术黑话；过滤区两个"选择日期与时间"输入框上下排列，没有"开始 / 结束"标注，分不清哪个是哪个。
- [ ] 【低】日志窗使用 macOS 风格红黄绿装饰圆点，与整体 Apple-like 但非 Mac 应用的语境略突兀（主观）。

## 其它观察（非缺陷但可改进）

- [ ] "开始执行"弹窗摘要区 label 与值上下错位缩进（"执行资源\n 尚未配置…"），对齐不一致。
- [ ] 创建任务弹窗中"使用 CoTest TestNG Adapter"未勾选时，Adapter Suite Name / Test Name / 环境地址等字段仍以禁用态全量展示，建议收进勾选后再展开。

## 第二轮（富数据）补充发现 — 2026-08-22

来源：造数后（18 用户 / 8 执行机 / 36 用例 / 11 任务 / 53 批次 / 631 执行 / 507 分析事实 / 2 项目）再次遍历截图（`test-results/ui-audit-2/`、`ui-audit-3/`、`ui-audit-4/`）。与第一轮重复的条目不再列出；标注"造数放大"的条目需用真实执行数据复核。

### 项目与顶栏

- [ ] 【高】新建项目后，全新浏览器会话默认落在**最新创建的项目**（支付中台）而非"默认项目"；该项目无测试阶段时顶栏阶段下拉显示"暂无阶段"，各业务页面全空——用户极易误判为数据丢失。默认选择应固定为"默认项目"或可靠记住上次选择并给出明显提示。
- [ ] 【中】项目与成员页只展示"顶栏当前选中项目"的成员，页面内没有项目切换入口；要管理另一个项目的成员必须先去顶栏切换项目，路径不直观。

### 执行记录 / 批次详情

- [ ] 【高】富数据下批次列表**横向溢出且无横向滚动**：最右"操作"列被卡片裁掉（表头只剩"操"字），"批次编…/已失…/执行机"等表头被自身截断，操作按钮实际不可见。
- [ ] 【中】"耗时"列对非终态批次显示文字"执行中"而不是已运行时长，与"状态"列语义串列。
- [ ] 【中】批次详情头部"当前轮次"单元格内容截断为"第 3 轮 · 用例重跑…"。
- [ ] 【中】批次详情默认选中最后一轮；当该轮为空时详情面板环图"0 已执行"与左侧"总体通过进度 100% 累计通过 36"同屏矛盾（本轮空数据部分由造数脚本 current_round 与实际轮次不一致放大，需真实重跑复核）。
- [ ] 【中】轮次用例表"耗时"列宽不足，"1 min 37 s"折行成"1 min ·/s"，秒数被挤压换行。
- [ ] 【低】批次列表底部分页是"查看更早记录"load-more，而安全审计是孤零零的"下一页"——两个核心列表的分页交互不一致，且都没有总数/页码。
- [ ] 【低】批次状态徽标文字被截断（"已生成…"）。

### 用例管理 / 任务

- [ ] 【中】任务列表对"已归档 / 已停用"任务（如"移动端 H5 冒烟"归档、"历史遗留模块回归"停用）**无任何视觉区分**，也无排序、搜索、分页，11 个任务一屏到底。
- [ ] 【中】用例详情"执行历史 / 分析历史"结果列直接展示原始枚举码 `TESTNG_SUCCEEDED` / `TESTNG_EXIT_NONZERO`，未翻译为用户语言。
- [ ] 【中】超长类名（VeryLongClassNameForTestingUiTruncation…）详情页标题整块多行换行挤压首屏，无截断/折叠策略。

### 开始执行弹窗

- [ ] 【中】任务摘要显示"执行资源：尚未配置，请先编辑任务"时，"确认并开始执行"仍可点击，未在提交前阻断或给出二次确认。
- [ ] 【低】"单个用例"页签自动预选列表第一个用例，用户不留意就会带错用例；离线执行机复选框仍可勾选且显示"可用槽位 2"，易误解为可立即执行。

### 运维计划（计划任务总览）

- [ ] 【高】"用例任务"列把任务名与原始 UUID **无分隔直接拼接**："每日冒烟测试01a001e4-40c6-7959-875c-a3bd4895647b"，超长英文名任务粘连三行，完全无法阅读。
- [ ] 【中】"Cron / 时区"挤在一列，折行后变成"0 2 * _\n_ Asia/Shanghai"——cron 表达式被从中间断开，极易误读。
- [ ] 【中】"上次 / 下次触发"两个时间粘连成"2026年8月20日 04:19:35下次：2026年8月22日 08:19:35"。
- [ ] 【中】计划任务只有"暂停 / 启用"操作，页面上找不到编辑 cron、删除、立即触发入口，管理闭环不完整。

### 执行机

- [ ] 【中】7 台执行机全部整卡纵向堆叠（页面近 3000px），无紧凑列表视图、搜索或按状态筛选；6 台离线机器与在线机器混排。
- [ ] 【低】离线机器同样显示"可更新至 0.2.2"和"批量更新"入口，无法判断更新通路是否可达。
- [ ] 【低】执行机组页页面副标题（"按机房、网络或能力组合执行机…"）与卡片列表上方说明（"按机房、网络区域或能力维护可复用资源池"）语义重复。

### 首页（富数据后）

- [ ] 【中】"失败数 59"下方红色"33.5%"子标签含义不明（失败率还是环比），与通过率卡"↓ 17.0%"的语义不对齐。
- [ ] 【低】趋势图 x 轴日期标签稀疏不均（08-15、08-19…），无数据日期直接缺柱（部分由造数分布放大，但轴标签策略本身可疑）。
- [ ] 【低】"最近动态"出现"执行已生成分配 / 执行等待资源 / 执行分配中"等内部状态黑话文案。

### 质量洞察

- [ ] 【中】失败原因把调度内部错误（"Assignment was not claimed before its deadline." 117 次）与真实测试失败混排展示（造数+调度 churn 放大，但内部错误本不应计入用例失败原因）。

### 文件来源

- [ ] 【中】"纳管文件"对象浏览器把完整对象键（三折行的长 UUID 路径）作为蓝色链接原文展示，且无下载/删除等操作列，只有"本页 6 个对象"。
- [ ] 【中】JAR 来源列表中多个同名 JAR（checkout-tests.jar）仅靠截断摘要和导入时间区分，无版本/标签列。

### 访问管理 / 账号安全

- [ ] 【中】用户管理"已分配角色"列宽不足，"▶ 1 个绑定"折行成"1 个绑 / 定"。
- [ ] 【低】访问管理"登录会话"页只显示创建/活动/过期时间，无会话标识、无 IP/UA、无"当前会话"标记；与"账号安全"页的会话表（有会话 ID 和"当前会话"标记）不一致。

### 平台设置

- [ ] 【中】LDAP 未启用（"启用 LDAP 登录"未勾选）时整份 LDAP 表单仍可编辑，服务器地址预填示例值，"Bind 密码"仍标"必填"，启用状态与表单状态脱节。

### 全局搜索 / 弹窗 / 其它

- [ ] 【中】全局搜索结果中 7 条同名"CheckoutTest / com.example.CheckoutTest"完全一致无法区分；"执行"类条目副标题直接是英文状态"queued"。
- [ ] 【低】"总体调度日志"弹窗空状态时整窗黑色大面积留白，仅左上角一行"暂无调度日志"。
