# AutoForge 待办路线图

> 基线日期：2026-08-09。本路线图只记录当前尚未完成或尚未达到生产验收标准的事项；README 中的目标架构不代表已经实现。完成事项必须同时满足本文的通用完成标准，不能仅以“页面可见”或“能够编译”勾选完成。

## 1. 使用规则

优先级定义：

- `P0`：安全边界或核心执行闭环的前置事项，没有完成就不应宣称平台可生产使用。
- `P1`：完整产品能力，完成后才能达到 AutoForge 的总体目标。
- `P2`：规模化、体验或增强能力，不阻塞最小生产闭环。

建议按以下依赖顺序推进：

```text
架构决策与安全基线
  ├─> 身份、LDAP、用户与权限
  └─> 执行契约与状态机
          └─> Agent 领取、执行、日志与产物
                  └─> Lite/Full 队列和后台工作器
                          ├─> 执行页面与运维闭环
                          └─> 分析与洞察

以上能力稳定后 -> 离线安装、升级、备份恢复与生产验收
```

每个事项的通用完成标准：

- 领域规则、应用用例、API 契约和 UI 在 Lite/Full 间共享，模式差异只存在于组合根和基础设施适配器。
- Lite 不连接或加载 PostgreSQL、NATS、MinIO、Redis；Full 不用缓存或队列代替 PostgreSQL 中的业务事实。
- LDAP 是可选的企业身份适配器；未配置时 Lite 仍只依赖 SQLite 和本地文件，启动过程不得探测目录服务。
- 输入、环境变量、协议消息和数据库映射在边界校验；错误包含稳定机器码和 `requestId`，不暴露堆栈或秘密。
- SQLite/PostgreSQL 分别提供版本化迁移，并验证全新建库、从上一版本升级和失败恢复。
- 覆盖成功、边界、失败、幂等、并发和恢复测试；涉及适配器时运行 Lite/Full 契约测试。
- 页面包含加载、空数据、错误、无权限和离线状态，并满足键盘操作与基本可访问性要求。
- 更新 README、配置示例、架构/运维文档；不把规划能力描述成已完成。
- 运行与变更范围匹配的格式、lint、类型、测试和构建命令，并记录实际结果。

## 2. 当前基线（不重复列入待办）

以下能力已有首版实现，后续待办只记录其缺失部分：

- Next.js 16 主平台、方案 E UI 基线和 Node.js 24 LTS 构建。
- TestNG JAR 有界静态扫描、内容寻址存储、扫描预览和用例导入。
- SQLite/PostgreSQL 用例与批次持久化，本地文件/MinIO 对象存储。
- 用例任务创建及任务内用例新增、删除。
- Runner 注册、身份落盘、资源心跳、在线判定和资源感知初始分配。
- Agent 本地受控单命令执行核心，以及默认关闭的直连 WebSocket 终端。
- 双架构后端镜像的 GitHub Release 构建、SBOM、校验和与构建来源证明；镜像内置兼容 glibc/musl 宿主的双架构静态 Agent 资源，不再单独发布 Agent。

当前实现已完成 Lite/Full 共享的身份、项目隔离、执行、分析、运维、页面可见性与离线发布候选门禁。平台数据盘提供容量分级告警，Runner spool 和单项上传使用严格配额；Full 对象存储总容量由 MinIO/S3 部署侧硬配额负责。M11 的 18 项完整 E2E 验收仍按 `tests/e2e/coverage-matrix.json` 保持 `partial`，必须补齐真实边界、失败与恢复证据后才能完成；Gate E 仍须基于新语义版本标签和不可变双架构资产执行。

## 4. M1 — 登录、LDAP、用户管理与权限分层

### 4.1 本地身份与会话

- [x] **AF-IAM-001 `P0` 建立统一身份领域模型。** 增加 `User`、外部身份、登录会话、角色、权限、成员关系和审计事件模型，使用应用层 UUIDv7 与 UTC 时间。
- [x] **AF-IAM-002 `P0` 完成双数据库身份迁移。** SQLite/PostgreSQL 同时支持用户、凭据、外部身份、会话、角色、授权关系和安全事件，并提供唯一性、版本条件和禁用约束。
- [x] **AF-IAM-003 `P0` 实现首位管理员引导。** 首次离线启动可通过一次性引导凭据创建本地系统管理员；凭据使用后失效，不能依赖邮件或公网服务。
- [x] **AF-IAM-004 `P0` 实现本地账号登录。** 使用经过评审的密码哈希、恒定时间校验、安全 Cookie、会话过期/轮换、登出和全会话撤销；密码和会话令牌不进入日志。
- [x] **AF-IAM-005 `P0` 实现离线密码恢复。** 管理员可重置本地账号、强制下次修改、解锁账号并撤销已有会话，不把邮件服务作为恢复前提。
- [x] **AF-IAM-006 `P0` 加固认证入口。** 提供 CSRF 防护、登录限速、失败锁定/退避、会话固定攻击防护、安全响应头和通用失败提示，并保留可审计原因。
- [x] **AF-IAM-007 `P1` 实现会话管理。** 用户查看并终止自己的会话，管理员按用户撤销会话；敏感权限变化后强制刷新或终止旧会话。

### 4.2 LDAP 配置与鉴权

- [x] **AF-LDAP-001 `P0` 定义 LDAP 配置 schema。** 字段与 DDT Insight 对齐，覆盖 URL、证书校验、连接超时、bind DN/密码、用户 Base/Filter、显示名/邮箱/Group 属性、Group Search 和统一默认角色。
- [x] **AF-LDAP-002 `P0` 实现 LDAP 配置管理。** 在系统设置中提供读取、修改、启停和连接测试；返回脱敏且可操作的 DNS、TLS、绑定、过滤器和权限诊断，不回显 bind 密码。
- [x] **AF-LDAP-003 `P0` 支持离线内网 TLS。** `ldaps://` 默认严格校验证书；隔离的旧目录允许管理员显式关闭校验，同时持续展示中间人风险并记录审计。
- [x] **AF-LDAP-004 `P0` 实现 LDAP 登录。** 用稳定外部标识关联本地 `User`，限制搜索结果和响应时间，防止 LDAP filter 注入，并清晰区分凭据错误、目录不可用和账号策略拒绝。
- [x] **AF-LDAP-005 `P0` 实现 LDAP 即时建号。** 首次成功登录按映射创建或更新用户，定义用户名/邮箱冲突、属性变更和本地账号合并规则，禁止仅凭可变邮箱静默接管账号。
- [x] **AF-LDAP-006 `P0` 保存 LDAP Group 资料。** 直接属性或 Group Search 的结果只写入用户资料供查看，不映射平台角色或权限。
- [x] **AF-LDAP-007 `P1` 退役全量目录同步。** 页面、API 和后台作业不遍历整个目录；历史表和字段只保留升级兼容。
- [x] **AF-LDAP-008 `P0` 定义目录失联策略。** 明确已有会话、新登录、本地紧急管理员、同步滞后和恢复后的行为；不得因 LDAP 暂时不可用锁死所有管理入口。
- [x] **AF-LDAP-009 `P0` 保留平台停用能力。** 管理员可在平台禁用 LDAP 用户并撤销会话，历史执行继续保留稳定用户 ID 归属。
- [x] **AF-LDAP-010 `P1` 增加 LDAP 测试矩阵。** 覆盖 LDAPS、证书校验开关、匿名/服务 Bind、直接与搜索 Group、特殊字符、超时、目录失联和重复身份。

### 4.3 用户管理与权限分层

- [x] **AF-IAM-008 `P0` 实现用户管理 API 与页面。** 支持游标分页、搜索、来源筛选、创建本地用户、查看详情、启用/禁用、解锁、重置凭据和撤销会话；LDAP 管理的属性明确只读。
- [x] **AF-IAM-009 `P0` 定义稳定权限目录。** 至少覆盖用例/来源、用例任务、批次/执行、日志/产物、Runner、直连终端、环境/密文、用户、角色、LDAP、审计和系统设置的 `read/create/update/delete/execute/admin` 动作。
- [x] **AF-IAM-010 `P0` 提供内置分层角色。** 至少定义系统管理员、项目管理员、测试管理员、执行操作员、只读观察者和审计员，并记录每个角色的精确权限；终端访问不得包含在普通执行权限中。
- [x] **AF-IAM-011 `P1` 支持自定义角色。** 角色可复制、编辑和停用；禁止删除仍被引用的角色或移除系统最后一位管理员，权限变更全量审计。
- [x] **AF-IAM-012 `P0` 实现服务端授权。** Route Handler、Server Action、Server Component、对象下载和 WebSocket 握手都调用共享授权用例；隐藏按钮只能改善体验，不能成为安全边界。
- [x] **AF-IAM-013 `P0` 实现数据作用域过滤。** 列表、详情、全局搜索、日志、产物和分析查询只返回当前身份有权访问的组织/项目数据，禁止通过猜测 ID 越权。
- [x] **AF-IAM-014 `P0` 将直连终端纳入 RBAC。** 以登录会话和短时一次性票据代替独立管理员访问令牌作为正常入口，保留 Runner 身份校验、会话时限、并发限制和完整审计。
- [x] **AF-IAM-015 `P1` 实现项目与成员管理。** 支持创建/归档项目、添加/移除成员、分配项目角色和转移负责人；历史数据不可因成员删除失去归属。
- [x] **AF-IAM-016 `P1` 完成多租户隔离。** 为所有业务聚合、仓储查询、唯一索引、对象键和缓存键加入明确租户/项目作用域，并用跨租户越权测试验证。
- [x] **AF-IAM-017 `P1` 实现 API 令牌/服务账号。** 令牌只显示一次、存储摘要、具有作用域和过期时间，可撤销轮换；Runner 身份、用户会话和自动化 API 身份保持分离。
- [x] **AF-IAM-018 `P0` 建立权限矩阵测试。** 对每个内置角色验证页面、API、对象下载和 WebSocket 的允许/拒绝结果，覆盖水平越权、禁用用户、过期会话和权限实时变更。

### 4.4 审计

- [x] **AF-AUDIT-001 `P0` 建立持久审计事件。** 记录登录、LDAP 配置/同步、用户与角色变更、用例来源变更、批次操作、Runner 管理、终端会话、密文访问、取消和重试；只记录脱敏摘要。
- [x] **AF-AUDIT-002 `P1` 实现审计查询与导出。** 支持按操作者、动作、资源、结果和 UTC 时间过滤，使用游标分页和有界导出，并受独立审计权限控制。
- [x] **AF-AUDIT-003 `P1` 定义审计保留与完整性策略。** 明确保留期、归档、备份、删除授权和篡改检测边界，任何清理都产生新的审计记录。

## 5. M2 — 执行领域、Assignment 与 Lease

- [x] **AF-EXEC-001 `P0` 增加版本化执行契约。** 在 `packages/contracts` 实现 `ExecutionSpec`、assignment、lease、日志、产物、完成、取消和 reconcile schema，并限制字段、条目数和载荷大小。
- [x] **AF-EXEC-002 `P0` 完成执行领域模型。** 为批次、单次执行、尝试、分配和租约实现不变量、版本条件、终态保护和可审计状态历史。
- [x] **AF-EXEC-003 `P0` 增加双数据库执行表与仓储。** SQLite/PostgreSQL 保存 assignment、lease、状态事件、完成确认、日志水位和产物元数据，仓储使用相同契约测试。
- [x] **AF-EXEC-004 `P0` 实现原子 claim。** Agent 通过有界长轮询只领取与自身标签、能力和容量匹配的 assignment；重复 claim 返回同一已知结果，不重复启动 attempt。
- [x] **AF-EXEC-005 `P0` 实现 lease 创建和续租。** lease 使用期限、令牌和版本条件，续租返回取消/排空指令；心跳不能代替 lease。
- [x] **AF-EXEC-006 `P0` 实现 lease 回收与 reconcile。** 后台回收真正过期的租约，处理 Agent 重启、网络分区、迟到完成和新 attempt 竞争，不覆盖已经确认的终态。
- [x] **AF-EXEC-007 `P0` 实现幂等完成上报。** 先持久化结果再向 Agent 确认；相同结果重复提交返回原确认，冲突结果产生稳定错误和审计事件。
- [x] **AF-EXEC-008 `P0` 接通失败重跑。** 根据已固化的 `retryLimit` 在失败/超时后创建下一 attempt，达到上限后形成唯一最终失败；取消和策略性拒绝不被错误重试。
- [x] **AF-EXEC-009 `P0` 实现批次取消和单次取消。** queued、assigned、running 状态都有明确行为，Runner 收到取消后清理进程树，完成/取消竞争只产生一个终态。
- [x] **AF-EXEC-010 `P0` 实现执行超时。** 区分排队超时、领取超时、执行超时和上传收尾超时，所有定时判断使用服务端 UTC 时间并可从崩溃恢复。
- [x] **AF-EXEC-011 `P0` 聚合批次结果。** 从权威 `ExecutionRun`/`RunAttempt` 计算进度、成功、失败、超时、取消和阻塞数量，重复消息不能重复计数。
- [x] **AF-EXEC-012 `P1` 增加优先级、公平性和配额。** 支持批次优先级、项目并发上限、Runner 并发上限和防饥饿策略，并验证并发调度不超卖。
- [x] **AF-EXEC-013 `P1` 增加 Runner 标签与能力匹配。** 执行快照声明 OS、架构、Java/TestNG/toolchain 等要求，调度器返回可解释的不匹配原因。
- [x] **AF-EXEC-014 `P1` 增加 Runner 排空、禁用和注销。** 排空停止领取新任务但允许在途任务结束；禁用、凭据撤销和注销不能遗留永久 running 状态。
- [x] **AF-EXEC-015 `P1` 实现单用例执行。** 与批跑共享 `ExecutionRun`、策略、权限、Runner 匹配、日志和产物闭环，不建立第二套执行路径。
- [x] **AF-EXEC-016 `P0` 实现控制面 Runner SDK。** 在 `packages/runner-sdk` 集中处理协议校验、Runner 认证、重试和兼容协商，区分传输错误与业务拒绝，不在页面或 Route Handler 中复制协议逻辑。

## 6. M3 — Runner Agent 实际执行闭环

### 6.1 领取、执行与恢复

- [x] **AF-AGENT-001 `P0` 实现 Agent claim loop。** 有界长轮询、指数退避与抖动、并发槽位控制、优雅关闭和服务端限流均可配置，空闲时不产生高频请求。
- [x] **AF-AGENT-002 `P0` 实现 lease 续租循环。** 与心跳生命周期分离，正确响应取消/排空/拒绝续租；失去执行权后不得继续普通上报。
- [x] **AF-AGENT-003 `P0` 实现输入获取。** 通过控制面授权下载权威 JAR 和其他输入，校验大小、SHA-256、目标相对路径和可用空间，不让 Agent 持有对象存储长期凭据。
- [x] **AF-AGENT-004 `P0` 实现 TestNG 执行规格。** 将固化的类、方法 JVM descriptor、参数和环境快照转换为明确的 Java 参数数组，不拼接 Shell；定义依赖 JAR/classpath 和退出码语义。
- [x] **AF-AGENT-005 `P0` 定义离线 Java/TestNG 工具链。** Runner capability 上报精确版本，运行时不下载 JDK、TestNG、浏览器、驱动或依赖；不满足要求时在调度前拒绝。
- [x] **AF-AGENT-006 `P0` 接入受控 process supervisor。** 每次 attempt 创建新工作目录，执行文件白名单、本地策略、cwd、环境、超时、日志和清理限制只能被本机策略收紧。
- [x] **AF-AGENT-007 `P0` 补齐资源限制。** 在目标 Linux 平台限制 CPU、内存、磁盘、进程数和文件数量；明确 cgroup/ulimit 等实际机制、权限要求和无法强制时的诊断。
- [x] **AF-AGENT-008 `P0` 实现取消和进程树清理。** 先温和终止、短暂 grace period 后强制清理整个进程组，覆盖超时、服务关闭和 lease 被拒绝场景。
