# ADR 0016：按日 PostgreSQL 日志库与月度离线归档

- 状态：已采纳并实现；本地验收范围见运维说明，正式发布验收单独记录。
- 日期：2026-10-29。
- 扩展 ADR 0015，保留原有日志与公开地址的兼容读取。

## 按日日志库

新增配置登记 PostgreSQL 日志服务器的地址、端口、管理员用户名、密码和库名前缀。管理员通常名为 `postgres`，也支持已配置的 `root` 等账号；必须拥有建库权限。密码沿用主密钥加密，不回显、不下发 Agent。业务主库不存日志正文。

日期采用日志自身记录时间的北京时间自然日，使跨日重传仍定位到原库。新库名由前缀、配置的稳定命名空间和 `YYYYMMDD` 组成；按需创建并校验永久身份。管理员连接、日库连接和旧库读取分离，读操作不得自动重建缺失库。跨日的同一 attempt 可有多个日库位置，主库持久化每个位置，读取必须合并；不能继续假定一个批次只在一个正文库。

批次固定选择日志服务器，切换只影响后续批次；日期库随实际日志日期滚动。去重、内容冲突与连续确认水位必须跨日一致。使用正文库上的 attempt 级协调，不在业务事务中等待日志库网络操作。连接数有界，旧库保留历史读取，新增管理入口只提供按日配置。

## 月度归档

默认按执行结束时间的北京时间月份分类。只纳入已结束且没有有效传输租约的批次；运行中和跨月未结束批次保留。以整个批次为最小归档单位，避免把一份用例执行日志截成不完整的两个月。

入口位于平台设置。流程分成生成并验证归档、下载、确认清理原始日志；生成失败、校验失败或未确认时不删除来源。只删除日志正文，保留任务、用例、轮次、执行结果、定位与必要的确认水位。

归档使用 ZIP64；日志转换为带 SHA-256 的分帧压缩记录，元数据分页索引，不直接导出 SQLite 主库或依赖 Go 的 SQLite 驱动。正文与索引条目以 ZIP STORE 保存，内部 gzip 压缩，便于对象存储按范围读取；查看器等可执行文件采用 ZIP 压缩。不得把全部日志、attempt 或索引灌入内存。

归档包包含 Windows x86_64、Linux x86_64／arm64 的静态 Go 查看器、说明及校验信息，不要求安装 Go、Node 或数据库。程序只监听本机地址，启动后打开浏览器；复用本地 Ant Design 主题和资源，提供批次／用例／轮次检索及分页日志，支持深浅色，不请求公网。其他系统按后续明确需求扩展。

在线原日志地址继续由归档读取器按位置读取已验证的压缩记录，公开权限和项目范围保持原规则。版本复制继续通过统一日志端口读取，不把已归档日志当成空日志。

## 后台工作与删除

归档是持久化、可恢复的后台操作，使用有期限的所有权和短事务。Lite 使用 SQLite 及本地对象存储；Full 使用 PostgreSQL 及 MinIO，归档产物可由任一节点读取。文件读取、压缩、校验、上传和清理均不进入 Web 请求主线程，且只允许一个重型归档阶段同时运行，在资源紧张时让位于执行控制。

删除前按批次登记已验证归档位置，使迟到读取不会因来源清理变成空日志。SQLite 清除已关闭的批次文件及 WAL／SHM；PostgreSQL 分批删除正文，已空且无活动引用的日库再回收，不强制终止其他连接。不能把 PostgreSQL DELETE 的逻辑大小误报为已归还操作系统的磁盘空间。旧单库的物理整理须独立、明确展示结果，并避免阻塞当前执行日志。

归档文件使用不可变对象键和摘要，删除失败可以重试；未完成归档、损坏归档、活动批次和正在使用的日库均不得回收。下载仅允许系统级日志归档管理者，公开日志不泄漏其他项目的归档包。

## 升级与验证要求

Lite／Full 分别维护版本化迁移，验证新建、升级、失败回滚。新增依赖固定版本、检查许可证与离线打包；查看器与资源清单随主平台交付，不增加独立 Release。

必要验证包括：午夜跨库、跨日乱序／重传／冲突／缺口恢复、多写入节点竞争、旧库兼容、归档失败不删除、取消／恢复、损坏检测、超大批次有界处理、真实空间回收、在线与离线读取一致、阻断网络后的查看器启动，以及 1024px 和代表性大屏的带数据 Playwright 截图。

## 分卷、容量预算与平台副本生命周期

本次扩展保留月级分类，每卷按源日志当前存储大小规划，默认 1024 MiB；单个执行批次不拆散，超过目标时独立成卷，因此目标不是 ZIP 文件硬上限。每卷还限制批次数以保持清单有界，不限制整月或任务用例总规模。整组冻结发起时的结束时间范围，逐卷规划期间保护尚未处理批次，防止保留策略先清理来源。已经上传并校验的卷不重建，失败重试只处理当前卷。

生成前估算分帧暂存、ZIP、本地对象副本及元数据排序的并存空间；默认安全余量取 1024 MiB 与文件系统总量 10% 的较大值，运行期间持续检查。选项随归档保存，无需重启；低空间拒绝生成，清理和已确认的副本移除不受生成预算阻挡。

Full 的每卷 ZIP 与范围索引上传到既有 MinIO，Lite 保存到本地 ObjectStore。默认保留平台副本。原日志清理完成后，当前操作人必须先完整下载本卷；服务端核对传输字节数和 SHA-256 并记录下载，再由用户勾选已完整下载且离线查看正常，明确确认单独移除平台副本。HTTP 传输结束不能证明用户磁盘已保存成功，手动确认保留为必要步骤。

先持久化离线意图，再通过后台租约幂等删除本卷 ZIP 和索引；失败可重试，不回退为空日志，不删除执行结果。平台读取明确返回离线状态，公开页保留结果和轮次。此步骤是用户明确授权的在线读取能力变化；此前原链接持续可读的保证适用于平台副本仍保留的归档。平台不得按浏览器开始下载、时间到期或缺失对象自动推断用户已备份并清理。
