# ADR 0018：退役 TestNG 执行产物

状态：接受（使用者明确要求移除）。

## 决策

平台不再收集、声明、上传、保存或预览新的 TestNG 执行产物。删除平台开关、任务产物规则输入、新授权中的产物权限选项、执行详情中的产物区域、Agent 文件扫描／持久上传／重传实现，以及平台和对象存储中的专用执行文件写入逻辑。普通 JAR、JDK、依赖包、DDT 表格、分析证明截图、导出和日志归档继续使用通用对象存储，与本次退役无关。

Adapter 和普通 TestNG 启动器关闭默认报告监听器，只保留本地最小 XML 结果。Runner 在工作目录读取它以生成方法状态、耗时、失败和配置失败等结构化结果，随后清理工作目录；XML 不上传。stdout、stderr、Agent 诊断、超时证据和完成上报继续保留。

## 日志上传阶段

原空产物声明兼任“Java 已结束”的生命周期标记，不能随文件上传链路一起删除。独立的 `POST /api/v1/run-attempts/{attemptId}/upload-phase` 通过 Runner 身份和有效 lease 登记上传开始时间，且重复调用不能延长原始期限。Web 将操作交由控制工作线程执行，SQLite／PostgreSQL 使用同一仓储契约和短事务。上传时限继续服务于日志排空，不改变用例进程的执行期限。

## 升级与兼容

- 不删除历史表或历史文件，不回写执行结果。历史数据库结构及版本复制中的旧引用继续保留，以支持升级、备份及存储清理。
- 协议 v1 的旧产物字段仅用于兼容读取，新的任务、批次和执行规格将规则归一为空；旧完成请求中的产物元数据只参与原始完成回执摘要的核对，不写入产物表，避免升级后的重复上报误报冲突。旧配置文件中的开关不再生效，界面及新的配置输出不提供该开关。
- 旧 Agent 的空 `/artifacts` 请求仅兼容转换为上传阶段握手；非空声明明确报告该功能已退役，不再签发上传目标。文件上传、下载和 finalize 端点移除。
- 新 Agent 连接相邻旧服务端时，仅在独立阶段端点返回 404 后回落到旧的空握手，从不上传文件。旧 Agent 接收新规格时得到空产物规则，继续上报日志与结果。
- 新 Agent 启动时清理退役的本地产物上传 spool，读取旧 attempt 状态时丢弃文件上传清单并保留原始完成结果用于幂等核对，继续核对租约、回传日志与结果，避免旧文件传输阻塞恢复。升级存在未完成文件上传的节点时，应先更新 Agent。

## Lite、Full 与离线

两种模式共享退役规则和控制协议，无新迁移、外部依赖或队列类型。Lite 使用 SQLite、本地日志与通用对象存储；Full 使用原有 PostgreSQL、NATS、Redis、MinIO 链路，均不再新建执行产物对象。离线运行和单个 Runner 同时兼容两种模式的要求不变。

## 验证范围

覆盖旧字段不能恢复收集、旧配置可读、独立上传计时与重复调用、日志排空和超时、旧状态恢复、两代阶段握手、普通及 Adapter 的结构化结果。更新相关用例，移除仅针对退役传输的断言；对设置、任务详情及执行详情使用带数据 Playwright，在 1024px 和大屏视口审查深浅主题。
