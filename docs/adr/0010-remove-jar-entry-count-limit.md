# ADR 0010：取消 JAR 条目数量限制

- 状态：已接受
- 日期：2026-08-21
- 取代：ADR 0007 中“ZIP/JAR 条目数保持有界”的部分决定

## 背景

TestNG 静态发现曾在遍历到第 20,001 个 ZIP/JAR 条目时以 `TOO_MANY_ENTRIES` 拒绝整个归档。
这个阈值与实际 JAR 字节规模、class 数量和解压体积没有直接关系：包含大量小资源文件的合法测试
依赖会被拒绝，而包含较少但很大的条目则由其他边界处理。产品要求扫描条目数量不再成为导入条件。

## 决定

1. 静态发现、后台导入和源码读取均不再按 ZIP/JAR 条目数量拒绝归档，也不提供可配置的隐藏条目
   上限；所有条目都会参与目录遍历和解压总量核算。
2. JAR 压缩上传大小、所有目录条目声明的解压总字节数、单个 class/源码大小和用户可见警告数量
   继续有界。这些边界针对内存、磁盘和响应体资源，而不是用例或目录数量。
3. 解析仍只保留与发现相关的 `testng.xml`、Manifest、`.class` 和 `.java` 内容；其他条目只计入
   解压总量，不进入发现结果。
4. 回归必须使用超过 20,000 个真实 ZIP 条目的归档，同时覆盖 class 发现和源码重新读取，防止
   任一路径恢复固定条目阈值。

## 影响

- 合法的大目录 JAR 不再收到 `TOO_MANY_ENTRIES`，API 契约中也不再产生该错误码。
- 极多空条目会增加与条目数量成线性的 CPU 和 ZIP 目录解析成本；上传字节上限仍对中央目录本身
  形成部署资源边界，但不再将其表达为产品条目数限制。
- Lite 与 Full 使用同一个发现实现，没有数据库或消息契约差异，也不需要迁移。
