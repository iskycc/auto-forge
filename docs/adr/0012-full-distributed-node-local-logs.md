# ADR 0012：Full 分布式部署与节点本地日志

- 状态：已接受，首版实现
- 日期：2026-09-05

## 背景

Full 已共享 PostgreSQL、Redis、NATS JetStream 和 MinIO，但每批次日志正文保存在本地
SQLite 文件。将多个独立数据目录直接放到负载均衡后面，会造成日志读取和重传水位不一致。
产品要求保留节点本地正文，并在平台中管理各节点的 IP 和端口。

## 决策

1. 用 `platform.json#nodeId` 保存安装身份；`deployment: distributed` 显式启用 Full 多节点。
   每个 Web/同机 worker 共享本节点数据卷，不同机器拥有不同 ID 和日志目录。
2. PostgreSQL `platform_nodes` 保存名称、直接访问地址及 revision；管理员通过“平台节点”编辑。
   `run_batch_log_locations` 以批次 ID 唯一选择日志所属节点，数据库条件插入解决并发选择。
   一个批次对应一个本地 SQLite 日志文件，日志正文不回写 PostgreSQL。
3. 任意 Web 都可接受 Runner 请求。执行认证后，日志操作被转发到所属节点的受认证内部接口。
   HMAC 绑定源/目标节点、接口、时间、nonce 和正文摘要；Redis 拒绝 nonce 重放。
   内部接口只执行明确的日志操作，不提供通用 HTTP 代理、任意路径或命令执行。
4. 先保存本地日志，再持久化共享确认水位，然后返回确认。记录重复、缺号和内容冲突沿用同一
   本地存储实现。完成事务中的水位元数据使用原 PostgreSQL 事务，不在事务内访问其他节点。
5. Redis Pub/Sub 转发已脱敏的实时日志，近期缓存最多 128 个 attempt、每个 256 KiB / 32 帧，
   TTL 为 120 秒。缓存缺失时从所属节点分页读取；Redis 不承担正文的最终持久化。
6. 所属节点故障、地址未配置或文件缺失明确返回 503，不自动重新选择节点，不以空日志掩盖故障。
   批次删除后保留位置记录，由所属节点的周期清理重试删除文件，再清除位置记录。
7. 分布式公共运行配置由部署文件统一管理，管理页面只读；节点地址是独立的 PostgreSQL 数据，
   更新后无需重启。所有节点共享应用密钥和基础设施配置；配置变化需同步并重启整个部署。
8. Nginx 负载均衡普通请求与实时日志连接。首版交互终端保持固定网关节点，避免 Agent 和浏览器
   连接落在不同进程；终端网关故障时需恢复或人工切换，随后重新建立终端会话。

## Lite 与兼容性

Lite 仍使用本地日志、SQLite 队列和嵌入式 worker，不连接 Full 服务。旧 Full 配置没有
`deployment` 时仍保持单机行为。两个数据库增加兼容的节点元数据表，不改变日志格式、任务配置、
Runner Protocol 或执行状态机。同一 Go Runner 继续通过负载均衡入口使用原协议。

## 升级、故障与恢复

升级前停止所有旧 Web/worker 并备份 PostgreSQL、MinIO、平台配置和每个节点的日志目录。
先在保存旧日志的原节点启动分布式版本；启动扫描按批次登记本地文件，按有界窗口导入确认水位。
另一节点发现已有不同归属的同名文件时拒绝覆盖。增加副本只复制公共配置，不复制日志目录或节点 ID。

新增 SQL 迁移只创建表和索引；迁移失败由现有迁移事务回滚。分布式上线之后不能直接切回旧单机
代码：旧代码无法读取其他节点日志。回滚应恢复上线前的完整一致性备份；或者继续使用新版本，
先完成受控的日志归并和归属验证再另行设计降级。不得仅删除节点元数据表。

此方案实现平台多节点和本地日志路由，不提供日志副本、自动日志迁移或底层数据库/Redis/NATS/
MinIO/Nginx 的高可用集群。日志节点磁盘损坏仍需该节点备份恢复。
