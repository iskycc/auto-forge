# ADR 0009：全局项目上下文与只读 TestNG 参数

- 状态：已接受
- 日期：2026-08-21
- 取代：ADR 0008 中“任务保存参数模板”和“单用例允许参数覆盖”的部分决定

## 背景

项目选择曾分别存在于用例、导入、任务、执行记录、洞察、来源、审计和项目设置页面。同一用户在
页面间移动时需要反复选择项目，URL 中还可能同时保留互相冲突的项目、版本和阶段。任务详情与
单用例弹窗也保留了手工 TestNG 参数覆盖，造成导入发现参数、任务模板和一次性覆盖三层来源，难以
解释最终执行值并增加了未验证输入面。

## 决定

1. 顶栏提供唯一的全局项目切换。当前项目以 HttpOnly、`SameSite=Strict` Cookie 保存；写入前按
   当前身份重新授权，页面仍按自己的权限收窄项目作用域。项目版本和测试阶段只在当前项目内部筛选。
2. 页面不再渲染用于切换上下文的项目选择器。项目字段仅可用于角色分配、服务账号授权等明确业务
   输入。旧 URL/API 的 `projectId` 可为兼容和服务端鉴权保留，但不能重新成为多个页面状态源。
3. `CaseSuiteExecutionPolicy` 和单用例创建请求不再接受手工参数。TestNG JAR/testng.xml 静态发现的
   参数仍属于不可变 `CaseVersion` 元数据，并在执行快照中只读固化。
4. 旧任务 JSON 中的 `parameters` 不需要数据库迁移；Lite 和 Full 仓储读取时通过同一个策略规范化
   函数丢弃该键，新版本和新批次不再写回。
5. CI 必须拒绝页面级项目切换、任务/单用例参数输入和侧栏非四字标签的回归。

## 影响

- Lite 与 Full 共享 Cookie、领域策略、契约和仓储规范化语义，没有模式分支。
- 切换项目时删除版本、阶段、项目洞察和游标参数，避免把前一项目的子资源带入新项目。
- 历史批次的实际参数快照继续可读，不修改审计证据；只取消新执行的人工覆盖能力。
- 单用例弹窗默认启用 CoTest Adapter，用户仍须填写 Suite、Test 和至少一个环境地址后提交。
