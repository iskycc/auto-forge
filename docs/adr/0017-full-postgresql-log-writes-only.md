# ADR 0017：Full 执行日志仅写 PostgreSQL

- 状态：已接受，按维护者要求实现
- 日期：2026-10-30
- 收紧 ADR 0012、0015、0016 的本地写入兼容策略。

## 决策

Full 新批次必须使用独立、按日分库的 PostgreSQL 日志服务器。创建任务执行、单用例执行及派生重跑前，通过注入的日志写入准入端口检查主库登记的活动写入目标；未配置时返回可操作错误，不创建批次。准入检查只读主库，不在请求链路预加载日志或连接所有日志日期库。

日志上传在路由适配器再次检查目标。缺少目标、旧本地批次或空数据库绑定均不得追加本地 SQLite 正文，也不自动改路由或返回成功。Full 本地日志适配器包装为只读兼容层，Web、独立 worker、后台工作线程及节点间历史通道均禁止追加正文和本地水位。已绑定 PostgreSQL 的批次仍写原数据库，不受之后切换影响；旧 PostgreSQL 单库批次保持原有读取和写入，不创建新的旧单库绑定。

日志数据库设置不允许选择空目标，服务和仓储均拒绝切回本地；页面移除本地写入按钮。引导页不再提供本地日志选项，首次保存 Full 必须填写独立日志服务器。既有 Full 配置缺少 `full.logServer` 仍能启动，便于登录补齐配置；在选择按日服务器前拒绝新执行，不因升级自动猜测或使用业务库。

历史 SQLite 日志继续按原路径及节点读取、归档和清理，不自动迁移、删除或截断。升级前应排空旧本地执行；仍在执行的旧本地批次追加被拒绝，Agent 不会收到虚假的持久化确认。保留原日志及 Agent spool，配置日志服务器后结束旧批次并重新执行。已有日志无法仅靠更换绑定实现完整迁移。

## 设置入口

平台配置与引导页共用主机／端口／认证字段和有界检查能力。设置页检查要求 `settings.manage` 和同源；不使用或接收引导令牌。凭据不回显，某块整块留空保留既有连接。日志服务器在独立的“日志数据库”模块维护，基础设施页提供直达入口，避免修改仅用于首次登记的 seed 而误以为切换了实际写入库。

## Lite、升级与回滚

Lite 保留 SQLite 日志写入，不接入 Full 准入端口。此变更无 SQL 迁移、外部依赖或 Runner 协议变化；所有 Full Web 和 worker 应同步升级。存储管理可重建索引、版本复制快照及归档临时索引不属于在线日志正文存储，不随本决策移除 SQLite。

回滚需使用同一平台配置和数据备份；旧版本可能重新允许本地日志写入，因此回滚后仍应保持 PostgreSQL 写入目标，避免产生新的分散日志。
