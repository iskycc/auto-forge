# ADR 0001：本地身份与 LDAP 访问策略

- 状态：已接受
- 日期：2026-08-09

## 背景

AutoForge 必须在完全离线且没有企业目录的 Lite 环境运行，也要在 Full 环境接入内网 LDAP。平台当前只有 Runner 身份和独立终端令牌，没有用户会话，不能作为生产鉴权方案。

## 决策

1. 本地账号是两种部署模式共有的基础能力；LDAP 是显式配置后才加载和连接的可选身份适配器。
2. 首次部署通过一次性管理员引导令牌创建本地系统管理员。令牌只保存摘要且只能成功使用一次；不提供默认用户名或密码。
3. 浏览器使用数据库会话。Cookie 只保存高熵随机令牌，数据库保存 SHA-256 摘要、过期时间、最后使用时间和撤销时间。
4. LDAP 登录先用受限服务账号搜索稳定目录标识，再以用户 DN 验证用户密码。用户密码不保存、不写日志，也不用于后台同步。
5. LDAP 用户用 `(providerId, externalSubject)` 唯一关联本地用户。邮箱和显示名是可变属性，不能用于静默合并身份。
6. LDAP 可按成功登录即时建号，并支持手动或持久后台同步。目录失联时拒绝新的 LDAP 登录，但不立即终止仍有效的本地会话；本地紧急管理员始终可按本地策略登录。
7. 目录确认账号停用或失去允许组资格后，禁用用户、撤销会话并保留历史记录归属。单次网络失败不能被当作离职信号。
8. 本地和 LDAP 用户共享 `User`、角色、项目成员和审计模型。身份来源不直接授予权限，权限只来自显式角色绑定和 LDAP 组映射。

## 后果

- Lite 未配置 LDAP 时不导入 LDAP 客户端、不探测目录服务，仍只依赖 SQLite 和本地文件。
- LDAP 需要受信任的 TLS/StartTLS、私有 CA、明确超时、过滤器转义和结果上限。
- 目录故障与凭据错误必须映射为不同内部诊断，但登录页面返回通用失败信息以减少账号枚举。
- 邮件不是首次引导、解锁或密码恢复的必要依赖。
