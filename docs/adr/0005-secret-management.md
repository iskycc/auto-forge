# ADR 0005：离线密文管理

- 状态：已接受
- 日期：2026-08-09

## 背景

LDAP bind 密码、执行环境密文和将来的服务账号密钥需要持久化。AutoForge 不能依赖在线 KMS，也不能把明文密文写入数据库、日志、审计或 Agent spool。

## 决策

1. 平台使用显式提供的 256 位主密钥执行 AES-256-GCM 信封加密。首版主密钥通过受限权限文件或环境注入，配置层只解析一次，不向业务模块暴露 `process.env`。
2. 每个密文生成独立随机 96 位 nonce，并将 schema 版本、用途和资源 ID 作为附加认证数据。数据库保存 `version + nonce + ciphertext + authTag`，不保存主密钥。
3. 没有主密钥时平台仍可运行，但创建或使用 LDAP bind 密码、执行密文等能力明确关闭；Lite 不因此获得新的必需依赖。
4. API 只接受新密文，不返回已有密文。更新时空值表示保持不变，显式删除使用独立操作。日志和审计只记录密文 ID、用途和变更动作。
5. 轮换采用“新写使用当前 key ID，读取支持当前和上一 key ID，后台重加密后撤销旧密钥”的可恢复流程。备份必须包含密钥引用说明，但不把密钥和密文备份放在同一未隔离介质。
6. Runner 只有在持有有效 lease 时才能通过受保护响应获得所需密文。明文只短暂存在于内存和子进程环境，不进入 `ExecutionSpec` 持久快照、日志或 spool。
7. Agent 与控制面对日志做双层脱敏。已知密文按值和稳定派生掩码匹配，跨块处理保留足够尾部窗口。

## 后果

- 主密钥丢失时密文不可恢复，备份/恢复验收必须验证密钥可用性。
- 主密钥轮换、LDAP 配置变更和执行密文读取都属于高风险审计事件。
- 未来可以通过新的 `SecretCipherPort` 适配离线 HSM/KMS，不改变领域模型。
