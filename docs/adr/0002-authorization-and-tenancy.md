# ADR 0002：授权、角色与数据作用域

- 状态：已接受
- 日期：2026-08-09

## 背景

AutoForge 管理可执行命令、密文、终端和测试资产。仅在 UI 隐藏按钮无法防止 API、对象下载或 WebSocket 越权。项目还要求权限分层和未来多租户隔离。

## 决策

1. 使用“稳定权限目录 + 角色绑定 + 项目作用域”的 RBAC。权限以 `resource.action` 命名，由代码版本管理，数据库不允许创建未知权限。
2. 所有授权默认拒绝。系统角色可以作用于整个平台，项目角色只作用于一个项目；系统管理员权限不能由普通项目管理员授予。
3. 内置角色为：系统管理员、项目管理员、测试管理员、执行操作员、只读观察者和审计员。终端使用独立 `runner.terminal` 权限，不包含在普通执行权限中。
4. 页面、Route Handler、Server Action、对象下载和 WebSocket 入口都调用同一授权服务。UI 状态不是安全边界。
5. 业务资源必须携带 `projectId`。仓储方法接收授权作用域并在查询中约束项目，不能先读取任意行再只依靠前端过滤。
6. 平台建立不可删除的默认项目以平滑迁移现有数据；新增项目使用 UUIDv7。跨项目复制必须创建新资源并记录来源，不能共享可变记录。
7. 禁止移除最后一个有效系统管理员。禁用用户、角色变化或成员移除时撤销相关会话，避免旧会话长期持有已经失效的权限。
8. Runner 身份、用户会话和服务账号是三种独立主体。Runner 不能调用用户管理 API，服务账号不能打开交互终端。

## 权限边界

权限目录至少覆盖：用例与来源、用例任务、批次与执行、日志与产物、Runner 管理、终端、环境与密文、用户、角色、LDAP、项目、审计和系统设置。

## 后果

- 现有无项目字段的数据在迁移时归入默认项目，但每个后续写入必须显式携带项目作用域。
- 缓存键、对象键和审计事件必须包含租户/项目语义；缓存不能替代仓储授权过滤。
- 权限矩阵必须同时验证页面、HTTP、对象和 WebSocket，覆盖猜测 ID 的水平越权。
