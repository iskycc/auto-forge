# ADR 0013：平台统一时间与时钟偏差容错

- 状态：已接受
- 日期：2026-09-05

## 背景

运行中批次曾使用浏览器 `Date.now()` 减去平台保存的开始时间。两端相差十分钟时，
刚创建的批次就显示十分钟耗时。Full 各 Web、调度线程和 worker 也分别读取宿主机时间，
导致租约、延迟执行、跨节点日志签名和短期 WebSocket 票据可能使用不同时间基准。

## 决策

管理员选择共享 PostgreSQL 作为 Full 时间基准。所有 Full 部署（含单机）在接收业务前
读取 `clock_timestamp()`，此后每五秒采样一次。无需选举平台节点，不依赖某台 Web 的
排序、在线状态或宿主机校时；数据库仍是时间基准和业务事实所在的共同依赖。

- 应用通过原有 `Clock` 端口获取时间。数据库驱动及采样定时器仅在基础设施层装配。
  时间采样复用已有连接池；连接获取受池的五秒超时约束，查询超过两秒销毁该连接。
  往返总耗时超过两秒的采样被拒绝；有效采样以往返耗时的一半估算响应传输延迟。
- 采样之间以 `performance.now()` 推进时间，不读取宿主机墙钟。两秒以内的偏差以
  最高 5% 的速率渐进修正，业务时间不会倒退。超过两秒的数据库时间跳变被拒绝。
- 短暂采样失败时继续使用原基准，保留结构化错误日志并报告 `holdover`。
  最后一次成功采样超过 120 秒后，业务取时抛出 `PLATFORM_CLOCK_UNAVAILABLE`，HTTP
  返回 503，readiness 不就绪；恢复有效采样后自动恢复。启动时没有本机时间回退。
  这段容错窗口不保证数据库业务读写在数据库断开时仍能成功。
- Lite 使用 Node 进程的时间原点加单调增量，主线程和工作线程共享同一原点。没有外部
  服务或采样过期限制；运行期宿主机校时不改变该进程的业务时间，重启后采用新的原点。
- 前端通过服务端首屏时间和无缓存的 `/api/v1/time` 同步平台时间，每 30 秒及页面重新
  可见时刷新；耗时、执行记录和延迟开始预览使用单调增量。只让订阅时间的组件每秒
  刷新，避免详情整页随时钟重渲染。网络断开时保留展示时间基准，业务权限仍由服务端决定。
- 节点日志 HMAC、临时进度链接和实时日志/终端票据的签发及验证使用同一基准。
  登录 Cookie 用平台计算的相对 `Max-Age`，避免浏览器解释错误的绝对到期日期。
- Runner Protocol v1 的 lease、续租响应和 reconcile 响应可选新增 `serverTime`。
  新 Agent 用“租约到期时间减服务端当前时间”生成本机单调截止时间，并保守扣除整个
  请求耗时。重启后重新 reconcile 获取时间，不从 spool 恢复单调时钟；旧控制面缺少
  字段时沿用绝对到期时间，新控制面也继续接受旧 Agent。完整偏差容错需更新内置 Agent。
- 平台诊断显示当前接入节点的时间源、采样状态和宿主机偏差，偏差达到五秒时提示校时。

## 边界与运维

这是统一业务时间，并非 NTP 服务。所有机器和 PostgreSQL 都错时，系统不能推断真实 UTC；
时间标签仍会偏离真实时间，但新批次的相对耗时可以正确推进。宿主机、PostgreSQL、Redis、
NATS、MinIO 和 Runner 仍应配置可靠校时：TLS 证书有效期、S3 签名及中间件自身 TTL
不由应用 `Clock` 接管，不保证任意幅度的系统时间错误下这些外部机制仍然工作。

数据库运行期大幅调时不能当作正常采样。优先恢复原时间源；若必须永久调整数据库时间，
应先停止新任务、排空执行、停止所有平台及 worker，统一校时后整体重启。不要让部分进程
保留旧基准、部分进程使用新基准。长期基础设施故障仍受原有 worker 有界恢复和进程监督策略约束。

无需数据库迁移或新增部署配置。首次升级前建议排空在途任务；旧版本已保存的错误开始、
结束或计划执行时间无法自动判断真实值，因此不自动改写历史记录，也不重排原有计划任务。

## 验证

- 时钟单元测试覆盖首次采样、慢采样、120 秒保留期限、恢复、渐进修正及正负十分钟跳变。
- SQLite 路径验证进程时间原点与宿主机调时隔离；真实 PostgreSQL 验证三组节点偏差和
  跨节点 HMAC。Go 测试验证相对租期、HTTP claim/续租、新旧字段兼容和重启状态隔离。
- Playwright 覆盖浏览器快/慢十分钟及运行期调时，检查运行耗时、倒计时并保留桌面截图。
- Full 分布式验收脚本在 Web/worker 进程中注入正负十分钟墙钟偏差，保留真实单调时钟和
  数据库时间；现有 GitHub Actions 分布式流水线继续验证 Nginx、会话、日志、节点故障恢复，
  并执行新增计时回归。注入仅位于测试脚本，不修改宿主机 NTP 或生产配置。

时间语义依据：[PostgreSQL 日期/时间函数](https://www.postgresql.org/docs/15/functions-datetime.html)、
[Node.js Performance API](https://nodejs.org/api/perf_hooks.html)。
