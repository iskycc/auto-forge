# 项目改名与 Agent 卸载

## 项目名称

在“项目设置”点击“修改项目名称”。拥有当前项目 `project.manage` 权限的用户可以修改启用项目的名称，包括系统创建的默认项目。名称去除首尾空白，长度为 1–120 个字符；已归档项目不能改名。

`PATCH /api/v1/projects/{projectId}` 的请求体为 `{"name":"新的项目名称"}`。只修改名称和更新时间，不修改项目 ID、slug、默认项目标记、负责人、版本、用例、任务和历史执行关联；旧执行快照保持原样。项目选择器刷新后显示新名称，使用项目 ID 的接口、链接和 Jenkins 配置继续有效。默认项目仍不能归档。

## 从平台卸载

在“执行节点 → 管理操作 → 卸载 Agent”打开确认框，需要 `runner.manage` 权限。可使用已保存的 SSH 连接，或填写 root／具有 sudo 权限的连接并探测、核对 SSH 主机指纹。勾选永久清理确认后才能提交。

建议先排空节点。卸载会停止服务，当前未完成执行会被中断，并通过现有注销／租约恢复路径处理；卸载不是等待任务自然结束的排空操作。

执行顺序如下：

1. 使用内置静态 Agent 资源，通过已核验的 SSH 连接上传临时卸载工具；不会要求远端旧 Agent 已支持卸载命令，也不需要公网、JDK 或 cgroup v2。
2. 只读检查远端配置、数据目录和 Runner 身份。SSH、权限或身份检查失败时，不更改平台节点。
3. 注销平台身份、撤销凭据并回收租约；停止和禁用 `autoforge-agent.service`，删除 unit 及其 override 目录、程序、Adapter、配置、CA 和前一版本备份。
4. 清理远端实际配置的数据目录下的 `identity`、`spool`、`work`、`cache`，包括本地日志、执行结果、产物、终端工作区和运行资源缓存；清理安装器创建的专用服务账号和组。root 或同名的其他用途账号不会删除。
5. 在同一个数据库事务内清除已保存 SSH 密文，并将已注销节点置为墓碑；节点从列表消失，历史执行的外键仍有效。SQLite 和 PostgreSQL 行为一致。

`POST /api/v1/runners/{runnerId}/uninstall` 接受 `{"profileId":"已保存连接ID","confirm":true}`；手工连接使用 `connection`、`expectedHostKeySha256`、`installationMode` 和 `confirm:true`。接口有同源保护、权限校验、限流和完成审计，不返回密码。

平台已接收并保存的执行记录、日志和产物继续保留。系统级 journal 由主机原有日志保留策略管理，不会清空其他服务的系统日志。若自定义数据目录中还有非 Agent 文件，保留这些文件及父目录，并在完成提示中说明；作为挂载点的根目录也会保留。工作区中的符号链接只删除链接，不跟随删除外部目标。数据目录中的嵌套挂载需先卸载后重试。

## 失败与重试

远端清理失败时，不隐藏节点，也不删除已保存 SSH 连接。节点可能已处于“已注销”，可再次进入“卸载 Agent”重试。远端私有恢复记录保留原 Runner ID 和目录，便于在部分文件已经删除后继续；完成后恢复记录也删除。若服务文件缺失，且恢复记录不能证明此前已经成功停止服务，则拒绝删除执行数据；需先停止 Agent 并恢复服务文件后重试。平台最终清理失败会回滚数据库事务，节点及连接仍可重试，不会删除一半平台记录。

若中断后重新安装了其他身份或修改了数据目录，工具会拒绝使用旧恢复记录，避免删除新 Agent 的数据；需先核对当前安装和原目录，再处理遗留恢复记录。

## 主机本地卸载

本版 Agent 也支持在执行机以 root 运行以下命令：

```bash
/opt/autoforge/bin/autoforge-agent uninstall --inspect
/opt/autoforge/bin/autoforge-agent uninstall --confirm
```

本地命令只清理执行机，不持有平台管理权限，不能代替平台上的注销和删除节点。手工在主机卸载前，应先在平台注销节点；远端自动卸载会自行完成这两个步骤。非标准安装位置不自动推断，请按实际服务配置手工处理。

两项功能均不新增数据库迁移、生产依赖或配置项。Full 和 Lite 共用接口、授权和业务流程。
