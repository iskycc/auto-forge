# 系统信息与连接池

侧栏使用四字名称：“文件管理”包括文件来源与存储空间；“日志管理”包括日志配置与日志归档；“系统信息”独立展示运行与中间件情况。系统信息、全平台空间与日志管理要求 `settings.read`，修改还需对应管理权限。Lite 的日志配置页显示本地存储说明，不连接 PostgreSQL。

旧 `/settings/platform?section=diagnostics` 跳转 `/system-info`；旧 `section=logs` 跳转 `/logs?section=databases` 并保留日志库游标；旧 `/objects?section=archives` 和平台设置归档入口跳转 `/logs?section=archives`。既有 `/api/v1/settings/diagnostics` 和按需中间件详情 API 不变。

系统信息的运行摘要仅读取当前 Web 进程内的请求总数、4xx／5xx、累计平均响应、最近 CPU 与事件循环采样。CPU 按当前进程可用核数归一化，请求指标从进程启动累计，不代表全部 Web／worker 节点的集群总量。执行配置摘要来自已经加载的配置，只列出超时、并发与调度策略，不输出凭据、地址或数据目录。继续使用既有 250 ms 资源监测与 15 秒信息快照，同一采样中的并发请求合并，依赖探测期限仍为 3 秒。没有新增后台轮询、大表统计或对象遍历；中间件详情仍需点击后才加载。

Full 主库和日志库此前均已使用 `pg.Pool`。本次改善连接保留与跨操作复用：

- 主库保留最多 2 个已建立的常驻连接，其余空闲连接在 10 分钟后回收；独立时钟池最多 1 个连接，首次使用后保留。主池上限仍取 `full.databasePoolMax`（默认 10），启动预热数量仍取池上限与 40 的较小值。所有池开启 TCP keepalive，首次探测延迟 10 秒。
- 日期日志连接缓存最多 4 个目标，每个目标正文池最多 2 个连接、锁池最多 2 个。事务与 advisory lock 的连接隔离保持不变；它们不设置常驻下限，空闲 10 分钟回收，以免永久阻塞日期库清理。
- 注册、检查、容量采样和按日建库使用最多 4 个管理池，每池最多 1 个连接；并发读者复用同一池。只淘汰无使用者的最久未用池，全部忙时返回可重试繁忙错误。凭据变化形成新连接身份；连接串只以摘要作为内存键，不对外展示。
- 删除空日期库之前，主动关闭本进程空闲的管理连接；其他读者仍使用时延后清理，不强制断开。关闭平台时统一结束连接池；连接失效由驱动丢弃，下一次操作按需建连，不让空闲连接错误事件终止 Web。

连接池减少握手与建连成本，但不能替代索引、短事务、合理 SQL 和数据库资源预算。池的 `min` 只保留既有连接，不主动预热；见 [node-postgres Pool 文档](https://node-postgres.com/apis/pool)。所有 Web、worker 和调度线程的上限需要加总，每个日志仓储实例最多 16 个日期连接与 4 个管理连接，另加主池、执行写入池及各自独立的时钟池。不要只为了增加连接数而无限增大 worker 或 `databasePoolMax`；总和应给 PostgreSQL `max_connections` 留出管理、备份与其他应用余量。

“系统信息 → PostgreSQL”按需浮窗展示当前 Web 主池上限、主池总／闲／等待连接及日志池计数。数据为该进程快照，并非所有节点连接总额。Full 日志写入仍必须使用独立 PostgreSQL 日期库，主库仍保存实际日志位置；Lite 仍使用原 SQLite／本地对象路径。

服务账号删除位于“平台设置 → 服务账号”。确认删除后移除账号和全部密钥，后续鉴权失效；账号版本不匹配时要求刷新。已撤销或已过期密钥的“删除”仅清理其密钥记录，活动密钥先撤销。操作写入独立删除审计，已有审计和执行快照不依赖这些密钥记录而继续保留。没有新增数据库迁移。
