# AI 初步分析：使用、部署与验证

状态：v1.22.1 使用 50,000／25,000 字符及首行补齐规则、去除 AI 额外脱敏并过滤通用退出码；实际发布状态以 GitHub Release 为准。更新时间：2026-11-06。

完整需求见[实现指导](../architecture/ai-failure-analysis.md)，提示词目标规范见[提示词附录](../architecture/ai-failure-analysis-prompts.md)。本页说明当前代码接入方式，不把后续规划能力描述为已经完成。

## 配置和入口

“平台设置 → 模型配置”配置 OpenAI 兼容 Chat Completions API 根地址、API Key、模型 ID、上下文和输出 token 预算、全端点共享并发／RPM／TPM、响应期限、最大重试及每例证据空间预算。例：`http://model.internal:8000/v1`，不要再附加 `/chat/completions`。API Key 加密保存，留空保留原值；无鉴权内网端点可以不设置。

“检查连接”只发送合成指令，核对接口和工具调用，不发送真实执行日志。配置保存后对新请求生效，无需重启。已有在途请求可能仍用其已取得的配置；关闭功能后不领取新工作，已有请求有限排空。平台不下载模型、不默认访问公网。

模型启用开关使用统一 Ant Design 尺寸，标签与开关同行。通过普通 HTTP／局域网 IP 访问时，分析入口使用浏览器 `getRandomValues` 生成幂等键，不依赖仅安全上下文提供的 `randomUUID`；提交响应丢失后，重试继续使用原键，避免重复创建分析作业。后台权限和模型连接方式保持不变。

管理员需为项目使用者授予 `analysis.ai.read` 和 `analysis.ai.create`，同时具有 `run.read、case.read、log.read`。原人工分析权限不会自动变成模型数据披露权限。系统管理员可管理配置；普通项目成员不能读取密钥。报告和证据按当前权限重新校验。

- 执行详情的“AI 初步分析”读取本批次最终失败／超时范围；手动发起整批分析需等批次结束，开启任务自动初析后可在执行期间从同一入口查看自动进度。同批次曾通过的用例不属于最终失败范围。
- 失败／超时行的“AI 初步分析”绑定该行 attempt，可在批次仍执行时分析已结束尝试。它不会改写其他轮次或其他执行批次的结论。
- 弹窗展示枚举、采集、分析、组内汇总、限流与资源退避、部分完成、失败和取消。关闭弹窗后后台继续，重新打开可以查看结论和进度；取消仅终止初析。
- 任务详情可勾选“任务结束后自动进行 AI 初步分析”，缺省关闭。选择写入任务策略并复制到批次快照；末轮分批接收已经最终结束的失败／超时用例，终态后补偿并关闭接收，不延迟完成上报。普通执行按实际拉起人授权；公开任务执行按批次中记录的链接分享人 ID 授权，拉起人无需额外 AI 权限。分享人账号或权限失效时跳过，不回退借用拉起人或管理员权限。AI 作业保存该授权账号，Worker 后续逐阶段继续复核；执行记录仍保存实际拉起人。

公开执行／日志访问能力不等于 AI 分析授权；首版不会把模型建议自动公开。

## 本轮分析方式与提示词

批次入口先采集最终失败／超时用例，按完整堆栈分组，相同堆栈共用一个疑似问题建议；异常消息、帧或行号不同则独立，缺失／不完整堆栈的用例各自分析。同栈数量不足 10 个时，按成员逐一读取 stdout 业务日志，按下述清理与尾部裁剪规则准备模型证据，并逐片累积判断，全部成员完成后统一回填同一疑似问题的简短建议。达到 10 个时共用堆栈证据，较大组按成员页／堆栈片续分析。每段最多 100 个成员回填，原工作租约、取消和限流退避保持。单例按钮独立读取该 attempt 的 stdout，使用相同输入处理规则，不复用批次分组结果；日志不可用或采集超出预算时明确报错。

2026-11-06 的输入规则：先使用主平台的有状态 ANSI 解析器移除颜色、OSC 链接和非显示控制字符，跨日志块／分页保留解析状态；不再执行 AI 采集层的密码／Token 替换，按 Unicode 字符计数；50,000 字符及以下保留全文，超过 50,000 时以末尾 25,000 字符为基准，再向前补到首行行首。补齐后可能超过 25,000 字符；支持 LF／CRLF／CR，不拆坏 emoji 或 CRLF。没有前置换行时保留整行，继续按上下文分片并受原有证据预算限制。stdout 跨块拼接为完整正文后统一判断，不按存储块分别取尾；JSON 中的字符串按字段值准备，结构、数组、数字、`0`、`false` 和 `null` 保持不变。协议 JSON、系统权限提示及工具 schema 不作任意字符串截断。

平台仍在原有字节预算内采集完整 stdout，用清理后的完整堆栈计算签名；相同尾部不能替代完整堆栈比较。发给模型的正文和堆栈使用上述尾部规则，处理信息放入 `inputTransformations`，模型不得把尾部样本描述为全文。主动裁剪不等于读取不完整，不会因此把正常作业标记为失败／部分完成；真正的预算不足、丢失或读取失败仍明确报错。原始日志、页面显示和日志导出不修改。

不足 10 例和单例传递 stdout 全文，而非仅传堆栈；上下文较小时分片累计分析，不自动把正文缩成退出码。独立的通用 TestNG 退出码行从 AI 证据中排除，只有退出码时明确报错，模型不猜测根因。AI 采集不对业务密码／Token 再次脱敏，不还原原日志已经处理过的内容；平台自身连接密钥和管理凭据不加入证据。

新结论统一三行：`可能重跑通过`、`可能用例问题需要修改`、`可能业务问题需要提单` 中的一项，加上简短原因和依据，均为待人工确认。单例细查日志仍使用同一精简输出格式，不输出长篇步骤或已确认处理结果。

“平台设置 → 模型配置 → 参考提示词”弹窗支持增删改多条提示，应用后保存配置；每次实际分析请求附带全部提示。最多 20 条，合计 20,000 UTF-8 字节，并校验上下文余量；不填写秘密。提示词跟随配置修订持久化，旧配置默认为空数组。正在发送的请求保留原配置，后续请求立即使用最新配置。

执行结果／失败分析 Excel 在批次已创建 AI 分析且导出者具有 AI 与证据读取权限时保留“AI 初步分析”列，未产出结果的行留空。失败分析清单中该列紧接“失败堆栈”；已产出的部分结果照常导出，原人工结论、日志链接、DDT 字段和数据校验不变。

SQLite `0096_ai_stack_groups.sql`、PostgreSQL `0095_ai_stack_groups.sql` 为作业保存分析策略，并给分组增加证据片及回填游标。旧作业使用 `legacy` 恢复，旧结论保留；重新分析使用新策略。升级前备份主库并运行正常迁移；DDL 失败会回滚，修复原因后重跑。由于存在新增作业状态，不支持旧新 Worker 混跑；降级前取消或完成新策略作业并保留备份。没有新增生产依赖、Runner 协议或基础设施配置。

弹窗仅保留整体进度、逐例结论与分页，移除“查看堆栈分组初析”的展开区；后台仍按组工作，不在列表里重复展示组报告。

本轮不新增数据库迁移、配置或 Runner 协议。证据清单使用 `stdout_business_tail_v3` 输入策略，保留 stdout 采集完整性和独立的输入处理说明，防止把旧作业的未清理正文继续发送。旧清单（包括 `stdout_business_v1`／`stdout_business_tail_v2`）继续推理会明确提示重新分析；已经保存的历史结论保留，不改写执行结果。重新分析后使用新采集与分组规则，Full 的 Web／Worker 同步升级。

## Worker 与中间件

Lite 的 Web 生命周期管理独立 AI 线程，SQLite 短事务保存状态和租约，持久队列用于唤醒，本地 ObjectStore 保存证据块。不要求 PostgreSQL、NATS、Redis 或 MinIO。

Full 每个 Worker 启动一条独立 AI 线程；Web 只提交作业和读取有界进度。所有 Worker 按主库条件租约领取不同工作，整个模型端点共用额度。Worker 数量增加不会自动放大模型并发。现有 Full Worker 启动方式不变，无需增加另一套执行机 Agent。

| 组件            | AI 链路职责                                                | 故障行为                                                         |
| --------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 主库 PostgreSQL | 作业、成员、分组、已发布结论、预算、租约和重试时刻         | 连接预算 1／AI 线程；短锁等待，繁忙时退避，不放宽执行查询期限    |
| NATS JetStream  | 主库 outbox 提交唤醒消息，普通消费车道唤醒 AI 线程         | 消息可重复；作业本身持久，扫描恢复丢失唤醒，不让调度车道执行推理 |
| Redis           | 多 Web 节点共享短时进度／报告页缓存，Worker 写入可重建进度 | 缓存失败回源主库；权威限流与租约始终在主库，不因缓存丢失而超发   |
| MinIO           | 分析输入、日志分块和证据清单                               | 对象写入失败只影响本次初析，有限重试；不会删除原日志或执行记录   |

AI 线程受父进程共享的资源压力信号约束；证据处理与模型调用之间再次检查，繁忙则持久保存等待时刻。解析、SQLite 查询与日志解压不在 Web 请求主线程运行。模型请求在数据库事务之外进行，单次有期限；模型断线不阻止原有执行、日志上传、人工分析和已有报告读取。

## 工具、数据与输出边界

采用标准 function calling 的 JSON Schema 工具和平台端执行循环，不向模型授权通用 HTTP、Shell、SQL、浏览器或平台 API Key。Worker 通过日志适配器分页取得当前工作项 stdout，清理颜色、按新长度规则分片并持久化后，以平台生成的 `read_evidence` 工具结果交给模型；没有注册让模型自行请求任意日志的读取工具。模型仅能调用 `submit_ai_conclusion` 写入该工作项的 AI 草稿。工具不接受任意成员 ID、URL、数据库字段名或写入目标。

提交后再次核对账号、权限、成员、证据引用、租约、取消和状态。模型不能修改任务配置、用例、执行状态、人工认领／分类或其他用户信息。相同堆栈只说明表现相同，初析始终需要人工确认。

模型输入仅保留用例名称、类路径、类型、实际业务输入／参数及 stdout 正文。平台通用错误码（如 TESTNG_ASSERTIONS_FAILED）、结果摘要、执行节点、时间、序号包装、stderr 和 Agent 诊断均不作为模型证据发送；原始日志存储、页面查看和日志导出不受影响。动态 JSON 和正文中的业务密码、Token 等保留源值，AI 采集不再做额外脱敏。每例证据空间预算默认 16 MiB，可配置为 1～64 MiB；执行输入正文读取保护为 8 MiB。批次证据不足时独立分析并提示限制；新单例全文分析遇到日志读取不全或超过日志预算时明确失败，不发布伪完整结论。旧作业继续保留原部分分析语义。

证据清单还限制为每例最多 4,096 块，避免低上下文配置生成巨型清单；达到限制时保留已处理范围并提示增大上下文后重新分析。上下文至少 8,192 tokens，并须为输出、工具和提示词留出预算。Lite 的初析查询直接读取有索引的持久记录，不把每个报告分页无限加入进程缓存；Full 使用 Redis 原生 TTL 缓存。

日志按适配器水位分页，证据按上下文保守分片；每片发布有效初析后续处理下一片，已有结论可先查看。完整异常块从 stdout 提取，签名规则为 exact-stack-bundle-v2：统一换行、ANSI、日志时间戳／线程前缀及帧缩进，去重排序后以平台密钥 HMAC 签名。明确已完整读取的 stdout 在文件末尾即使没有结束换行，也关闭异常块；未完整读取时仍不推断尾部。无关的输入快照缺失不再阻止相同完整堆栈归类；数字、异常消息、断言值、类路径、cause 链和行号差异仍保留。不使用只有 4,096 字符的结果摘要判断相同堆栈。

当前按一个用例中取得的完整堆栈集合排序去重后分组，组内按堆栈批量分析并统一回填简短结论；没有完整块的用例独立保留。逐个 occurrence 的多组成员映射、TestNG XML 产物解析、截图理解、历史检索、结构化事实／反证的完整目标 schema、自动格式修复以及证据自动到期清理仍需后续落实；本版不声称已经提供。

站内版本复制仍复制原有执行与业务数据范围，AI 衍生作业／证据暂不进入复制清单，目标可重新初析。自动触发另绑定实际创建的批次标识；复制历史执行不会隐式拉起模型工作，复制后的任务以后真正创建新执行时仍可按开关自动初析。

## 重试、导出与升级

临时网络错误、429 和 5xx 有限重试；平台统一控制，不叠加 SDK 自动重试。遵循合法 Retry-After，将等待时刻持久化并释放工作租约；没有提示时指数退避加抖动。模型端点共享冷却和额度，资源退让与等待额度不消耗用例分析失败次数。认证、计费、格式和权限错误直接说明原因，不无限重试。

Full 的日志平台身份由主密钥的既有 SHA-256 摘要生成，Web、后台工作线程与 AI 线程使用同一函数；不会把原始主密钥作为日志库身份。独立按日／历史固定日志库仍通过原有路由定位，不回退到主库或 SQLite。日志库读取失败时显示稳定错误码和已脱敏原因，不再保存误导性的“不完整日志”清单继续分组；日志服务临时不可用有限重试，日志池繁忙释放工作并退避。空间／分片预算或实际缺失正文仍明确提示限制，不把不完整证据当作全文。升级 Web／Worker 后重新发起 AI 分析即可采集新证据，无需重新执行原用例或修改日志数据库身份。

正常执行结果与失败分析清单均支持“AI 初步分析”列。导出开始时冻结读取时刻，逐页批量匹配 attempt；截止时已有的有效部分结论也导出，尚未生成的行置空。未创建 AI 分析时不增加列；已创建但尚无结论时列保留且单元格为空，不等待模型、不改变普通列、日志链接和 DDT 字段。导出所选尝试未分析时，不串用其他轮次结论。

新增 SQLite 迁移 `0094_ai_analysis.sql` 和 PostgreSQL 迁移 `0093_ai_analysis.sql`，仅增加 AI 表、索引及默认限流行；任务开关存储在既有版本化策略 JSON。升级前按现有流程备份主库与对象存储。回退时先关闭 AI、停止 AI Worker 并保留新表／对象，再部署旧版本；旧代码忽略新增表和缺省关闭的字段。不要直接删除尚有分析引用的证据对象，原始日志清理仍走原有流程。

## 验证记录

### 2026-11-06：50,000 字符全文规则与原值证据

首行补齐加固先复现 7 项失败，再通过 4 个文件、58 项定向回归：超过 50,000 字符后从尾部 25,000 字符的候选起点向前回溯到行首，覆盖 LF／CRLF／CR、截取点位于 CRLF 中间、恰好行首、空行、无末尾换行及 emoji。没有前置换行时保留整行，不把完整保留标记为已裁剪；JSON 原值和签名规则保持。

生产 Lite 主闭环再次通过，实际发送的超长 stdout 首行是完整业务日志行，长度介于 25,000 和 25,000＋首行长度之间。批次／单例、429、幂等、自动分析和 Excel 导出一起通过。实际查看 1024×768、1536×960 深浅色批次与单例截图（`/var/tmp/autoforge-ai-line-tail-ui-20261106/`），说明自然换行，按钮和表格没有新增溢出；Web 生产构建通过。

本地先复现旧 5,000／2,500 字符窗口会丢失日志前部异常，且 stdout 中的独立 TestNG 退出码未被排除。按现行要求调整：不足 10 例和单例提供清理颜色后的 stdout 全文；超过 50,000 个 Unicode 字符才取末尾 25,000 字符，并向前补齐首行。AI 采集不再额外替换业务密码／Token；平台自身配置密钥不加入证据。通用退出码独立行被排除，只有退出码时明确报错，不发起模型推断。原始日志不修改，10 例以上的共享堆栈与完整签名保持。

6 个文件、57 项定向回归通过，包含真实 PostgreSQL 按日日志库、MinIO、NATS、Redis 与两个 AI Worker 的 5 个场景，以及 SQLite／PostgreSQL AI 仓储。验证小组／单例在大于旧 5,000 字符阈值时仍完整发送头尾；9／10 例分界不变、排除流不发送、业务密码保留，结果不改写。文本测试覆盖 49,999／50,000／50,001 字符、emoji、跨页颜色、嵌套 JSON、长密码字段与相同尾部不误分组。

## 执行期间自动初析

任务开启自动初析后，最后允许轮次中不再重试的失败用例可以先被空闲 Worker 分析。已发布结论可立即查看／导出，作业总数会随晚完成的失败用例增长；剩余执行不等待 AI。分析按周期继续接收，同栈建议保持统一，批次结束后才关闭接收。没有失败时不请求模型。资源紧张、数据库繁忙或模型限流会继续退避；关闭 AI 或取消分析不影响执行。边界和升级／回退操作见[两轮调度窗口与渐进初析](../architecture/round-tail-scheduling.md)。
