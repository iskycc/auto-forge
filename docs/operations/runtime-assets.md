# JDK 与用例依赖资源

“项目设置 → JDK 与依赖 JAR 压缩包”按当前所选版本展示两类资源：

- JDK 的本地包显示“上传时间”，内网链接显示“登记时间”。
- 依赖包显示“更新时间”，取当前资源上传或链接登记时保存的时间；Jenkins 发布新依赖也会生成新资源和时间。
- 继承共享资源保留原始时间，不以继承操作时间、版本创建时间或 JDK 配置修改时间替代依赖内容的时间。
- 时间按平台配置的时区显示，悬浮可查看 UTC 原值；未配置资源不显示时间。

在“文件管理 → 存储空间”筛选 JDK 包或依赖包，点击文件名展开，查看“使用项目与版本”。
清单读取实际资源绑定，而非根据上传项目推断；同一资源可以显示多个项目、版本，归档项目／版本也保留并标注。
项目和版本名称最多显示两行，可悬浮查看完整名称；引用表格有独立的有界滚动区，每页 20 项，支持前后翻页和刷新。
关闭文件详情会取消读取，重新展开读取最新引用。资源当前没有引用、读取失败和加载状态分别展示，读取失败可通过“刷新引用”重试。

清单展示的是当前配置引用，不将历史执行快照列为当前使用版本。已有执行快照与删除保护保持原逻辑，
不能用“当前没有引用”代替服务端删除检查。解除某个版本绑定后，刷新引用即可看到变化，不必重新扫描文件系统。

`GET /api/v1/settings/storage/runtime-asset-usage` 与存储清单使用相同的全局 `settings.read` 权限，
接收 `runtimeAssetId`、可选 `cursor` 和 `limit`（默认 20，最多 100），返回 `items` 与可选 `nextCursor`。
项目／版本名称是读取时的当前名称，包含归档标记；兼容历史项目默认绑定，无需将其误标为具体版本。
返回使用 `private, no-store`，不依赖 Redis、NATS 或 MinIO 的缓存作为事实来源。

Lite 与 Full 使用相同应用用例、契约和 UI，分别从 SQLite／PostgreSQL 读取现有绑定表，按稳定引用 ID 做游标分页。
本次无需数据库迁移或新增配置，也不改变资源上传、执行快照、Runner 下载、继承及删除行为。
