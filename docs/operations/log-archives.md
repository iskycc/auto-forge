# 按日日志库与月度离线归档

## PostgreSQL 按日建库

Full 部署在 **平台设置 → 日志数据库 → 添加日志服务器** 填写独立日志 PostgreSQL 的主机、端口、管理员用户名和密码。账号可使用 `postgres`、已配置的 `root`，或其他具有 `CREATEDB` 权限的管理员；PostgreSQL 不会自动提供名为 root 的账号。管理员密码加密保存，不回显，不传给 Runner Agent。维护数据库默认为 `postgres`，不能指向平台业务数据库。

选择该服务器作为写入位置后，新批次首次上传时绑定服务器。平台按日志记录时间的**北京时间日期**创建数据库，例如：

```text
autoforge_logs_6fa01b2c_20261028
autoforge_logs_6fa01b2c_20261029
```

中间的标识区分服务器配置；末尾是自然日。跨日执行、延迟上传和重复上传按原记录日期定位，主库保存 attempt 的实际日期库位置，读取合并多个日期库。更换写入服务器不改变已经绑定的批次；选择、密码轮换在后续操作中生效，无需重启平台。修改连接会验证已有日期库身份，库名前缀不可修改；需要另一组前缀时新增服务器。

旧版单库和本地日志继续读取，已绑定旧库的批次保持原位置。旧单库不能再设为新批次的写入位置；升级后如果原配置仍选中旧单库，先添加并选择按日服务器，再启动新任务。平台不会在日志库故障时把该批次自动改写到其他库，也不会因读取失败而新建一个同名空库。

按日建库需要账号的建库权限、数据库所在磁盘空间和正常连接。首次写入某一天时执行日志 schema 迁移和库身份校验；失败时 Agent 保留尚未确认的 spool，修复服务或权限后重传。

## 月度归档入口

Lite 和 Full 都提供 **平台设置 → 日志归档**。生成和下载需要全平台的 `settings.manage` 与 `log.read` 权限；清理、取消需要 `settings.manage`，操作记录进入安全审计。

1. 选择执行结束月份，可在“归档选项”选择项目范围、分卷目标和磁盘安全余量，再点击“生成并校验归档包”。月份按北京时间划分，批次终态的 `updated_at` 作为结束时间；只收录已结束且没有有效上传租约的批次。
2. 后台逐页读取每个用例的全部轮次和尝试，生成压缩日志及分页索引，再由独立 Go 程序验证文件摘要、日志顺序、数量和源内容摘要。通过后才提供下载。
3. 下载并妥善保存 ZIP。建议在另一目录完整解压并打开查看器，核对需要保存的记录。
4. 点击“清理原日志”并确认。平台再次校验存储中的 ZIP 与索引，先发布归档读取位置，再删除对应正文。归档文件继续保留在平台对象存储，原公开日志链接、日志查询和版本复制继续通过归档读取。

归档以整个执行批次为单位；同一组冻结发起时已结束的范围，之后新结束的批次留待下一次归档。默认按当前源日志存储大小约 1024 MiB 分卷，每卷独立上传、校验、下载和清理。单个大批次保持完整并独立成卷，分卷目标不是 ZIP 文件硬上限。已经完成的卷不会因后续卷失败而重新生成；可对失败记录点击“重试生成”。取消当前待生成卷会停止本组继续产生后续卷。原记录重试沿用已保存选项；需要修改目标或安全余量时，取消当前卷后重新发起，既有成功卷不会重复收录。

正在运行、跨月仍未结束、仍持有有效上传租约的批次不会被截断归档。当前月份可以多次归档，每次只收录尚未被其他归档占用的已结束批次；同月可有多个压缩包。单个归档未通过校验或没有确认清理时，原日志保持不变。

执行结果、任务配置、用例及轮次历史不会被清除。归档包含日志正文和必要的执行展示元数据，不包含执行产物、报告附件、JAR、数据库密码或平台配置。不要把它当作整个平台的备份。
## 确认下载后移除平台副本

每卷在 Full 的 ZIP／索引自动存入已有 MinIO，在 Lite 保存到本地对象目录，无需另设 MinIO 凭据。默认保留以提供在线历史日志。

原日志正文清理完成后，可以在该卷选择“删除平台副本”：

1. 使用当前账号完整下载本卷。服务端对传输字节数和 SHA-256 校验通过后记录完成；仅点击下载、下载中断或内容损坏不构成有效完成记录。
2. 完整解压并在本地打开查看器；必要时运行 `--verify` 校验 ZIP。建议保存独立备份。
3. 打开删除弹窗，核对文件名和 SHA-256，勾选“我已完整下载本卷，并确认离线查看正常”，明确确认删除。
4. 后台只删除本卷的 ZIP 和范围索引。失败显示“副本删除失败”，可以重试；其他卷不会被删除。

浏览器写盘成功仍需用户自行确认，服务端传输完成不能替代这一点。删除后不可继续下载本卷，对应在线日志显示“已离线归档”，执行结果、轮次、历史记录和审计信息保留；使用已下载的 ZIP 离线查看。平台不会依据下载开始、定时到期或对象丢失自动清理，也不会把离线日志当成空日志复制。

MinIO 若配置了版本保留、对象锁或外部保留策略，实际物理空间回收以存储侧策略为准；平台移除当前对象不会绕过这些保护。此功能只作用于单卷归档 ZIP 与索引，不清理 JAR 或执行产物。

## 离线查看

ZIP 内包含三个可执行程序和开源许可：

- `viewer-windows-amd64.exe`：Windows x86_64，完整解压后双击运行。
- `viewer-linux-amd64`：Linux x86_64。
- `viewer-linux-arm64`：Linux arm64。

Linux 解压工具若未保留执行权限，可执行：

```bash
chmod +x ./viewer-linux-amd64
./viewer-linux-amd64
```

程序自动打开本机浏览器。没有图形桌面时，添加 `--no-browser` 并使用输出的本地地址。默认只监听 `127.0.0.1` 的随机端口，不提供外网监听。无需安装 Go、Node、数据库，不访问 CDN 或公网；支持批次检索、用例检索、轮次和尝试结果、分页日志、复制及深浅色主题。每次只读取当前页和所需压缩帧，不把整月日志放进浏览器。

可以手工校验压缩包：

```bash
./viewer-linux-amd64 --verify ./AutoForge_执行日志归档_202610_标识.zip
```

归档包含执行日志，应按原日志的敏感程度保管。离线查看器的访问能力来自本机文件，不连接原平台做登录或权限查询。

## 空间、失败和恢复

- SQLite：移除对应批次日志文件及 WAL／SHM，其他日志进程会关闭已移除文件的缓存句柄，释放占用。不需要对平台主数据库做全库 VACUUM。
- PostgreSQL：按有界小批次删除日志块、流和位置记录。已空、无写入引用且没有连接占用的旧日期库可回收；平台不会强制断开连接，仍有连接时由后续维护重试。
- 旧单库或仍包含其他批次的日期库，DELETE 首先形成数据库内部可复用空间，不等于已归还操作系统磁盘。平台不自动对这些库执行阻塞式 `VACUUM FULL`。
- 平台保留压缩包以维持原链接，净节省量取决于原存储与压缩后的大小。少量日志可能因内置查看器产生固定开销；管理页显示原正文与归档大小供核对。
- 生成需要临时空间：压缩帧暂存、最终 ZIP 和本地归档对象在阶段之间可能同时存在。生成前按源存储、执行尝试数量和查看器大小估算临时空间，另外默认保留 1024 MiB 与文件系统总量 10% 中的较大值。运行中持续检查安全余量；空间不足时停止并保留来源，可调整后重试。清理已验证归档和移除平台副本不受生成预算阻挡。
- 同时只允许一个重型归档工作，使用持久化状态与租约。资源紧张时让位于执行控制。Lite 在独立后台车道处理；Full 由后台 worker 处理。
- 生成／校验失败可在原记录“重试生成”，或取消本卷后重新创建。清理失败时原链接优先读取已验证归档，可在同一记录重试清理。清理开始后不支持取消。
- 源日志节点离线时，Full 本地旧日志不能凭空归档或物理清除；恢复原节点后再处理。已成功上传 MinIO 的归档不依赖原日志节点读取。
- 重启后后台接管过期租约。未完成卷从已固定的原日志范围重建，已发布卷保留；清理按批次状态继续，不会把未校验文件作为删除依据。

备份和迁移仍需一起保留平台主库、全部未归档日期库、对象存储中的 ZIP 与范围索引、旧节点本地日志，以及平台主密钥。仅下载 ZIP 可以离线查看日志，不能恢复平台身份和执行事实。

## 维护者说明

正文按约 256 KiB 的目标分帧压缩，单帧解压上限 8 MiB；单个协议日志块仍限制为 1 MiB。目录元数据分页为最多 100 条执行尝试，超大批次通过临时 SQLite 索引排序。ZIP64 的写入和完整校验使用 Go 标准库 `archive/zip`；对象存储读取使用随包生成并受摘要保护的 STORE 条目范围索引。索引／清单有独立的有界读取预算，超出时拒绝清理来源。

主平台发布物内置查看器资源和 SHA-256 清单；构建阶段可以重新生成，运行时不调用 Go 编译器、不下载依赖。按日日志与归档初版迁移为 SQLite `0087` 与 PostgreSQL `0085`，分卷及确认下载生命周期新增 SQLite `0088` 与 PostgreSQL `0086`；Full 的 Web／worker 应同步升级。迁移失败可整体回滚事务后重试；已经清理来源后不要降级到不支持归档读取的版本，应先完整备份或恢复原始日志。

## 本地验收范围

2026-10-29 使用生产构建完成 Lite 与 Full 的真实 Playwright 归档闭环，覆盖分卷、下载、确认清理、原公开日志继续读取，以及离线查看器的中文日志和分页。扩展场景验证完整下载后的独立确认、只移除指定卷、其他卷保留，以及公开页显示已离线归档并保留结果和轮次。Full 使用独立 Web／worker 和真实 PostgreSQL、NATS、Redis、MinIO，并直接核对指定卷的 ZIP／索引对象已删除、另一卷对象仍存在；日志服务器切换验证新批次写入新位置、原批次继续写入旧位置和历史公开链接读取。

另以真实 SQLite 和本地对象存储运行 20,000 个用例、10 轮共 200,000 条执行尝试的独立规模检查，覆盖全部归档、Go 校验、原正文清理和首尾日志回读。单核限制下生成与校验约 95 秒，Node 进程峰值约 258 MiB；该合成日志的源存储约 429 MiB，ZIP 约 78 MiB，不代表实际日志压缩率或集群吞吐。可单独设置 `AUTOFORGE_TEST_LOG_ARCHIVE_SCALE=1` 运行 `packages/db/test/log-archive-scale.integration.test.ts`，不要与构建或其他压力检查同时运行。

实际审查了 1024×768、1536×960 的深浅色页面截图，包括日志数据库、管理员配置弹窗、归档列表、离线批次／用例表格与日志抽屉。Linux x86_64 查看器在禁网、只读 Alpine 容器中实际启动，完成 ZIP 校验、HTTP 页面和中文日志分页；Linux arm64 与 Windows x86_64 已交叉构建和校验文件格式，未在对应宿主机实际运行。此验证不替代正式发布的完整离线安装、故障注入或百万级日志压力验收。
