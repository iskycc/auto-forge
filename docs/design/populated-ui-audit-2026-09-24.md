# 带数据 UI 复查（2026-09-24）

本轮在 v1.17.25 基础上使用生产构建和隔离的 Lite 数据目录检查页面。数据来自合成测试夹具与真实管理 API，未读取或修改生产数据库。首轮包含 65 条 DDT 用例、TestNG 类与源码来源、已结束批次、失败分析结论及离线执行机；随后补充多用户、服务账号、令牌、Webhook、执行机组和字段模板，特意使用连续英文长名称与长描述。

## 范围与方法

- 35 个页面／子页分别遍历浅色、深色和 1024×768、1536×960 两种视口，共 140 张首轮截图。
- 补充 12 个有数据的页面状态和弹窗，覆盖用户角色分配、服务账号权限、DDT 长字段预览、最近执行、存储目录和长名称分析。
- 继续补查 7 个状态，包括有分类与执行类的 DDT、回收站、源码提示和机组长描述；存储目录额外展开 SQLite 文件，检查文件行、路径及伴随文件信息。
- 通过 Playwright 读取实际布局，检查页面横向溢出、卡片越界、控件重叠、小字号与浏览器脚本错误；人工实际查看截图，检查信息层级、行列对齐、换行、按钮位置与明暗主题。
- 不以页面没有溢出代替业务验收。缺陷补充独立测试数据，验证编辑入口、完整字段值和令牌列表仍可使用；关联业务另用空白测试数据库回归。

| 页面组 | 检查范围 |
| --- | --- |
| 工作概览与质量洞察 | 有执行样本的统计、失败方法、趋势与结果颜色 |

| DDT | 概览、用例详情、高级检索、导入结果、字段模板、回收站、开放 API、SR 关联 |

| 分析 | 任务列表、我的分析、已完成结论、长名称分析弹窗 |
| 执行资源 | 执行机列表、不同 Agent 版本的操作组合、执行机组 |
| 组织与管理 | 项目版本、成员、用户、角色、LDAP、会话、账号安全、Webhook、审计 |
| 平台设置 | 配置、服务账号与令牌、保留策略、诊断、存储目录 |

## 已修复的问题

| 问题 | 触发条件与影响 | 调整 |
| --- | --- | --- |
| Webhook 卡片侵入相邻卡片 | 连续英文名称、描述触发网格隐式最小宽度；大屏下内容与相邻操作重叠，小屏下页面变宽 | 卡片内容允许收缩、长词换行，URL 在卡片内截断，操作区自动换行并底部对齐 |
| 服务账号撑宽页面 | 长账号名称或连续英文描述无法收缩，1024px 下出现页面横向滚动 | 名称与说明列允许收缩并换行，令牌操作按钮保持完整宽度 |
| 展开令牌后再次溢出 | 长令牌名称挤压使用状态和撤销按钮，回归检查测得卡片越界 56px | 令牌文字列可收缩、长词换行，状态与撤销按钮保留空间 |
| 执行机列错位 | 有升级入口和没有升级入口的行采用不同的内容宽度，实测同一信息列错位约 60px | 名称、资源与操作采用统一列比例；小桌面按一致顺序分行；搜索栏补齐上内边距 |
| 执行记录筛选多占一行 | 1024px 下“重置筛选”单独落在第三行，推低记录列表 | 搜索和重置作为同一操作组，主操作明确使用主按钮 |
| 执行机组长描述过度占高 | 长名称、长说明将同排卡片一起拉高 | 列表名称最多两行、说明最多三行；保留完整文本提示，编辑弹窗仍展示原值 |
| 源码用例提示未统一 | 原提示采用普通容器和独立图标，图标与正文分行 | 改为共享 Ant Design Alert，图标、文本与两种主题保持一致 |
| DDT 回收站编号被截断 | 沿用旧列表的勾选框列宽，连 `PAY-002` 都显示不全；较长编号无法辨认，操作按钮也可能被裁切 | 移除过时列宽，保留日期和完整操作按钮的空间，编号、SR 与来源支持换行 |

前四类布局问题及回收站编号截断已经通过修改前的浏览器检查复现。颜色检查没有发现执行记录状态文字对比度不达标，因此没有为视觉偏好改动已有状态色。数据库结构、执行调度、日志传输、数据缓存和权限判断均不涉及本次修改。

## 验证与边界

验证结果：

- `pnpm --filter @autoforge/web build`：生产构建通过；最后一轮 Playwright 在空白测试库启动前再次完成构建。
- `pnpm exec tsc --noEmit -p tsconfig.tests.json`、变更文件的 ESLint／Prettier 和 `pnpm test:e2e:matrix`：通过。
- `pnpm exec vitest run apps/web/src/components/ui-usage.test.ts apps/web/src/lib/ant-design-theme.test.ts`：18 项通过。
- `pnpm exec playwright test tests/e2e/ui-layout.spec.ts tests/e2e/management-operations.spec.ts tests/e2e/jar-import.spec.ts --grep 'populated webhook|populated service accounts|runner facts align|service account lifecycle|project webhooks support|permission selection supports|imports TestNG methods'`：空白测试库 7 项通过。覆盖新的三项布局检查，以及 JAR 导入执行与日志查看、服务账号令牌权限、项目 Webhook 绑定、批量权限选择。
- `pnpm exec playwright test tests/e2e/ddt-management.spec.ts --grep 'DDT workspace imports, edits'`：独立测试库 1 项通过。覆盖导入、字段编辑、冲突处理、批量修改、删除与恢复、API 访问，以及浅色／深色下回收站完整编号和两个操作按钮的边界。

实际查看了修复后的 1024×960、1536×960 截图：长名称、描述和令牌完整保留且不侵入相邻区域；执行机资源列边界一致；筛选和重置同行；两种主题下按钮和状态可辨。导入执行场景还复查了 1024×768、1536×1024 的公开日志、质量洞察和执行机截图。

DDT 回收站另实际查看了 1024×768、1536×1024 的修复截图，编号换行后完整可读，恢复与永久删除均在表格边界内。存储文件及 SQLite 伴随文件在 1024×960、1536×960 下复查，未发现新的横向溢出。

截图与浏览器诊断保存在本地忽略目录 `.local/ui-populated-audit-2026-09-23`，不提交图片、数据库、令牌或构建产物。自动化回归保留在 `tests/e2e/ui-layout.spec.ts` 与 `tests/e2e/ddt-management.spec.ts`，使用独立的长名称实体，不依赖旧测试执行顺序。

本轮是共享前端的 Lite 浏览器与组件验收，不等同于 Full 数据库、消息队列或真实 Runner 压力验收。布局优化不会更改现有 API、项目范围、数据库语义或后台统计刷新方式。
