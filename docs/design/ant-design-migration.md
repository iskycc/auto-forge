# Ant Design 全局界面重构

本文保留首轮迁移记录；后续组件遗漏、兼容修复和重新验收以[界面复查报告](./ant-design-ui-audit.md)为准。

本次替换全局样式体系，而不是在旧 CSS 上叠加皮肤。`globals.css` 及公开首页、系统诊断、跨版本继承弹窗的 CSS Module 已移除；主题入口改为 `apps/web/src/app/theme.css`。

## 实现边界

1. 所有页面共享颜色、圆角、字号、控件与表格规范。组件源码位于 `components/ui`，通用页面组合位于 `ui/patterns.ts`。
2. 顶栏、侧栏、工作概览、TestNG/DDT、任务、执行记录、分析、执行机、洞察、来源、组织与平台设置均使用静态 Tailwind 类；业务组件只维护自身布局和交互状态。
3. 普通表单继续使用原有保存、校验和并发修订逻辑；错误留在弹窗中，操作通知保持右上角横幅。
4. Checkbox/Radio 使用 Ant Design；多选表单值与 indeterminate 状态保留。下拉使用标准 combobox/listbox，键盘操作和浮层定位由 Ant Design 负责。
5. 原数据量控制、浏览器缓存、后台快照、目录展开加载与权限检查不变。此次没有数据库迁移或 Runner 协议变更。

## 维护规范

- 新控件优先组合 `components/ui`，页面通用排版优先使用 `ui/patterns.ts`。
- 不恢复 `globals.css`，不新增页面全局 CSS 或 CSS Module；主题外观只能读取共享语义 token。
- 复杂业务布局允许组件内静态 Tailwind 变体，动态状态不能拼接 Tailwind 类名，应提供可静态扫描的完整类。
- 日志、图表可以使用实际数值的 inline style；颜色仍使用主题变量。xterm 只在终端组件中加载自己的渲染 CSS。
- 保留 URL、可访问名称与数据边界。不得借视觉迁移改变接口请求、目录加载策略或保存顺序。

## 离线交付

完整 Ant Design CSS 从本地包编译进 `.next/static`，JS、SVG 图标和中文语言资源进入本地构建产物。发布 Docker tar 内包含静态资源与服务端依赖，不访问 CDN 或字体网站。配置见 [ADR 0014](../adr/0014-ant-design.md)。

打包脚本比较每个静态文件的内容摘要，生成 `frontend-assets.json`；缺少延迟加载脚本、CSS、组件样式或出现远程 CSS 地址时直接失败。容器验收在 `--network none` 下复核清单与 SHA-256。构建缓存和 `.next/dev` 不进入运行镜像。
