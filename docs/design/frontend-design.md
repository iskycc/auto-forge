# AutoForge 前端设计方案

状态：视觉方向与基础控件已落地，业务页面持续按本文收敛。

AutoForge 采用方案 E 作为前端视觉基线：轻盈的桌面级 Web 应用、Bento 式信息分组、柔和层次和高可读性。这里的 “Apple-like” 表示对克制、清晰、空间感和细节质量的借鉴，不表示复制 Apple 产品、商标、图标或专有设计资产。

## 设计原则

1. **先清晰，再精致**：状态、数字和主要操作必须一眼可辨，装饰不能削弱信息层级。
2. **轻盈但不稀疏**：首页允许舒展，任务表、日志和执行机列表保持专业信息密度。
3. **渐进披露**：概览展示结论，详情、筛选和高级设置在抽屉、Inspector 或二级页面展开。
4. **状态不只靠颜色**：成功、失败、运行中和离线同时使用文字、图标与颜色。
5. **离线一致**：字体、图标、图表和动画资源全部本地提供，不因断网改变布局。
6. **跨模式一致**：Lite/Full 只显示能力和规模差异，不形成两套视觉系统。

## 信息架构

一级导航固定为：

| 导航     | 主要内容                                                 |
| -------- | -------------------------------------------------------- |
| 首页     | 质量概览、活动执行、用例库、执行机群、失败洞察、最近动态 |
| 用例库   | 用例、版本、标签、分组、参数和启停状态                   |
| 用例任务 | 可复用的用例集合、执行策略与版本快照                     |
| 执行记录 | 批次、单次执行、状态、日志、产物和重试                   |
| 执行机   | Runner 状态、能力、标签、负载、版本和最近任务            |
| 洞察     | 趋势、失败分类、耗时分布、批次对比和不稳定用例           |

管理目的地数量收敛后全部提升为侧栏一级入口，不使用只有一两个子项的折叠组；关联配置合并为“访问管理”和“平台设置”，再用页内四字标签渐进披露。全局项目、版本、测试阶段切换与搜索位于顶部，三者作为一个层级跨页面共享。“开始执行”固定为顶栏主按钮，在所有授权页面打开统一弹窗；创建、密码重置、角色分配和任务复制等低频操作收纳到标题区按钮触发的居中弹窗，搜索、筛选与需要持续对照列表的配置才保留平铺。

## 页面框架

### 桌面布局

- 左侧导航：展开宽度 `232px`，收起宽度 `72px`，固定在视口左侧。
- 顶部工具区：内容高度 `64px`，搜索框最大宽度 `420px`。
- 内容区：最大宽度不强制封顶；在超宽屏上使用 `12` 列网格并限制单卡最大宽度。
- 页面内边距：`24px`；小于 `1280px` 时降为 `16px`。
- 网格间距：常规 `16px`，密集列表 `8px`。
- 右侧 Inspector：按需出现，宽度 `320–400px`，不挤压主体到不可用尺寸。

### 响应式策略

| 宽度          | 行为                                                   |
| ------------- | ------------------------------------------------------ |
| `>= 1440px`   | 完整导航，首页 4 列 Bento 网格，可显示右侧 Inspector   |
| `1024–1439px` | 导航可收起，首页 2–3 列，次要卡片换行                  |
| `768–1023px`  | 图标导航，单/双列内容，Inspector 改为抽屉              |
| `< 768px`     | 支持查看、搜索、取消等关键操作；复杂编排提示使用桌面端 |

管理平台以桌面为第一目标，但不得通过固定宽度让窄屏完全不可用。

## 设计 Token

初始 token 使用语义命名。下面的值是首版目标，落地后统一放入主题文件，不在组件中散落十六进制颜色。

### 颜色

| Token                    | Light                    | 用途                       |
| ------------------------ | ------------------------ | -------------------------- |
| `--color-canvas`         | `#F5F5F7`                | 页面底色                   |
| `--color-surface`        | `#FFFFFF`                | 卡片、侧栏、浮层           |
| `--color-surface-muted`  | `#FAFAFC`                | 次级区域                   |
| `--color-text`           | `#1D1D1F`                | 主要文字                   |
| `--color-text-secondary` | `#6E6E73`                | 辅助文字                   |
| `--color-border`         | `rgba(29, 29, 31, 0.10)` | 分隔线和描边               |
| `--color-brand`          | `#D92D20`                | AutoForge 主操作、品牌强调 |
| `--color-brand-hover`    | `#B42318`                | 主操作悬停                 |
| `--color-info`           | `#0066CC`                | 选择、链接、运行中         |
| `--color-success`        | `#248A3D`                | 成功、在线                 |
| `--color-warning`        | `#B25000`                | 警告、繁忙                 |
| `--color-danger`         | `#D70015`                | 失败、离线、危险操作       |
| `--color-accent-violet`  | `#7D55C7`                | 洞察与产物辅助系列         |

图表颜色必须按语义复用；通过率不能在不同页面随机更换主色。正文文字与背景至少满足 WCAG AA 对比度。

### 字体与数字

使用本地系统字体栈，不发起字体网络请求：

```css
font-family:
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

- 页面标题：`28/36`, `font-weight: 650`。
- 区块标题：`18/26`, `font-weight: 600`。
- 正文：`14/22`。
- 辅助文字：`12/18`，不可再小。
- KPI 数字使用 tabular numbers；日志、ID 和命令使用本地等宽字体栈。
- 中英文混排不得通过字符间空格模拟字距。

### 圆角、阴影和间距

- 控件圆角：`10px`；卡片：`16px`；大型概览卡：`20px`；胶囊标签使用全圆角。
- 卡片默认使用细描边和极浅阴影；悬浮层才增加阴影，不使用强烈玻璃模糊。
- 间距采用 `4px` 基线：`4 / 8 / 12 / 16 / 24 / 32 / 48`。
- 常规控件高度 `36px`，主要按钮 `40px`，密集表格控件可为 `32px`。

### 动效

- 微交互持续 `120–180ms`，页面级过渡不超过 `240ms`。
- 只对 opacity、transform 等低成本属性做动画。
- 实时数字变化不使用夸张跳动；状态变化可短暂高亮。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 核心组件

### App Shell

- 导航当前项使用浅蓝底、清晰图标和文字，不仅用一条细线表示。
- Lite/Full 模式放在导航底部或系统信息中，只读显示；模式切换不是随手可点的 UI 开关。
- 顶栏保留全局项目/版本/测试阶段、搜索、通知、帮助和用户菜单；三个层级选择器必须在 1024px 及以上桌面视口保持可见。

### Bento Card

- 标题、状态和局部操作保持固定位置。
- 支持 `loading`、`empty`、`error`、`forbidden` 和 `stale` 状态。
- 卡片可点击时整卡提供明确 hover/focus；内部另有按钮时避免嵌套交互。

### 表单与操作控件

- 业务页面只能使用共享的 `Button`、`Input`、`Select`、`Textarea` 组件；原生表单元素限制在组件实现内部，避免页面各自维护浏览器默认外观。
- 文本、密码、数字、文件、复选和单选输入共享边框、圆角、阴影、禁用态与焦点环 token；特定页面只能调整布局，不得重新定义一套控件视觉。
- 下拉框隐藏浏览器默认箭头并使用本地图标；多选列表保留原生键盘语义，同时使用统一表面和滚动条。
- 主、次、危险、幽灵按钮使用明确语义变体，并完整覆盖 hover、active、focus 与 disabled 状态。
- 页面和日志区域的滚动条统一使用语义颜色与细轨道，不依赖操作系统默认配色。

### 数据表

- 表头吸顶，首列可按需要固定；数字右对齐，状态和名称左对齐。
- 排序、筛选和分页状态进入 URL。
- 行操作默认收纳到更多菜单，取消、删除等危险动作需要确认。
- 大数据量使用服务端游标分页；不在客户端一次加载全部记录。

### 状态与进度

- `queued`：灰色时钟；`dispatching`：紫色路由；`running`：蓝色进度；`succeeded`：绿色勾；`failed`：红色叉；`timed_out`：橙色计时；`cancelled`：灰色停止。
- 环形图只用于少量互斥状态；超过 5 类优先条形图或表格。
- 进行中的批次同时显示百分比、完成数/总数和异常数。

### 日志查看器

- 使用虚拟列表和固定行号，支持 stdout/stderr、级别、关键字和时间筛选。
- 默认跟随最新日志，用户向上滚动后停止自动跟随并提供“回到最新”。
- ANSI 颜色经过白名单解析，禁止将日志内容作为 HTML 注入。
- 截断、断线补传和日志缺口必须在界面明确标记。

### Inspector / 抽屉

用于查看执行机、执行尝试、产物和失败细节。桌面端可固定在右侧，窄屏改为抽屉；打开状态应进入 URL 或可恢复状态。

## 关键页面蓝图

### 首页

沿用方案 E：

- 左上大卡：本周质量、趋势和关键统计。
- 中上：活动执行及当前批次摘要。
- 右上：用例库数量与快捷入口。
- 左下：执行机群，以分组和容量展示，不逐台堆满首页。
- 中下：失败洞察及高频失败用例。
- 右下：最近动态和需要处理的告警。

### 用例库

顶部提供搜索、标签和状态筛选；主体使用可排序表格。右侧 Inspector 预览版本、命令、参数和最近结果，编辑进入独立页面，避免在拥挤抽屉中完成复杂配置。

### 新建执行

采用顶栏全局弹窗。任务模式只选择一个已配置任务并直接执行，弹窗只读展示任务保存的 Runner/Runner Group、项目版本、重跑和 Adapter 地址；单用例模式才进入“选择执行机或执行机组 -> 配置执行策略”的步骤，默认启用 CoTest Adapter 并允许填写执行环境地址。任务与单用例均不提供手工参数覆盖；导入发现的 TestNG 参数只读固化。产品不再提供受管执行环境、内联环境变量或执行密文表单。

### 执行详情

页面头部展示不可混淆的最终状态；主体提供“概览 / 日志 / 产物 / 时间线”。运行中展示取消入口、租约和 Runner 状态；失败时优先显示首个有效错误和失败阶段。

### 执行机

默认显示执行机与执行机组两个工作区。执行机组按机房、网络区域或能力维护可复用成员，执行创建时固化成员快照；单机页展示 Agent 版本、协议版本、能力、标签、并发、心跳、租约、资源快照和最近任务。

### 洞察

筛选条件固定在 URL。页面主体只保留固定高度的折线趋势、失败原因饼图、样本柱状图、用例结果环图和批次变化柱状图，详细数据由每张图右上角入口在浮窗中按需展示，避免数据量增长拉长整页。浮窗表格使用视口内双向滚动、粘性表头和舒适行高；已有游标分页的数据继续保持有界分页。图表提供文本摘要和数据表替代，颜色语义与首页一致，不使用无意义的装饰性图表。

权限、状态和结果等领域枚举在界面中统一显示人类可读名称；稳定 code 只用于表单值、API 和诊断边界，不作为面向用户的主文案。权限选择控件同时给出用途说明，未知的新权限保留原 code 作为兼容兜底，避免信息被静默隐藏。

## 图标与图表

- 使用可离线打包、许可证明确的开源线性图标库；推荐评估 Lucide，锁定版本后随应用打包。
- 不复制 SF Symbols、Apple Logo 或其他专有资源。
- 默认图标尺寸 `16/20/24px`，同一控件层级不混用粗细。
- 图表优先 SVG/Canvas 本地渲染；坐标、图例、单位和空数据必须可读。
- 不用生成式图片作为正式 UI 图标。

## 可访问性与验收

- 键盘可到达所有操作，焦点环清晰且不被裁切。
- 触控/指针目标通常不小于 `36×36px`，关键操作不小于 `40×40px`。
- 表单字段有持久标签、错误说明和正确的 `aria-describedby`。
- 实时更新使用克制的 live region，不连续朗读日志流。
- 200% 缩放时主要流程仍可完成。
- 浅色模式为首版必需；深色模式只有在 token、图表、日志和 E2E 同时覆盖后才发布。

## 实施顺序

1. App Shell、主题 token、字体栈、图标和基础可访问性。
2. Button、Input、Select、Badge、Card、Table、Dialog、Drawer、Toast、Skeleton。
3. 首页 Bento 网格及假数据故事/组件测试。
4. 用例库、新建执行、执行记录和执行详情闭环。
5. 执行机与 Runner Agent 状态页面。
6. 洞察图表、窄屏适配、深色执行日志模式。

每阶段使用真实组件和固定测试数据验证，不以概念图截图作为页面背景或实现捷径。
