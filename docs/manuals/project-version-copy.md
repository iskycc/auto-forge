# 整个版本站内复制

在「项目设置」选择来源版本，点击「复制整个版本」，选择本站目标项目，再选择「新建版本」并填写名称，或选择「已有空版本」。支持同项目及跨项目复制；不合并或覆盖已有数据的版本，来源版本始终保留。该功能不是数据库离线备份或跨平台导入工具。

已有空版本必须没有测试阶段、版本运行资源配置、用例（含个人 DDT 调试数据）、导入、任务和历史执行等版本数据。目标列表按 20 条游标分页；非空版本不可选，提交时后端在短事务中再次核验，不能通过绕过界面覆盖非空目标。来源版本不能同时作为目标。

选用已有空版本时保留其名称、ID、归档状态、修订号和时间属性。复制期间预留并隐藏目标版本，测试阶段和版本资源写入也检查预留状态；PostgreSQL 通过同一版本行锁协调预留和首个写入，SQLite 通过短写事务协调。取消并清理后已有版本重新可见，原属性保留，可以再次作为复制目标；新建副本则在清理后删除。清理失败时目标继续保留并锁定，支持重试清理。

## 数据范围

- 版本测试阶段、JDK/依赖配置、普通用例及不可变版本、来源 JAR、方法元数据、来源对比和导入记录。
- 正式 DDT 用例、回收站、编辑历史、导入文件、执行类范围、SR/标签分类映射、模板、变更申请。
- 当前任务、普通/DDT 成员、任务版本快照、轮次恢复配置、计划、绑定的通知配置。
- 版本历史执行批次、执行轮次、用例执行、attempt、调度/状态历史、日志确认水位、日志、已上传产物、失败分析、认领/释放及截图和备注图片。分析重跑证明所引用的同项目执行也随副本保留。

业务 ID 会重新生成并统一映射引用；DDT CaseID、原始字段值、中文、用户参数、结果及历史时间保持原值。批次获得新的自然编号。Jenkins 凭据按目标任务及规则重新加密；用户、执行机和执行机组继续引用本站原记录，不复制账号、权限绑定、Runner 身份和租约。个人调试工作区、平台配置、系统审计和缓存不属于版本副本；复制操作另行记入原始系统审计。

本地上传的 JAR、输入文件、截图和已上传产物创建独立对象，日志写入新批次的独立日志存储；源文件清理不影响已完成副本。URL 形式的运行资源保留原地址，仍需该地址可用。既有业务 ID 公开访问授权随记录复制，但随机令牌形式的旧链接仍访问来源记录，不生成新的旧式分享串。

副本任务、计划和通知配置默认停用；尚未发送的历史通知标记为失败并说明已停止，避免重复发出。历史结果不重新执行。需要执行副本任务时，先确认目标版本和执行机配置，再显式启用。

## 一致性、容量和失败恢复

开始生成快照时，来源版本必须没有未结束的执行、导入和轮次恢复；否则显示原因，结束相关工作后重试。快照生成后来源可继续修改，副本仍表示该快照时刻的数据。引用已退役执行环境的历史批次会明确拒绝复制，避免生成缺少关联数据的副本。

HTTP 请求只持久化复制命令。Lite 使用 SQLite 持久队列与后台线程；Full 使用事务 outbox、JetStream 和后台工作器。全站同时最多一个活动复制。来源使用一致性只读快照，先分批写入私有磁盘快照，然后释放来源事务，再进行对象存储和跨节点日志 I/O。Full 的来源快照连接独立于心跳/权限检查连接。

每个集合只生成一次临时键索引，随后按最多 32 行、约 2 MiB 分页读取和短事务写入；单个已有的大快照行单独处理。不会把十万用例或全部 attempt 加载到 Web 请求或 DOM。上传对象流式校验 SHA-256 和大小；元数据行数和日志确认水位通过后，才在最终短事务中发布目标版本。发布前版本选择器和公开访问均不可见。

可关闭弹窗，稍后从相同入口查看最近复制及进度。中断或重启后从已持久化检查点继续；同一命令不会重复创建版本。失败时保留隐藏副本，提供「重试复制」或「清理副本」。取消会分批清理该复制拥有的记录、日志和对象；已有目标版本本身及源数据不受影响；清理失败可重试清理。

清理在删除元数据和日志后先持久化检查点，再删除私有快照及对象；即使最后删除版本时数据库暂时失败，也可继续清理。发起人被撤权后不能继续复制，具备完整权限的管理员仍可取消并清理该副本。

源文件缺失、校验不一致、日志缺少已确认块、数据库或节点不可达时会停止并显示原因，不静默跳过数据。私有快照保存在受控数据目录，预留磁盘余量；Lite/Full 均需足够空间存放临时快照和文件副本。已完成复制保留私有元数据快照以供诊断；不能通过公开进度 API 下载。

## 权限和接口

来源需要项目管理、用例/来源读取、任务管理、执行/日志/产物读取和分析管理权限；目标需要项目、用例、来源、任务及分析管理权限。请求及后台执行都校验发起人，后台定期重新读取当前角色，撤权/停用后停止复制。

| 方法 | 地址                                           | 行为                                                                                                                                                                      |
| ---- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET  | `/api/v1/project-version-copies?projectId=...` | 可用目标项目及最近 50 条授权范围内复制；再传 `targetProjectId` 可读取目标版本选项及 `empty` 标记（每页 20 条，`afterId` 翻页）                                            |
| POST | `/api/v1/project-version-copies`               | 提交 `sourceProjectId`、`sourceVersionId`、`targetProjectId`、幂等 `requestKey`，以及二选一的 `targetVersionName`（新建）或 `targetVersionId`（已有空版本），立即返回 202 |
| GET  | `/api/v1/project-version-copies/{copyId}`      | 有界进度，不包含内部快照、存储键、凭据和工作器租约                                                                                                                        |
| POST | `/api/v1/project-version-copies/{copyId}`      | `{ "action": "retry" }` 或 `{ "action": "cancel" }`                                                                                                                       |

## 升级与回退

新增 SQLite `0080_project_version_copies.sql`、PostgreSQL `0078_project_version_copies.sql`，包含复制状态、目标预留约束及任务/批次版本范围查询索引；无新增配置、生产依赖和 Runner 协议变化。先备份数据库与对象/日志目录，再按原有部署步骤升级。

回退前停止新复制，等待完成或取消并清理隐藏副本。旧程序不认识后台复制命令，因此不要在复制仍活动时降级；需保留新表用于审计，或在完整备份恢复后再启动旧版本。不要直接删除表来解除未完成副本的隐藏条件。

## 本次验证

- SQLite/PostgreSQL 使用同一套复制测试，覆盖文件与日志独立副本、中文 DDT 原值、任务成员和快照、Jenkins 凭据重新加密、分析截图、公开访问发布屏障、幂等、在途源拒绝、缺失日志、文件损坏、检查点重试、取消清理及清理最后阶段故障恢复、过期租约和撤权后的管理员清理。新增已有空版本覆盖同项目/跨项目、原属性保留、非空目标拒绝（含仅历史/任务/资源配置）、目标分页、复制期间写入保护、部分复制取消后保留原版本、清理失败恢复及再次使用目标。
- 新建副本链路在两种数据库均实际验证十万 DDT 任务成员复制；已有空版本扩展未重复该规模场景。测试串行运行并限制单核、4 GiB。没有把这次环境中的耗时作为其他部署的时延承诺。
- 另以 `E2E_VERSION_COPY_SCALE=1` 运行生产 Lite Playwright：实际后台工作线程在该资源配置下完成十万成员、200,020 行业务记录复制，界面仍可轮询进度并查看副本。该场景的 34 次复制相关 HTTP 请求均为 200/202，服务端记录最大 84 ms；这是本机观测值，不能保证其他部署同样的延迟。
- 新迁移覆盖全新建库、上一 schema 升级、注入失败回滚和重新应用。Full 跨节点日志端口的既有六项契约回归通过。
- 生产 Lite Playwright 分别验证新建版本、已有空版本两条跨项目复制流程、非空目标禁选及目标 ID 保留，复制后查看任务和执行历史；复制弹窗实际检查 1024×768、1536×960 浅色/深色及完成状态。执行表格在这两个视口及 2560×960 下验证分享、单行操作、拖动与持久化，并实际检查 12 张截图；无新增错位、按钮变形或横向越界。
- 完整 Full 中间件部署、真实 Runner 执行和新离线发布包断网验收本次本地未重跑；未变更 Runner/Adapter 协议和离线依赖。

针对性验证使用 `vitest run`（`--maxWorkers=1 --no-file-parallelism`）、受影响文件 ESLint、`pnpm format:check`、DB/Web/Worker 的 `typecheck`、`tsc --noEmit -p tsconfig.tests.json`、`pnpm --filter @autoforge/web build` 及 `pnpm test:e2e:matrix`。生产 Playwright 场景位于 `management-operations.spec.ts` 和 `ui-layout.spec.ts`；适配器规模测试通过 `AUTOFORGE_TEST_VERSION_COPY_SCALE=1` 启用，并通过 `AUTOFORGE_TEST_POSTGRES_URL` 连接隔离测试库。
