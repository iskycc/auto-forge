# 平台首次初始化

首次启动且尚未创建管理员时，打开 `/setup`。选择 Lite 可直接使用 SQLite 和本地存储；选择 Full 后，按组件分别填写连接信息。IP／主机名字段不填协议、端口或路径，密码按原样保存，特殊字符不需要手工转义。

## Full 配置

| 区域 | 必填信息 | 默认值与说明 |
| --- | --- | --- |
| PostgreSQL 主库 | IP／主机名、端口、数据库名、用户名、密码 | 端口 5432、库名 `autoforge`；先创建空库，账号需要 CONNECT 和 public Schema 的 USAGE、CREATE 权限 |
| PostgreSQL 日志库 | 独立服务器 IP／主机名、端口、维护数据库、库名前缀、管理员用户名和密码 | 端口 5432、维护库 `postgres`、前缀 `autoforge_logs`；账号需要 CREATEDB 或超级用户权限，自动按北京时间日期创建独立日志库 |
| Redis 缓存 | IP／主机名、端口、逻辑库编号 | 端口 6379、逻辑库 0；没有认证时用户名、密码留空，使用 ACL 时填写对应用户名 |
| NATS 消息队列 | IP／主机名、端口 | 端口 4222，需要开启 JetStream；启用 Token 认证时填写至少 16 位的 Token |
| MinIO 对象存储 | IP／主机名、API 端口、Access Key、Secret Key、Bucket、Region | API 端口 9000，不能填控制台端口 9001；先创建 Bucket，默认 `autoforge-objects`，Region 默认 `us-east-1` |

每个组件可独立配置加密连接。PostgreSQL 提供不启用 SSL、SSL 加密但不验证证书、SSL 加密并验证证书三种模式；Redis、NATS 和 MinIO 提供 TLS 开关。证书验证使用平台运行时的信任配置。

日志库与主库分别填写，可以使用不同主机、端口、账号和密码。日志维护连接不能指向主平台业务数据库。Full 必须配置独立 PostgreSQL 日志服务，引导页不再提供本地 SQLite 日志写入选项。已有 Full 部署若尚未配置，在“平台设置 → 日志数据库”中添加、检查并设为写入库后才能创建新的执行。

## 检查并保存

1. 填写页面上方的“平台配置引导令牌”，内容来自数据目录的 `config/initial-admin-token`。
2. 逐块填写配置并点击“检查连接”。检查使用当前尚未保存的内容，从平台所在主机发起；只有首次初始化尚未完成且引导令牌有效时才允许检查。
3. 主库检查连接及 Schema 权限；日志库检查建库权限与业务库分离；Redis 检查认证和 PING；NATS 检查 JetStream；MinIO 检查 Bucket，以及唯一临时对象的写入、读取和删除。每项检查都有超时，错误不会回显连接串、密码或 Token。
4. 点击“保存平台配置”，随后重启主平台。重启后使用相同的一次性令牌创建管理员。检查结果仅代表检查时刻，不替代保存和重启。

配置写入所选数据目录的 `config/platform.json`，文件权限为 `0600`。`full.logServer` 是可选的首次日志登记配置；Full 启动时只对尚未设置过写入目标的日志库注册表执行一次初始化，重复启动和并发启动不会覆盖管理员之后的写入库切换。日志仍使用现有路由记录实际写入位置，历史日志读取不受切换影响。

已有配置的引导页不会回显凭据。某块全部留空会保留原配置；修改某个组件时，完整填写该组件。正式运行后的多日志服务器管理、切换和连接更新仍在“平台设置 → 日志数据库”中操作。

“平台设置 → 平台配置 → Full 基础设施”与引导页使用同样的分区字段和连接检查，保存主库、Redis、NATS、MinIO 变更后按提示重启 Web／worker。日志配置从该分区的“管理日志数据库”进入，切换写入服务器实时生效。只读账号不能修改或检查连接，敏感字段不回显。

Full 的历史本地日志仍可读取和归档，但不能继续追加；升级前排空旧本地批次，升级后配置 PostgreSQL 日志库并重新执行。Lite 的本地 SQLite 日志保持原有行为。

使用 `deployment: distributed` 的部署文件统一管理连接信息时，继续通过各节点配置文件保持一致，引导页不会覆盖部署文件。旧版 URL 配置和旧版没有 `full.logServer` 的配置仍可读取，无需数据库迁移。
