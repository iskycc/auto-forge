# 用户手册

## 来源与用例

先在顶栏选择项目、项目版本和测试阶段，再在“用例来源”上传 TestNG JAR。导入页只读显示当前
目标层级，不提供局部覆盖；上传按该层级和 SHA-256 保存，再由后台任务进行有界静态扫描；
页面展示进度、警告、失败诊断、取消和幂等重试。扫描不会加载或执行 class。来源对比会列出
新增、变化、移除与冲突，用确认同步代替覆盖历史。用例可编辑展示名、描述、标签、分组和启停，
每次修改生成不可变版本，可从旧版本恢复成新版本。

用例管理目录中的用例名称会直接进入独立详情页；行末的眼睛按钮只用于在当前页面右侧快速预览。
详情页的“全部执行历史”按时间倒序分页加载，不设置固定的最近十条/五十条可见上限。每条执行记录
只回填一个任务总结结果：只要该批次中有一轮通过，就保留最新的通过轮次；始终没有通过时只保留
最后一轮。中间失败不会重复堆积到用例历史。拥有日志权限的用户可直接打开总结轮次的完整或实时
日志，也可返回对应任务批次查看全部轮次。页面每次最多读取 50 个执行记录，点击“加载更早的执行
历史”继续追溯，因此长期历史不会一次性占满浏览器或数据库内存。完整详情页和用例管理右侧预览
同时展示与该用例永久关联的人工失败分析结论，包括责任人、结论类别、问题说明、修改证明/问题单、
备注及重跑证明；历史证明截图可在平台内直接查看和放大。

用例详情右上角的“匿名分享”会生成永久只读链接并自动尝试复制。访问者无需登录，只能看到当前用例
的展示名、类名、版本/测试阶段友好名称、状态、参数和测试方法；源码、执行控制、执行历史以及项目
其他数据不会出现在公开页。链接本身等同只读凭据，应只发给需要查看的人；删除用例后链接失效。

用例管理中的“导入用例”用于按路径批量勾选已有用例，支持 `.xlsx`、`.csv`、`.tsv` 和 `.txt`。
XLSX 读取首个工作表第一列，首行可为“用例路径”表头；文本文件支持 UTF-8、UTF-16 和 GB18030，
兼容中文 Windows Excel 导出的 CSV。旧版 `.xls` 需先另存为 `.xlsx`，文件中的路径不会创建新用例，
只会与当前层级用例库精确匹配并勾选。文件最大 32 MiB，XLSX 首个工作表最多 100,001 行（含可选
表头），可覆盖 10 万条用例路径。

新安装默认允许最大 256 MiB 的 JAR。系统管理员可在“平台设置 → 平台配置”的“容量、会话与调度
阈值”中将上限调整为 1–256 MiB；现有安装保留原配置，保存后需重启 Web 和 worker 才会使用新
上限。扫描不限制 JAR 条目数或测试类数量；压缩大小放宽不会取消解压总量和单 class 大小等安全边界。

### DDT 管理

用例管理顶部可切换到“DDT 管理”。DDT 用例与 TestNG 用例共享顶栏项目层级和权限，但自身保存
的是动态字段数据，不会把 CaseID 当成 Java class。普通表格使用名为 `data` 的 Sheet，首行必须包含 `CaseID`
和 `srNum`；用户旅程使用连续的 `step1`、`step2`… Sheet，各 Step 的行数、CaseID 和 srNum 必须
一致。平台支持 XLSX、XLS、XLSB、CSV、ODS，或把这些文件放在 ZIP 根目录/一层子目录中批量上传。
导入弹窗既可点击选择文件，也可把一个或多个受支持文件直接拖入上传区域；拖入时会高亮提示，
不受支持的格式会在开始预检前明确拒绝。

导入先显示逐文件预检，损坏文件不会阻止其他有效文件确认。确认时选择“覆盖并保留历史”“跳过
已有用例”或“遇到冲突终止”，随后在“导入任务”查看进度、取消、失败原因和本次 CaseID 导出。
列表支持 CaseID 前缀、srNum 和动态字段条件筛选；选择用例后可批量修改、导出或移入回收站。
详情编辑、导入覆盖、批量修改和历史恢复都会生成永久差异记录。字段模板按 srNum 设置必填和类型
规则；回收站恢复遇到同名 CaseID 时会拒绝，永久删除需再次确认。

执行 DDT 前，先在列表选择一条或多条用例并点击“设置执行类”，再从当前项目版本和测试阶段的
普通 TestNG 用例中选择人类友好名称；完整类路径会作为辅助信息显示。一次保存会把同一个执行类
批量应用到所有选中 CaseID。随后点击“加入用例任务”即可与普通用例混合编排。任务详情会用
“普通用例”与“DDT”标识区分类型：普通用例仍按包路径分组，DDT 用例固定以 SR 作为文件夹。
未设置执行类、执行类停用/归档，或任务没有启用 CoTest Adapter 时，执行预检会列出具体的 DDT
CaseID 并拒绝启动。

仍属于任一用例任务的 DDT 用例不能直接移入回收站。平台会提示先在任务详情中移除该成员，以免
一次删除操作绕过任务版本记录、静默改变后续批跑范围；移除完成后即可正常删除或批量删除。

批次创建时会为每个 DDT CaseID 固化一份独立的 `classDataFile` JSON，Runner 下载并校验后传给
现有 CoTest Adapter；任务运行期间修改 DDT 数据或普通用例映射不会改变已经开始的批次。执行详情
的每一行会显示“普通用例”或“DDT”，DDT 行同时显示 SR 和实际执行类路径，方便确认本次运行来源。

单文件上限 128 MiB，一次最多 200 个上传文件且总计不超过 512 MiB。上传原件作为导入来源证据
保存在当前项目对象空间。DDT API 复用平台服务账号令牌和 `case.read`/`case.manage` 权限；完整
接口与重复能力融合结论见 [DDT 管理与融合说明](../architecture/ddt-management.md)。

导入页同时接受包含 `.class` 的普通测试 JAR 和包含 `.java` 的 `*-sources.jar`：

- 普通测试 JAR 继续通过 class 注解发现 TestNG 用例，可作为 Agent 执行输入；如果归档中同时
  带有匹配的 Java 源文件，用例详情也会显示源码。
- sources JAR 通过受限的 Java 词法/声明扫描发现 `org.testng.annotations.Test` 类和方法，导入
  后可在用例详情查看完整 UTF-8 源文件。它不会被编译或执行，也不能作为 Agent 执行输入；需要
  执行时应另外导入包含 `.class` 的测试 JAR。
- 源码发现覆盖顶层类中的类级/方法级 `@Test` 及常用属性，不冒充 Java 编译器；源码继承、注解
  处理器、Lombok/代码生成和运行期动态测试不会展开，并会在扫描结果中显示有界能力警告。
- 源文件查看会重新校验导入快照中的条目路径、大小与 SHA-256。绝对路径、目录穿越、非 UTF-8、
  超大单文件或解压膨胀归档都会被拒绝或产生明确警告；条目数量本身不作为拒绝条件。

## 任务配置与执行

用例任务支持复制、归档、启停、普通/DDT 批量成员和版本快照。任务保存 Runner/Runner Group、项目版本、
优先级、基础并发、动态重跑并发、轮次间 Jenkins 环境恢复、重试、排队/领取/上传恢复时限、Adapter 地址，以及全局产物收集开启时的
产物规则。单个用例的执行时限只使用“平台配置”中的全局值，任务不再提供第二个执行超时。
首次执行按资源评分选择 Runner，并按稳定用例顺序分散 Adapter 环境；同一用例的后续重试按
稳定 Runner ID 和完整 Adapter 环境池分别轮询，只有候选节点或环境不足时才循环复用。
点击“创建任务”时可以选择“空白创建”或“复制已有任务”。复制会在当前项目版本内新建独立任务、
普通/DDT 成员记录、执行策略、恢复配置和首个版本快照，完成后直接进入副本详情继续修改；副本与来源任务
不会共享成员记录，修改或删除任一方不会影响另一方。为避免意外产生外部副作用，执行历史、计划触发和
Webhook 绑定不会复制。
计划触发使用显式时区、暂停和错过触发策略。任务详情中的普通用例包目录和 DDT 的 SR 目录默认
收起，展开后每次显示 100 个用例，其余成员通过“加载更多用例”继续读取，避免大型任务一次挂载
过多页面元素。

“动态重跑并发”仅用于整轮轮次模式。每条规则可组合一个判断轮次、上一轮通过率范围和本轮剩余用例
范围。规则按页面顺序形成阶段：只在指定轮次内判断，命中后并发会从本轮开始持续生效；后续即使
条件不再满足也不会恢复基础并发，只有列表中排在当前阶段之后的规则在自己的指定轮次命中才会切换。
规则在该轮结束前未命中时不会在更晚轮次补判；所有规则从未命中时才使用基础并发。首轮编号为 1，
因此第一次重跑是第 2 轮。上一轮通过率只统计已完成的成功、失败、超时或取消用例，正在执行的
用例不进入分母。批次会按轮次固化实际生效的并发数，轮次表可直接复盘；动态规则首次切换时
同时显示“已变更”并写入总体调度日志，记录原并发、新并发、上一轮通过率和剩余用例数。

“轮次间环境恢复”可在第 N 轮结束后暂停，Rebuild 配置的 Jenkins 任务上一次流水线。同一轮可以
配置多个环境恢复步骤，平台会并行触发；每个步骤从自己的 Jenkins 构建成功时开始计算等待时间，
只有全部步骤都完成构建并结束各自等待后才继续第 N+1 轮。Jenkins 成功后的下一轮调度会持久重试，
即使平台进程在交接期间重启也不会重新触发 Jenkins 或永久挂起批次。任务链接填写 Jenkins job 页面链接；API 密钥使用单个
`用户名:API Token` 字段，保存后只显示“已配置”，不会回显。此功能要求 Jenkins 安装 Rebuilder
插件，账号拥有读取和构建该 job 的权限，并且 AutoForge 已配置平台主密钥。Jenkins 构建失败会
显示为执行异常；终止 AutoForge 批次不会尝试终止已经在 Jenkins 中启动的外部构建，但会取消
平台内尚未继续的轮次。保存前可使用每条规则的“测试配置”读取任务名称、可构建/排队状态和上一
构建；该测试只调用 Jenkins 只读 API，不会触发 Rebuild 或普通构建。已保存规则留空密钥时会在
服务端解密使用原密钥，明文仍不会返回浏览器。

等待整轮结束、Jenkins 构建和构建后等待均不消耗用例的排队超时时间。平台只在下一轮真正释放时
按任务的“排队超时”重新开始计时；立即重跑和 Runner 故障回排也从重新可调度时刻获得完整的新
窗口。Jenkins 返回明确失败结果时任务仍立即显示执行异常；如果只是一次状态查询超时或网络抖动，
平台会持久化并自动退避重试，连续 10 次无法读取状态后才终止恢复。

执行详情的轮次表会在触发边界插入“环境恢复”节点，暂停时间会计入任务总时长。点击该节点可分别
查看每条 Jenkins 流水线的构建号、实际开始/结束时间、构建结果、构建耗时和成功后等待分钟数；
同轮配置多个恢复步骤时会显示多张任务卡片，不会只展示最慢的一个。

Jenkins `autoforgeRun` 启动后先输出七天有效的匿名实时进度链接。批次到达终态后，插件再输出永久
匿名结果链接，并通过返回值 `resultUrl` 交给 Pipeline；执行记录列表也可为任何状态的批次生成同一类
永久链接。匿名页与执行历史详情保持一致，展示批次概览、轮次、结果图表、用例表格和已固化的结构化
TestNG 结果，但不加载平台侧栏，也不开放产物、导出、调度事件或执行操作。每条已经产生执行尝试的
用例提供“查看公开日志”，直接沿用批次永久分享凭据读取该用例的日志及同一用例的其他轮次；服务端
会再次校验批次与 ExecutionRun 边界，不能通过替换 attempt ID 访问其他任务。公开页最多读取并展示
前 512 KiB 日志，避免超大日志拖慢页面。用例断言失败但调度和 Runner 生命周期完整时，批次仍是
“执行完成”。

任务完全结束且仍有失败或超时用例时，批次详情提供“重新执行最后一轮”。新批次只包含最终仍未通过的
用例，从原批次不可变快照继承版本、Runner、Adapter 资产、超时与重跑策略。弹窗可单独设置本次基础并发，
并可仅对本次关闭动态并发规则或 Jenkins 环境恢复；不会改写原任务。这种重跑是正常的新执行记录，可在
执行历史中追踪。

任务必须绑定一个处于活跃状态的项目版本，且只能加入该版本的用例。顶栏切换版本后，用例任务、
快捷执行、执行记录、质量洞察和计划作业只展示当前版本的数据；界面展示版本名称，不要求用户识别
内部 ID。已有任务只有在不包含其他版本用例时才能切换版本；无法确定版本的历史任务在修复关联前
保留详情和审计读取，但不能继续执行。

顶栏“开始执行”的任务模式只需选择任务即可直接执行，运行时以任务保存的版本化配置为唯一来源；
单用例模式可临时选择 Runner/Runner Group、配置重跑和 Adapter 地址，并默认勾选 CoTest Adapter。任务与单用例都不提供手工参数覆盖；导入发现的 TestNG 参数作为只读版本元数据执行。产品不提供受管执行环境、
任意环境变量或执行密文注入。创建批次前，平台逐项检查用例/来源、Runner 能力、Java/TestNG、
项目版本依赖、资源和磁盘限制。

单次用例状态含：`queued` 等待调度，`assigned` 已分配，`running` 执行中，`succeeded` 通过，
`failed` 断言失败，`timed_out` 超时，`cancelled` 取消。任务批次使用生命周期状态：所有用例正常
跑完（无论断言是否通过）显示“执行完成”，基础设施异常显示“执行异常”，人为取消或中断显示
“执行中断”。重跑策略可创建下一 attempt；历史 attempt、lease、Runner、失败阶段、UTC 时间和
状态事件均保留。

轮次用例表的状态筛选覆盖“已分配”和“执行中”，可直接定位已经领取且尚未结束的用例；“未执行”
只表示当前轮尚未产生 attempt 的用例。表格搜索、状态筛选、排序和每页 20–500 条都在服务端执行；
页面只读取当前页，轮次/Runner/最终结果使用数据库聚合，因此 10 万用例批次不会先下载或渲染全量
run/attempt。活动批次刷新同样只重读聚合与当前页。

轮次页的“导出结果”可选标准执行结果或“失败用例分析清单”，两者都支持当前轮次、
全部轮次与最终结果范围。分析清单只导出正常失败或异常结束的用例，且仅包含用例编号（用例
类路径）、用例名称、失败堆栈、分析责任人、分析结果、问题根因、问题单号或用例修改证明、重跑通过截图、
备注和用例日志链接。“分析结果”使用 Excel 三选一下拉框：重跑通过、用例问题已修改、代码问题已提单；
工作簿使用适合中英文混排的微软雅黑 UI 字体、深色表头、低饱和斑马纹和三类结论配色；待分析列使用
浅色背景和适宜列宽，数据行保持单行紧凑高度。通过“用例分析”主页任务卡片或详情页的
“导出分析结果”可随时导出最终失败清单：未认领或尚未完成的字段保留空白，已经认领的责任人以及已
提交的结论、问题根因、修改证明/问题单、重跑日志或截图证明和备注会自动回填；用例日志仍使用永久
公开链接。

## 日志、产物与洞察

### 用例分析

主导航“用例分析”用于分工处理批跑中的最终失败用例。可选记录必须是当前项目版本下由真实用例任务
发起、已经进入终态的普通执行批次；单用例执行、日志诊断重跑、最后失败再次执行和仍在运行的批次
不会进入分析范围。认领池严格读取任务 `currentRound` 对应的最后一轮，只展示该轮执行结果为失败且
最终结果仍为失败的用例；较早轮次失败但最后一轮通过、超时、取消和调度异常不会混入三个业务失败
类别。可以按类路径、用例名称、失败堆栈或认领状态排序，也可以使用类路径、名称和堆栈关键字筛选。
列表每页最多读取 50 条，较大批次通过游标继续翻页，不会一次渲染全部失败用例。
当前 Tab 与任务标题同时由服务端返回，“认领失败用例”和“我的分析”中的隐藏 Tab 仅在切换后取数；连续筛选或排序会取消已过期请求，
不会让较慢的旧响应覆盖新条件。表格筛选和摘要预览最多读取失败摘要前 8,192 个字符；完整
stdout/stderr 与堆栈仍通过“弹窗日志”或“公开日志”按需读取。Lite/Full 都以 10 万条最终失败
记录验证主页聚合、四种排序、搜索、认领、证明和批量提交路径。

用例分析主页为每个可分析任务提供“查看用例分析详情”入口，并展示最终轮次、最终失败数、已认领数和
已完成分析数。进入详情并勾选待处理用例后，页面底部悬浮按钮会显示已选数量；点击“认领并进入分析”后进入“我的分析”。同一
执行用例只能由一人认领，多人同时提交时数据库事务决定唯一认领人，其余用户会收到冲突数量提示。
认领人用户名和显示名、认领时间、当前状态以及后续类别都保存在平台数据库中；URL 同时记住当前
执行记录和“认领/我的分析”步骤，因此刷新、退出登录或换浏览器后可以直接继续。

在“我的分析”中可按类路径、用例名称、失败堆栈或分析状态进行服务端排序并切换升降序；排序条件会
进入分页游标，翻页后不会退回固定顺序。候选表、个人分析队列及弹窗内用例清单均使用紧凑行距。
可打开单个用例，也可勾选多个用例后使用悬浮按钮批量分析。弹窗先展示用例名称、
类路径、最终失败轮次和失败概要，并提供弹窗日志与永久公开日志入口。分析必须选择且只能选择一个
结论：重跑通过、用例问题已修改、代码问题已提单；三种结论均可填写备注。选择“重跑通过”时，平台
会自动查找从该用例公开日志页发起且已成功的重跑，并把成功 attempt 的永久公开日志链接保存为证明；
没有成功重跑时，在分析弹窗任意位置直接按 `Ctrl+V`（macOS 为 `⌘+V`）粘贴 PNG/JPEG/WebP
通过截图；粘贴区不再打开系统文件选择器。截图在 Lite 保存到本地对象目录，在 Full 保存到 MinIO。
已粘贴截图会直接显示在分析详情中，点击缩略图可在当前页面放大至
50%～300%；导出的 XLSX 使用可直接打开原图的链接。选择“用例问题已修改”时，问题说明和用例修改证明必填，提交前还必须在二次
风险弹窗中确认确为用例问题；选择“代码问题已提单”时，问题说明以及问题单链接或编号必填。完成结果、
责任人、证明和时间均持久化，刷新或重新登录后仍可查看。分析弹窗还会按用例读取最近的历史人工
结论；单用例存在上一条“代码问题已提单”结论时，可以继承其问题说明、问题单和备注，但必须先在
二次强提醒中确认问题单尚未闭环、当前失败仍由同一问题引起。批量分析只展示各用例自己的历史，不
会把一个用例的问题单自动套用到其他用例。

执行详情分页读取 stdout/stderr/agent 日志，可按关键字和后台配置的平台时区筛选（默认 `Asia/Shanghai`，UTC+8；数据仍以 UTC 保存）。ANSI 仅渲染安全 SGR
样式；控制序列与链接被移除，缺口/截断/补传状态有文字标识。日志区域可使用独立深色模式。类名、
包名和普通关键字原样展示；平台只保护任务已知密文与明确的 Bearer、密码、Token、API Key 凭据
格式，不再根据点分字符串形状猜测并替换日志内容。

用例执行日志不写入主数据库：每个执行批次的日志块存放于独立 SQLite 文件
（`<数据目录>/attempt-logs/<批次ID>.sqlite`，Lite 与 Full 一致），主库仅记录该文件路径、
用例成功/失败结果和失败摘要。控制面优先读取 Adapter 的 UTF-8 机器标记；旧日志没有标记时
才从日志中查找异常行。失败描述保留完整多行内容，不按页面长度截断，也不会替换成
“类路径#测试方法 执行失败”，并同时显示在批次详情和日志公开访问页。批次删除或保留期清理时，
对应日志文件一并删除。

单次 attempt 可以生成永久匿名日志链接。该链接以签发时的用例执行记录为授权边界，侧边栏按
时间顺序展示同一批次、同一用例的全部已完成轮次、结果、完成时间和耗时；点击轮次会在当前
标签页替换日志并保留浏览器前进/后退历史。其他用例或其他批次的 attempt ID 不在该链接的授权
范围内。正在执行的轮次到达终态后才会出现在匿名轮次列表中，匿名页不提供实时日志订阅。
终态用例的“查看日志”弹窗和永久公开日志页都提供“执行此用例”：它使用原批次的固化配置进行一次单用例诊断重跑；连续提交同一用例时，会从上一次实际使用的 Runner 和 Adapter 环境的下一项继续轮询，
不进入执行历史、质量洞察、平台统计、Webhook 或完成通知。调度产生 attempt 后，原日志弹窗会自动出现“查看实时日志”；
永久日志详情侧栏也会立即新增“手动重跑 · 执行中”记录，登录用户点击该记录后可在当前页面打开实时日志，完成后刷新为
最终结果。记录显示操作人用户名及本地/LDAP 身份来源。公开链接允许匿名阅读已持久化日志，但发起执行和 WebSocket 实时订阅
仍须登录；发起执行还须同时拥有对应项目的日志读取和执行创建权限，永久分享令牌本身不能用于发起执行。

执行详情的轮次总数按轮次资格计算：初始轮次为批次全部用例，后续重跑轮次为上一轮失败或超时
用例；“全部轮次”是各轮总数、通过、失败和未执行的逐项相加。运行中的轮次也会实时展示尚未
产生 attempt 的未执行数。单轮通过率只以该轮终态 attempt 为分母，assigned/running 不会被当作
未通过。终态 attempt 行不再提供取消按钮；待调度的当前/后续轮次占位行仍可取消。
进行中批次每五秒只拉取一次有界概要并局部更新指标、轮次和当前用例页，不再刷新整个页面；当前
筛选、分页、已展开行和滚动位置会保留，刷新期间也不会先清空当前列表。

批次详情提供三层执行日志，均以终端风格弹窗展示：总体调度日志记录每轮调度分配、用例-执行机
绑定、领取与完成结果，以及低频的执行机资源快照；单个执行机调度日志按 Runner 过滤同一事件流，
保证每个经过该 Runner 的调度都可定位；单个用例日志即对应 attempt 的 stdout/stderr/agent
输出流，入口保持原有“查看日志”。调度日志先展示最新一页并默认定位末尾，随后自动反向补齐历史；
同一页面内再次打开会立即复用有界缓存，只增量查询新事件。事件行使用窗口化渲染，打开期间按 3 秒
增量轮询刷新，不需要手工“加载更多”。

产物下载会校验项目权限、对象归属、大小和摘要，并使用安全媒体类型与下载头；仅白名单文本、
图片和报告可受控预览。洞察从已确认 attempt 重建，显示样本数、成功/失败/跳过、P50/P95、趋势、
失败签名和 flaky 置信；失败签名保留异常类名和消息的原始大小写，仅将 UUID、整数和连续空白等动态内容归一化以聚合同类失败。
质量洞察的筛选、不稳定用例分析和批次对比在提交后立即显示加载反馈。正常 TestNG 断言或配置失败
只展示错误堆栈/错误信息，不展示内部结果码；调度、Runner、超时等非正常执行失败同时展示稳定错误码
与可读错误信息。页面导航和大数据区域使用统一加载状态；保存、删除和测试连接等一次性结果在右上角
按成功、警告、错误或提示分色展示，危险操作统一在平台弹窗内确认，不再调用浏览器原生确认框。
工作台与洞察统计直接在 SQLite/PostgreSQL 中聚合，不再读取最多 100,000 条明细后在 Web 进程计算；
超过 10 万次的历史样本仍会继续准确增长。工作台只读取趋势和高频失败等首屏数据，完整洞察才计算
分位耗时、维度与不稳定用例。
不稳定用例可在卡片内单独指定任务和起止时间。批次样本范围不同时不会直接比较总体百分比。导出在后台生成有界 CSV/JSON，
可取消并在完成后下载。

## 管理中心与执行机

主导航“管理中心”提供用户管理、角色权限、项目成员、LDAP、会话管理和平台配置的明确入口。
LDAP 目录配置使用一个服务地址：`ldap://` 表示明文 LDAP，`ldaps://` 表示隐式 TLS；填写
`ldap://` 的 636/3269 端口时平台会自动规范为 `ldaps://`。配置字段与 DDT Insight 一致，不再
提供 StartTLS 模式、私有 CA、分页/全量同步或用户名映射属性。Bind DN 和密码可以留空，用于允许
匿名搜索的目录；填写 Bind DN 时必须提供加密保存且不回显的 Bind 密码。服务器证书默认校验；
管理员为隔离的旧目录关闭校验时，页面会持续显示安全风险提示。历史扩展字段只保留数据库升级
兼容，不参与新的连接与登录流程。

用户过滤器必须使用 `{{username}}`，平台会在查询前按 LDAP 过滤器规则转义登录名。登录流程与
DDT Insight 一致：过滤器唯一命中用户后使用结果 DN 校验密码，并直接以登录框中的用户名创建或
更新平台账号，不读取额外的用户名映射属性。首次建号时统一分配配置的默认平台角色；后续登录不会
根据目录 Group 修改角色或权限。未配置 Group Search Base 时读取用户条目的 `memberOf` 等多值
属性；配置后使用 `{{userDn}}` 或 `{{username}}` 搜索组，并读取 `cn` 等名称。获取到的 Group 只保存
到用户资料供管理员查看，不参与鉴权。平台不执行目录全量同步，因此 LDAP 组织数量不会导致保存
配置或登录时遍历整个目录。已有本地同名账号始终先走本地认证，已停用 LDAP 账号会在访问目录前
直接拒绝。升级前遗留的目录身份与同名 LDAP 账号不一致时，登录名对应的平台账号优先，平台只修复
辅助目录身份关联，不删除或合并历史用户数据。若 LDAP 已验证成功但账号关联仍失败，登录页会展示
请求 ID，管理员可据此在服务端日志中定位具体数据库错误。
角色、服务账号、项目作用域与 API 令牌的权限都以复选框展示，可直接逐项勾选，并同时显示权限的
中文名称与用途说明，不需要按住 Ctrl 或 Command。

执行机页面的“探测并核验主机”支持 OpenSSH Password 与 Keyboard-Interactive/PAM 密码认证。
探测不要求先配置 Agent 控制面地址；安装前仍须配置执行机可访问的 HTTP 或 HTTPS 地址，可信内网
可直接使用 IP。失败信息会区分 DNS、端口拒绝、超时、认证、握手、systemd、cgroup v2 与 sudo
前置条件。首次安装成功后，平台以 AES-256-GCM 保存主机、端口、用户名、密码和可选私有
CA；浏览器只读取不含密码的摘要。使用已保存连接重新安装时仍会先探测主机，再展示名称、标签、
并发、终端策略、运行账号和数据目录供管理员确认或修正。批量升级复用加密连接档案，但只替换
Agent 与 Adapter 程序，不重写远端配置、systemd unit、身份或数据目录。

执行机注销（deregister）后，其凭据立即失效且不能再认证；此时可以在执行机列表中删除该记录，
删除后从列表移除且永不恢复，历史执行记录中的执行机引用仍保留。未注销的执行机不允许删除。
JDK 与依赖 JAR 压缩包按项目版本管理。通过界面上传时先在平台数据目录暂存并校验格式与摘要，
再写入对象存储；数据目录磁盘不足时上传会明确报错，而不会写入不完整文件。版本可显式继承另一
版本的资源引用而不复制文件；删除只解除当前版本引用，仍被其他版本或活动批次使用的对象不会回收。

当平台内置 Agent 版本高于执行机当前版本时，执行机列表会显示“可更新至 x.y.z”标记。批量升级
只替换 Agent/Adapter 程序并重启服务：远端配置文件、systemd unit、执行机身份、凭据、名称、
标签、并发配置与历史执行记录全部保留。需要修改配置时应使用自动安装面板明确填写并重新安装；
单机更新表单中显式填写的部署配置则按本轮请求生效。更新前自动备份当前版本，失败时可在自动
安装面板执行“回滚上次安装”。已注销的执行机不能原地更新。

执行机列表使用紧凑行，只保留状态、平台/Agent、容量资源、心跳和操作。项目任务已经下发自己的
JDK 与依赖时，主机探测到的 Java/TestNG 版本不会阻止该执行机调度。直连终端右上角可铺满当前
浏览器视口，再次点击或按 Escape 可先还原窗口，xterm 的行列数会随窗口尺寸自动调整。

“平台运维 → 系统诊断”会列出队列死信的任务类型、关联对象、最后错误、投递次数和失败时间。管理员
应先根据错误信息修复根因，再确认“重新投递全部”；单次最多处理 100 个，重新投递后从第一次投递
重新计数。若根因仍存在，任务会按正常重试预算再次进入死信，平台不会静默删除失败证据。

“平台设置 → 存储空间”用于分析 AutoForge 实际数据占用。概览分别显示文件逻辑大小与平台实际占用；
文件按“数据目录 / 对象存储 / 外部引用”和逻辑路径直接组成可折叠目录树，不需要逐页翻看。展开文件
可查看完整逻辑路径、实际位置、大小、磁盘占用、所属项目与更新时间；单个目录内容很多时可继续加载该
目录的下一组节点，不会一次渲染全部文件导致页面卡顿。目录可按类型、名称或路径筛选，覆盖 SQLite
主库、WAL/SHM、每批次日志库、JDK、依赖包、用例来源、DDT 导入、执行产物、导出与配置文件。
Lite 展示数据目录中的绝对位置；Full 同时展示本地日志 SQLite 与 MinIO 对象键。通过 HTTP(S) 登记
的 JDK/依赖显示为外部引用：声明大小计入内容规模，但平台占用为 0。MinIO 只能返回对象内容大小，
副本或纠删码开销仍需在 MinIO 运维侧查看。页面不会扫描容器镜像、程序源码或数据目录之外的宿主机文件。
