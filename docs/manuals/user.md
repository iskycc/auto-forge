# 用户手册

## 来源与用例

在“用例来源”上传 TestNG JAR。上传先按项目和 SHA-256 保存，再由后台任务进行有界静态扫描；
页面展示进度、警告、失败诊断、取消和幂等重试。扫描不会加载或执行 class。来源对比会列出
新增、变化、移除与冲突，用确认同步代替覆盖历史。用例可编辑展示名、描述、标签、分组和启停，
每次修改生成不可变版本，可从旧版本恢复成新版本。

新安装默认允许最大 256 MiB 的 JAR。系统管理员可在“管理中心 → 平台配置”的“容量、会话与调度
阈值”中将上限调整为 1–256 MiB；现有安装保留原配置，保存后需重启 Web 和 worker 才会使用新
上限。压缩大小放宽不会取消条目数、解压总量、单 class 大小和测试类数量等安全边界。

导入页同时接受包含 `.class` 的普通测试 JAR 和包含 `.java` 的 `*-sources.jar`：

- 普通测试 JAR 继续通过 class 注解发现 TestNG 用例，可作为 Agent 执行输入；如果归档中同时
  带有匹配的 Java 源文件，用例详情也会显示源码。
- sources JAR 通过受限的 Java 词法/声明扫描发现 `org.testng.annotations.Test` 类和方法，导入
  后可在用例详情查看完整 UTF-8 源文件。它不会被编译或执行，也不能作为 Agent 执行输入；需要
  执行时应另外导入包含 `.class` 的测试 JAR。
- 源码发现覆盖顶层类中的类级/方法级 `@Test` 及常用属性，不冒充 Java 编译器；源码继承、注解
  处理器、Lombok/代码生成和运行期动态测试不会展开，并会在扫描结果中显示有界能力警告。
- 源文件查看会重新校验导入快照中的条目路径、大小与 SHA-256。绝对路径、目录穿越、非 UTF-8、
  超大单文件、超量条目或解压膨胀归档都会被拒绝或产生明确警告。

## 任务配置与执行

用例任务支持复制、归档、启停、批量成员和版本快照。任务保存 Runner/Runner Group、项目版本、
优先级、并发、重试、排队/领取/上传恢复时限、Adapter 地址，以及全局产物收集开启时的
产物规则。单个用例的执行时限只使用“平台配置”中的全局值，任务不再提供第二个执行超时。
计划触发使用显式时区、暂停和错过触发策略。

顶栏“开始执行”的任务模式只需选择任务即可直接执行，运行时以任务保存的版本化配置为唯一来源；
单用例模式可临时选择 Runner/Runner Group、配置重跑和 Adapter 地址，并默认勾选 CoTest Adapter。任务与单用例都不提供手工参数覆盖；导入发现的 TestNG 参数作为只读版本元数据执行。产品不提供受管执行环境、
任意环境变量或执行密文注入。创建批次前，平台逐项检查用例/来源、Runner 能力、Java/TestNG、
项目版本依赖、资源和磁盘限制。

单次用例状态含：`queued` 等待调度，`assigned` 已分配，`running` 执行中，`succeeded` 通过，
`failed` 断言失败，`timed_out` 超时，`cancelled` 取消。任务批次使用生命周期状态：所有用例正常
跑完（无论断言是否通过）显示“执行完成”，基础设施异常显示“执行异常”，人为取消或中断显示
“执行中断”。重跑策略可创建下一 attempt；历史 attempt、lease、Runner、失败阶段、UTC 时间和
状态事件均保留。

## 日志、产物与洞察

执行详情分页读取 stdout/stderr/agent 日志，可按关键字和 UTC 时间筛选。ANSI 仅渲染安全 SGR
样式；控制序列与链接被移除，缺口/截断/补传状态有文字标识。日志区域可使用独立深色模式。

用例执行日志不写入主数据库：每个执行批次的日志块存放于独立 SQLite 文件
（`<数据目录>/attempt-logs/<批次ID>.sqlite`，Lite 与 Full 一致），主库仅记录该文件路径、
用例成功/失败结果和失败摘要。控制面优先读取 Adapter 的 UTF-8 机器标记；旧日志没有标记时
才从日志中查找异常行。失败描述保留完整多行内容，不按页面长度截断，也不会替换成
“类路径#测试方法 执行失败”，并同时显示在批次详情和日志公开访问页。批次删除或保留期清理时，
对应日志文件一并删除。

执行详情的轮次总数按轮次资格计算：初始轮次为批次全部用例，后续重跑轮次为上一轮失败或超时
用例；“全部轮次”是各轮总数、通过、失败和未执行的逐项相加。运行中的轮次也会实时展示尚未
产生 attempt 的未执行数。终态 attempt 行不再提供取消按钮；待调度的当前/后续轮次占位行仍可取消。

批次详情提供三层执行日志，均以终端风格弹窗展示：总体调度日志记录每轮调度分配、用例-执行机
绑定、领取与完成结果，以及低频的执行机资源快照；单个执行机调度日志按 Runner 过滤同一事件流，
保证每个经过该 Runner 的调度都可定位；单个用例日志即对应 attempt 的 stdout/stderr/agent
输出流，入口保持原有“查看日志”。调度事件打开期间按 3 秒增量轮询刷新。

产物下载会校验项目权限、对象归属、大小和摘要，并使用安全媒体类型与下载头；仅白名单文本、
图片和报告可受控预览。洞察从已确认 attempt 重建，显示样本数、成功/失败/跳过、P50/P95、趋势、
失败签名和 flaky 置信。批次样本范围不同时不会直接比较总体百分比。导出在后台生成有界 CSV/JSON，
可取消并在完成后下载。

## 管理中心与执行机

主导航“管理中心”提供用户管理、角色权限、项目成员、LDAP、会话管理和平台配置的明确入口。
LDAP 支持 LDAPS 或 StartTLS 连接测试、加密保存 bind 凭据、用户同步和组角色映射。

执行机页面的“探测并核验主机”支持 OpenSSH Password 与 Keyboard-Interactive/PAM 密码认证。
探测不要求先配置 Agent 控制面地址；安装前仍须配置执行机可访问的 HTTP 或 HTTPS 地址，可信内网
可直接使用 IP。失败信息会区分 DNS、端口拒绝、超时、认证、握手、systemd、cgroup v2 与 sudo
前置条件。首次安装或更新成功后，平台以 AES-256-GCM 保存主机、端口、用户名、密码和可选私有
CA；浏览器只读取不含密码的摘要。后续可选择多台执行机批量更新，并复用各自已保存的连接档案。

执行机注销（deregister）后，其凭据立即失效且不能再认证；此时可以在执行机列表中删除该记录，
删除后从列表移除且永不恢复，历史执行记录中的执行机引用仍保留。未注销的执行机不允许删除。
JDK 与依赖 JAR 压缩包通过界面上传时先在平台数据目录暂存并校验格式与摘要，再写入对象存储；
数据目录磁盘不足时上传会明确报错，而不会写入不完整文件。

当平台内置 Agent 版本高于执行机当前版本时，执行机列表会显示“可更新至 x.y.z”标记。点击“更新”
按钮，输入该主机的 SSH 凭据并核对指纹后，平台会原地替换 Agent 并重启服务：执行机身份、凭据、
名称、标签、并发配置与历史执行记录全部保留，无需注销重装。更新前自动备份当前版本，失败时可
在自动安装面板执行“回滚上次安装”。已注销的执行机不能原地更新。
