# 新版本初始化

顶栏创建项目版本后自动打开初始化弹窗。创建版本已经保存成功，初始化不是创建的必填条件。
每一步都提供“跳过此步”，步骤标题可以直接跳转；“稍后配置”直接进入目标版本。
之后可在顶栏版本下拉菜单点击“初始化当前版本”，补充尚未完成的内容。

## 继承范围

继承来源只允许选择同项目的其他版本，默认不选择来源。每步都会提示可以继承的内容；
项目没有其他版本时显示“暂无可继承版本”。可以逐步选择不同来源。

| 步骤     | 可继承内容                                    | 已有目标内容与前置条件                                                     |
| -------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| 测试阶段 | 启用阶段的名称、说明                          | 同名启用阶段复用；也可手动创建阶段                                         |
| 运行依赖 | 版本的 JDK、完整依赖 JAR 压缩包引用           | 目标已有任一种资产时保留全部配置，需要更换时使用执行资源配置页             |
| 普通用例 | TestNG 用例当前版本、导入 JAR 来源            | 选择目标阶段；同阶段已有完整类名跳过                                       |
| DDT 用例 | CaseID、SR、字段、用户旅程                    | 选择目标阶段；已有 CaseID 跳过；不复制模板和执行历史                       |
| SR 关联  | 候选测试类范围、需求分类、SR 分类或直接类关联 | 目标阶段需已有对应普通用例和 DDT SR；按完整类名重新匹配，不复用来源用例 ID |
| 用例任务 | 任务配置，可选任务成员                        | 普通成员按阶段和完整类名、DDT 成员按阶段和 CaseID 匹配；缺失用例跳过并提示 |

来源阶段默认按名称匹配目标启用阶段，可逐项改选，也可以取消不需要继承的阶段。
任务列表按需读取，支持选中/取消当前已加载任务以及加载更多。只复制任务配置时无需准备目标用例。
继承的任务默认停用，Adapter Suite/Test 名称重新使用目标项目、版本和阶段的默认值；
不复制执行记录、分析结论、定时计划或通知绑定。启用前需检查执行节点、Adapter 地址及恢复策略。

继承后两边独立维护；JAR/JDK 文件复用平台已有对象引用，无需重新上传。
依赖 JAR 仍采用全量覆盖规则，初始化不会将旧依赖补充到新依赖中。
已有目标分类和 SR 关联保持不变，不同执行类或缺失关联会给出提示，需人工确认。

## 暂停、恢复和权限

- 可在当前批次处理完后暂停。连续处理约 30 秒后自动暂停，点击“继续继承”处理下一批。
- 错误在弹窗中显示；完成部分已经保存，选择继续、跳过或关闭均不会撤销。
- 弹窗关闭或浏览器刷新后，不保存当时的勾选和进度游标；重新选择内容即可补充，已存在的用例、
  阶段及同一来源任务的目标副本会复用。不会因重试创建多份任务。
- 任务来源在处理期间发生修改时停止并提示重新读取。已经启用或归档的目标任务不能继续初始化成员。
- 需要项目管理权限；继承用例还需要用例读取和管理权限，TestNG 继承还需要来源管理权限；
  任务继承需要任务读取和管理权限。无权操作时可跳过该步骤。

## 部署行为

Lite 与 Full 使用同一应用服务，分别持久化到 SQLite 和 PostgreSQL。初始化请求通过维护工作线程
处理有界批次：SR 配置每批最多 20 项，任务成员每批最多 50 个普通用例和 50 个 DDT 用例；
用例资产沿用已有有界继承接口。平台高优先级工作繁忙时暂停接收继承请求，前端允许稍后继续。
每次操作有权限校验和审计记录，不在 Web 主线程执行批量继承，不需要新增外部服务或数据库迁移。
Runner 和既有执行协议保持一致，初始化不触发任何用例执行。
