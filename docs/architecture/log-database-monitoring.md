# 日志库心跳与容量监控

Full 的所有已登记日志服务器及旧版单库均参与后台探活，包括当前写入库和仅保留历史读取的库。每日物理库由同一登记服务器负责，不逐日展开全库探测。Lite 不启动此监控，也不连接 PostgreSQL 或 Node Exporter。

```mermaid
flowchart LR
    Registry[分页读取日志服务器标识] --> Probe[每分钟只读心跳]
    Registry --> Exporter[各服务器 Node Exporter]
    Probe --> Snapshot[有界监控快照]
    Exporter --> Snapshot
    Snapshot --> Cards[所有日志库卡片自动展示]
    Cards --> Details[查看容量及手动刷新]
```

Web 启动后进行首次采集，此后每轮完成后间隔 60 秒继续。即使没有人打开设置页也会检查；平台资源繁忙时退让，关闭时停止开始新采集，等待有时限的在途检查结束。目标枚举只查询标识，使用游标分页，不汇总执行记录或日志正文。每轮最多同时采集两台服务器，一个进程最多接纳四个不同服务器的监控请求；同一目标的在途请求合并。

PostgreSQL 心跳使用独立连接池，最多四个池，每池一个连接，以容纳后台两项采集与页面两项读取；不占用或淘汰执行日志正文的连接池。连接期限 1 秒、SQL 语句期限 1 秒、客户端查询期限 1.5 秒。每日服务器只读检查账号建库权限及维护连接是否误指向业务库；旧版单库检查平台与数据库身份。采集不建表、不建库、不迁移、不写日志，不触发写入切换。手动“检查连接”仍执行原来的完整校验。

连接与磁盘分别采集。磁盘沿用各目标已保存的 Node Exporter 地址和数据卷挂载点，不从数据库体积、Web 宿主机或其他日志库推算；未配置时明确显示待配置。连接失败不会隐藏仍可用的独立磁盘采样；磁盘失败不把数据库标记为断连。旧容量保留时明确标记过期，并显示采样时间。

监控快照是可重建的观察数据，不是日志位置或数据库配置的权威来源。缓存有容量上限，90 秒后按需重新采集；连接或磁盘配置修改会使旧快照失效，在途旧采样不能覆盖新配置的结果。数据库临时繁忙会退让或返回可重试错误，不记为离线；失败输出只包含安全的状态和错误码，不回显连接串、账号密钥或底层错误正文。

页面对所有卡片默认加载，最多并行两个 HTTP 请求，每 30 秒读取新快照，隐藏标签页暂停并取消排队请求。单个数据库故障不阻塞其他卡片；显式刷新优先于排队采集。`GET /api/v1/settings/log-databases/{id}/status` 要求 `settings.read`，响应禁止缓存；`refresh=1` 请求即时重采集。原容量及连接检查接口保留兼容。

面向使用者的步骤见 `/docs/log-archives#heartbeat`。监控不增加数据库迁移、部署组件或 Runner Protocol 字段。
