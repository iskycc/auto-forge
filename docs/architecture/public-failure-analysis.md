# 公开用例分析与表格工作台

分析任务详情的“公开分析”入口可启用、复制和撤销 `/CaseAnalysis?BatchId=…`。链接使用已有执行批次 ID，不生成随机分享串；执行详情或日志的原有公开授权不会自动公开人工分析。

公开链接弹窗将标题、正文与操作栏独立排布：标题／操作栏保留统一内边距，长提示与错误只在正文内滚动，长地址在有界区域换行并完整复制。继续使用共享 Ant Design 弹窗，不改动全局弹窗或链接的授权逻辑。

## 访问范围

- 发布者需要本项目的 `analysis.manage`、`run.read` 和 `log.read` 权限，并使用个人账号登录。弹窗在启用前明确说明公开的内容和协作权限。
- 未登录访问者仅可读取本次分析范围内的失败用例、人工结论、失败日志及证明图片，不能认领、上传、提交或取消认领。
- 个人账号登录后，无需成为项目成员，即可通过该链接认领用例、分析本人认领的未完成记录、补充本人的证明和填写原因后取消认领。不能分配给其他人、修改他人记录、修改执行结果、控制执行或访问其他批次。服务账号 API Token 不能取得此个人协作授权。
- 普通后台接口继续执行原项目 RBAC；公开协作不改变账号角色，也不授予项目范围的其他权限。强制修改初始密码限制继续生效。
- 已归档任务只读。关闭分析任务时授权随其删除；撤销链接或停用分享人后，后续公开读取和提交被拒绝，已经提交的分析结论、执行结果与证明保留。已被访问者读取的内容无法通过撤销收回。

公开页面沿用主平台的当前页登录弹窗和会话恢复：登录后留在原链接，不跳转后台首页。页面不展示主导航、后台分配或其他项目入口。公开日志仅从当前批次、当前人工分析口径的最终失败尝试读取；不能借用 `executionRunId` 获取其他批次、通过用例或早期轮次的日志，也不为整个执行批次隐式生成公开执行授权。

## 表格交互

后台详情默认进入“表格分析”，原“详细工作台”保留分配、历史结论、日志对比等既有流程；明确指定 `view=claim`、`view=workbench` 或 `layout=classic` 的旧入口继续进入详细工作台。公开页只使用同一个表格组件，不开放跨批次历史读取。

工作表采用已有 Ant Design Table、表单、弹窗和主题，不引入第二套 UI 框架或新生产依赖。固定用例与操作列，单元格以相同行高截断长文本；点击用例可查看完整摘要和结论。搜索、本人认领范围及排序保留在 URL。列表每页 50 条，后端最多 100 条，按游标翻页；首屏复用服务端有界分页结果，不在挂载时重复请求。其他人的新认领通过手动刷新查看，竞争以数据库提交结果为准。

认领后点击分析类别、问题说明、问题单、修改证明文字或备注单元格即可编辑。选中单元格右下角有填充柄，可向下拖拽复制同一列；也可聚焦填充柄，用方向键选择下方范围，Enter 确认、Esc 取消。工具栏提供填充至本页末行和撤销最近一次填充。填充范围只包含本页本人认领且尚未完成的记录，已完成、未认领和他人记录自动跳过并提示数量。

填充只更新浏览器内存草稿，不写执行结果、认领人、用例 ID、截图或重跑证明。修改证明的文字可以复制，但执行通过截图和重跑通过关联仍须逐例提供和校验。切换范围、翻页、刷新、离开或切换工作台前提示未提交修改；不把日志和草稿写入浏览器持久缓存。

“提交草稿”先确认本页的提交范围；存在“用例问题已修改”时要求确认确实由用例引起。复用原人工分析完成服务，保留所有类别要求、逐例成功重跑／截图校验、对象校验及归属检查。每次顺序提交一个记录，显示完成进度；成功行转为只读，失败行保留草稿与具体原因。相同已完成结论的响应丢失可重试确认，不重复完成；记录修订变化时拒绝陈旧提交。仍不允许借表格修改已经完成的结论。

## 持久化与接口

SQLite 迁移 `0095_public_failure_analysis.sql`、PostgreSQL 迁移 `0094_public_failure_analysis.sql` 新增 `public_failure_analysis_links`，保存批次、分享人、发布时间和撤销时间。既有分析不自动公开，升级不改已有认领和结论。授权引用分析任务，关闭任务时级联清理；项目版本复制不复制此公开授权。

Lite 使用主 SQLite 保存授权和分析，证明仍存本地对象目录；Full 使用 PostgreSQL 保存相同事实，证明复用 MinIO。Redis 和 NATS 不承担授权或分析结果的唯一来源。本功能不创建新的后台调度工作、不轮询完整批次、不访问完整日志生成列表；日志仅打开后按原分页与隔离 I/O 链路读取，无 Runner 协议或执行调度变更。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/failure-analysis/batches/:batchId/publication` | 读取当前发布状态，需要项目分析权限 |
| `POST /api/v1/failure-analysis/batches/:batchId/publication` | 显式启用公开分析，校验发布权限并记录审计 |
| `DELETE /api/v1/failure-analysis/batches/:batchId/publication` | 撤销链接，保留分析及证明 |
| `GET /api/v1/failure-analysis/batches/:batchId/sheet` | 后台有界分页，保持项目 RBAC |
| `GET /api/v1/public/failure-analysis/:batchId` | 公开只读分页；`view=mine` 还需个人登录 |
| `POST …/:batchId/{claim,complete,proof,rerun-proofs,release}` | 个人会话及明确发布范围内的协作，验证归属与状态 |
| `GET …/:batchId/{logs,evidence}` | 仅读取当前授权批次的失败日志和分析图片 |

后台动作使用 `…/batches/:batchId/sheet/:action` 路径。请求体不能覆盖项目、版本、分享人或操作人；公开接口拒绝跨任务认领记录、跨任务日志和未知动作。写入继续要求同源，并记录真实操作账号、批次、请求编号和项目／公开入口来源。

## 升级与恢复

按正常流程备份并运行双数据库迁移。新表初始为空，历史数据和旧公开执行／日志链接不变。迁移 DDL 失败时事务回滚，可修复原因后重跑；旧程序忽略此独立授权表，降级前应撤销新增公开分析链接并保留数据库备份，不需要删除执行历史或证明对象。
