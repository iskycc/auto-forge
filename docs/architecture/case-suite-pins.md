# 任务个人置顶

任务卡片底部的“置顶”勾选项只维护当前用户的展示偏好。置顶任务在当前项目版本的列表中优先
显示，多项置顶按中文任务名称自然排序，名称中的数字按数值比较，例如“任务 2”在“任务 10”
之前；名称相同时保留原列表顺序。普通任务继续按更新时间倒序，取消置顶后回到该顺序。

偏好跟随个人账号，刷新、退出后重新登录或换浏览器不会丢失，不影响其他用户。置顶不修改
任务版本、修订号、更新时间、执行策略或历史快照，也不改变调度优先级。任务复制不会复制
个人置顶。已归档或停用任务仍可置顶，其原状态与操作限制保持有效。

## 权限与请求

`PUT /api/v1/case-suites/{suiteId}/pin` 接收严格的 `{ "pinned": true }` JSON，取消时传 `false`，
限制请求体大小并执行同源校验。用户 ID 始终来自登录身份，不能通过请求指定其他账号。用户只需
在任务所属项目具有 `case_suite.read`；超出可见项目范围或不存在的任务返回同一 404 错误。
服务账号不能维护个人置顶。

重复设置同一状态是幂等操作。界面立即显示新顺序，在请求和刷新期间禁用勾选项；保存失败时
恢复原勾选与顺序，显示错误并允许重试。

## 双模式与升级

Lite 的 SQLite 和 Full 的 PostgreSQL 使用相同的 `case_suite_pins` 表：`user_id`、`suite_id`
构成联合主键，`created_at` 记录首次置顶时间。用户或任务被物理删除时通过外键级联删除偏好。
列表查询先按当前用户的置顶优先级选取有界任务，再计算展示顺序；不会先截取最近 200 个任务
才寻找置顶，也不会加载用例成员或全部执行历史。列表保留现有最多 200 项的窗口，置顶数量
超过窗口时仍按窗口返回，所有偏好继续持久化。

SQLite 迁移为 `0075_case_suite_pins.sql`，PostgreSQL 为 `0073_case_suite_pins.sql`。迁移只
新建偏好表和索引，不回填或改写历史任务；全新建库和升级后均默认没有置顶。该偏好不涉及
队列、对象存储、缓存或 Runner Protocol；Lite 不需要外部服务，Full 多节点读取同一数据库。

升级前按[备份恢复手册](../operations/backup-recovery.md)保存完整备份。失败的迁移在数据库
事务中回滚；已经完成升级后，如需退回旧版本，应按手册恢复升级前完整备份和旧镜像，不修改
历史迁移文件或直接删除迁移记录。
