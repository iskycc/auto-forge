# AI 初步分析：提示词与输出契约

状态：v1.21.25 调整证据与同栈归类，发布状态以 GitHub Release 为准。更新日期：2026-11-06。使用入口与部署见[操作说明](../operations/ai-analysis.md)。旧版长报告模板已由本规范替代；已有历史结论保留。

## 两种分析

- **批次初析 `stack_groups_v2`**：先采集最终失败／超时用例的完整堆栈，按确定性签名分组。相同完整堆栈视作同一疑似问题；异常消息、帧、行号和 cause 链不同则分组不同，不按截断摘要或相似文本强行合并。同栈组不足 10 例时逐例读取 stdout，按清理及长文本尾部规则准备证据，可按上下文分片；全部成员完成后生成一份统一初步建议。达到 10 例时共用堆栈证据，每次最多附带 50 个成员，较大组／堆栈继续分页或分片，最终一个组结论回填全部成员。
- **单例细析 `single_full_v2`**：绑定具体失败 attempt，独立于批次分组结论读取 stdout 及必要业务输入，按相同颜色清理和 50,000／25,000 字符规则准备，超过上下文时逐片提供并累积修正。真正的读取不全、日志离线不可用、达到每例空间／分片上限时明确失败；按明确规则取尾不算读取故障。

没有可确认完整堆栈的用例独立分组，不与其他缺失堆栈用例合并。达到 10 例的分组依据共同堆栈提出初步建议，需要逐例细查时使用用例行的按钮。模型输入不包含通用 TestNG 错误码、结果摘要、节点、时间、stderr 或 Agent 诊断。

输入先清理 ANSI 颜色、OSC 与非显示控制字符，跨日志块保留解析状态；AI 采集不再额外替换密码、Token 等字段，保留源数据。业务字符串按 Unicode 字符计数，最多 50,000 字符时保留全文，超过后以末尾 25,000 字符为基准向前补齐首行；stdout 按完整流判断，JSON 按字段值处理，不截坏协议结构。`inputTransformations` 明确告知模型哪些输入取了尾部，禁止声称读取了省略部分。完整堆栈签名在裁剪前计算，不能因模型看到相同尾部而合并不同完整堆栈。系统权限规则、工具 schema 与业务输入保持分离。

## 固定输出

每次模型只能调用 `submit_ai_conclusion` 提交以下严格对象：

```json
{
  "recommendation": "rerun_likely",
  "reason": "依赖服务短暂断开，可能为环境波动。",
  "evidence": "堆栈为 ConnectionReset，失败点位于连接读取阶段。",
  "evidenceReferences": ["stack-1"]
}
```

`recommendation` 仅允许三种值：

| 值 | 展示 |
| --- | --- |
| `rerun_likely` | 可能重跑通过 |
| `case_change_likely` | 可能用例问题需要修改 |
| `business_issue_likely` | 可能业务问题需要提单 |

`reason` 最多 160 字符，`evidence` 最多 200 字符，分别一句话。界面和导出统一渲染为“初步分类（待人工确认）／原因／依据”三行，不附加步骤清单、多个候选根因、长篇背景或模型自评置信度。长文本、额外字段、未知分类和越界证据引用在服务端拒绝，不只依赖提示词约束。

证据不足时仍只提出低把握的初步建议，并在简短原因中明确“证据不足，待人工核对”；不得把推测写成已确认、已重跑、已修复或已提单。退出码 143 不能单独证明 OOM。相同堆栈作为同一疑似问题，不宣称根因已被证实。

## 系统与参考提示词

实际系统提示和 tool schema 在 [ai-analysis-prompts.ts](../../packages/application/src/ai-analysis-prompts.ts)，Zod 输出边界在 [ai-analysis.ts](../../packages/contracts/src/ai-analysis.ts)。

“平台设置 → 模型配置 → 参考提示词”使用 Ant Design 弹窗增删改多条标题与内容，应用后需保存模型配置。最多 20 条，单条标题 60 字符、正文 1500 字符，合计最多 20,000 UTF-8 字节；配置校验还会预留输出、系统和证据上下文。所有实际分析请求，包括重试、分片及分组续分析，附带当前配置的全部参考提示词；连接检查不发送业务提示和真实日志。保存后下一次模型请求读取新修订，已发出的请求不会追溯变更。

参考提示只补充业务规则、常见错误和经验，不改变工具权限、精简格式或证据事实。不得填写密码或 API Key。旧配置缺少此字段时默认为空数组，继续可用。

## 工具与安全边界

Worker 先执行绑定证据的读取，把结果作为 `read_evidence` 工具响应下发；模型仅获一个写工具 `submit_ai_conclusion`。项目、批次、attempt、成员范围与真实操作人均由平台确定，模型不能声明或切换。每个请求前及结论落库前重新校验发起人的当前权限。

单例每片必须引用当前片，可继续引用前片已读取证据；分组只允许引用本片共同堆栈或本次实际提供的成员。模型不可运行命令、访问任意 URL、执行用例、认领人工分析、改变测试结果或提交问题单。日志、用例和参考提示中的指令不能扩展权限。

组结论仅在所有必需堆栈片和成员页处理完成后分批回填，每段最多 100 个成员。取消或租约失效拒绝迟到写入，其他组可独立完成；模型限流、临时故障或平台资源紧张继续持久化退避。旧作业保留 `legacy` 策略恢复，旧结论不会被自动重写；用户重新分析则采用本轮新策略。

通用 `TestNG exit code:1`、`TestNG exit status` 等独立退出码行在采集时排除，不能用作根因或关键日志。stdout 只有这些行时直接报告没有实际业务正文／异常堆栈，不调用模型生成猜测。不足 10 例和单例使用 stdout 全文（仅超 50,000 时取尾部并补齐首行），不以独立堆栈替代日志。原始日志已有的处理结果不还原，平台管理密钥不进入证据。

截取点若在行中，向前回溯至该行开头；支持 LF、CRLF 和单独 CR，不从 CRLF 中间开始，也不拆坏 Unicode 字符。保留内容可能超过 25,000 字符；没有前置换行时保留整行。补齐后继续按模型上下文分片，现有采集空间、分片和模型额度上限仍生效，超预算明确报错，不静默丢掉半行。
