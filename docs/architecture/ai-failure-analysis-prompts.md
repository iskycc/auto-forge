# AI 初步分析：提示词与输出契约

使用入口与部署见[操作说明](../operations/ai-analysis.md)。已有历史结论继续可读。

## 两种分析

- **批次初析 `stack_refinement_v3`**。先用 `classify_ai_stacks` 为达到 5 例的每条去重堆栈命名。初分只写可见现象，数量只表示范围。再用 `submit_ai_issue` 根据当前用例全文和本组子类结论选择根因相同的类别，或新增子类。比较组件、操作、触发条件和具体因果证据。相同异常类和相同建议不足以归并。二次分类后实际不足 5 例的用例使用独立分析，保留类别统一发布结论。
- **单例细查 `single_full_v2`**。读取所选尝试的 stdout，使用 `submit_ai_conclusion` 累积证据并在收尾时提交初析结论。

已存在的 `legacy` 和 `stack_groups_v2` 作业按原策略恢复。全文日志清理颜色后，50,000 字符以内保留全文，超长时保留末尾 25,000 字符并向前补齐首行。上下文较小时按片累计，日志不可用或空间不足时明确报告。初分使用清理后的完整失败堆栈做签名和送模。单条堆栈超过模型请求预算时，或 stdout 回退标题超过执行摘要的长度上限时，发送标有 `shortened` 的开头，分组签名仍使用完整值。

## 固定输出

阅读阶段提取前序证据、反证及缺失项供续跑，收尾阶段综合已读证据并写出可独立阅读的原因和依据。单例及独立分析只有收尾结论写入可导出的记录。发布边界清理可识别的过程标签，对只含阅读过程而无业务依据的返回进行有限重试。组内沿用旧结论前也校验可读性，缺少业务事实的候选需要用新证据更新。

日志片和独立分析用 `submit_ai_conclusion` 提交以下对象。逐例复核将同一对象放入 `submit_ai_issue` 的 `conclusion` 字段，并附本页的候选类别 ID 或空值及问题简述。同因用例用 `useExistingConclusion: true` 沿用已有类别结论，平台保留已保存的内容。提供可适用于整个类别的新证据时，模型提交更新后的统一结论并将该值设为 false。

分组复核工具还提交 `affectedSubjects`，仅记录当前用例中与失败相关的对象或操作名称。中间片的同名工具在 `conclusion` 之外记录直接从本片提取的候选名称，传给最后一片供核对。Worker 校验最终名称出现在当前日志或此前已核对的候选中，按组顺序合并并去重。类别简述、原因、依据写可适用于整组的共性。若多个对象的类别结论仍使用单例对象表述，Worker 要求重试并改写公共结论。汇总最多保留 8 个名称，每个最多 80 字符，超出数量标为“等”；没有可核对的对象时省略该行。该机制适用于日志中可辨别的各类对象和操作。

类别达到 5 例后，平台通过 `summarize_ai_issue` 汇总每个成员的复核结论。按成员 ID 逐页读取，窗口最多 24 例，等同观察合并并附数量。跨页携带已归纳的共性和持久化游标。最后一页完成后才允许排名与发布。在限额内重试仍无法汇总的类别，其未完成成员进入独立分析。升级前已保存的报告及无逐例观察的旧类别可以继续读取。

```json
{
  "recommendation": "rerun_likely",
  "reason": "依赖服务短暂断开，可能为环境波动。",
  "evidence": "堆栈为 ConnectionReset，失败点位于连接读取阶段。",
  "evidenceReferences": ["stack-1"]
}
```

`recommendation` 仅允许三种值：

| 值                      | 展示                 |
| ----------------------- | -------------------- |
| `rerun_likely`          | 可能重跑通过         |
| `case_change_likely`    | 可能用例问题需要修改 |
| `business_issue_likely` | 可能业务问题需要提单 |

`reason` 最多 160 字符，`evidence` 最多 200 字符，分别一句话。界面和导出分别展示初步分类与原因，依据附于原因下方。界面同时提示待人工确认。兼容服务可能忽略工具的字数限制，因此服务端先合并空白，再按字符边界截短超长原因与依据并加省略号，不拆断 Unicode 代理对；该兼容处理同时用于堆栈分组和单例全文，不重新请求模型。额外字段、错误类型、空白内容、未知分类和越界证据引用仍在服务端严格拒绝，并显示可读的字段错误，不把原始校验 JSON 直接展示给用户。

证据不足时仍只提出低把握的初步建议，并在简短原因中明确“证据不足，待人工核对”；不得把推测写成已确认、已重跑、已修复或已提单。退出码 143 不能单独证明 OOM。相同堆栈作为同一疑似问题，不宣称根因已被证实。

## 系统与参考提示词

实际系统提示和 tool schema 在 [ai-analysis-prompts.ts](../../packages/application/src/ai-analysis-prompts.ts)，Zod 输出边界在 [ai-analysis.ts](../../packages/contracts/src/ai-analysis.ts)。

“平台设置 → 模型配置 → 参考提示词”使用 Ant Design 弹窗增删改多条标题与内容，应用后需保存模型配置。最多 20 条，单条标题 60 字符、正文 1500 字符，合计最多 20,000 UTF-8 字节；配置校验还会预留输出、系统和证据上下文。所有实际分析请求，包括重试、分片及分组续分析，附带当前配置的全部参考提示词；连接检查不发送业务提示和真实日志。保存后下一次模型请求读取新修订，已发出的请求不会追溯变更。

参考提示只补充业务规则、常见错误和经验，不改变工具权限、精简格式或证据事实。不得填写密码或 API Key。旧配置缺少此字段时默认为空数组，继续可用。

## 工具与安全边界

Worker 先执行绑定证据的读取，把结果作为 `read_evidence` 工具响应下发；模型只获当前阶段对应的一个写工具。项目、批次、attempt、成员范围与真实操作人均由平台确定，模型不能声明或切换。每个请求前及结论落库前重新校验发起人的当前权限。

单例每片必须引用当前片，可继续引用前片已读取证据；二次分类的结论必须引用当前用例本片，可以继续引用本用例已处理的片。其他用例的类别摘要只作比较参考。模型不可运行命令、访问任意 URL、执行用例、认领人工分析、改变测试结果或提交问题单。日志、用例和参考提示中的指令不能扩展权限。

组结论在所有成员复核和类别排名完成后分批回填，每段最多 100 个成员。取消或租约失效拒绝迟到写入，其他组可独立完成；模型限流、临时故障或平台资源紧张继续持久化退避。旧作业保留 `legacy` 策略恢复，旧结论不会被自动重写；用户重新分析则采用本轮新策略。

通用 `TestNG exit code:1`、`TestNG exit status` 等独立退出码行在采集时排除，不能用作根因或关键日志。stdout 只有这些行时直接报告没有实际业务正文／异常堆栈，不调用模型生成猜测。组内复核及独立分析使用 stdout 全文（仅超 50,000 时取尾部并补齐首行），不以独立堆栈替代日志。原始日志已有的处理结果不还原，平台管理密钥不进入证据。

截取点若在行中，向前回溯至该行开头；支持 LF、CRLF 和单独 CR，不从 CRLF 中间开始，也不拆坏 Unicode 字符。保留内容可能超过 25,000 字符；没有前置换行时保留整行。补齐后继续按模型上下文分片，现有采集空间、分片和模型额度上限仍生效，超预算明确报错，不静默丢掉半行。
