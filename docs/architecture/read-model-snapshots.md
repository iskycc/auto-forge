# 大数据页面的缓存与后台快照

后台刷新与执行控制的资源隔离、退让及故障反馈见[运行资源优先级](./runtime-resource-priority.md)。

工作概览与匿名统计、TestNG 用例目录、任务成员目录、DDT 概览、质量洞察及批次对比、执行历史计数、执行详情轮次统计与筛选分页、任务的近期执行统计、用例分析任务列表和分析统计使用共享的后台读模型。执行、领取、修改、删除及权限判断仍读取业务事实；统计快照不参与版本冲突、租约或执行状态判定。

## 读取与更新

页面请求只登记查询并读取已经持久化的结果，不在请求内启动全量统计。首次访问尚未生成的查询会显示准备状态，完成后自动更新。已有结果过期、更新失败或网络断开时保留上次内容，并显示更新时间或失败提示。页面的“刷新数据”提交后台刷新请求，通过右上角通知反馈，不阻塞用户继续查看。

最近五分钟仍有人访问的普通统计查询，每次成功生成后至少间隔 60 秒再次计算。进行中批次的计数、轮次统计与用例页键快照间隔为 5 秒；终态批次按业务版本区分缓存，最长复用 24 小时。匿名首页按配置中的公开刷新间隔生成统计。可见页面每 30 秒检查元数据；首次准备或等待更新时每秒检查，断线或失败时退回 30 秒。后台忙碌或大范围查询耗时较长时，统计延迟可以超过 60 秒，界面会展示实际生成时间。隐藏标签页和未显示的页面面板不轮询；打开操作弹框时推迟自动整页更新，后台读取不清空当前选择。

有项目范围的操作审计会使该项目的读模型失效；JAR 和 DDT 后台导入在完成写入后再次失效，避免只在入队时刷新。执行机上报等高频写入通过周期刷新归并，避免每条日志或完成消息触发全表重算。JSON 分页读者在首次生成或明确失效时最多等待 10 秒，随后返回 `READ_MODEL_PENDING`（503），可以重试；已有未失效的结果直接返回。

查询类型由契约白名单定义。键包含 schema 命名空间、查询类型、项目、版本、阶段及筛选参数，规范化属性顺序后计算 SHA-256。统计接口和分块接口每次都重新认证及验证项目权限，不把知道快照 ID 当成读取凭证。

## 浏览器缓存

Next.js 客户端路由缓存复用最近 60 秒访问过的页面。用例目录、对比明细及 DDT 列表额外使用会话内存 LRU，序列化载荷总预算 24 MiB、单项最长保留五分钟。刷新文档会丢弃浏览器内存，但仍可读取数据库中已有快照；没有新增 localStorage、IndexedDB 或业务数据的公开 HTTP 缓存。

账号、项目层级或权限上下文改变时清空数据缓存；退出登录同样清空。请求携带缓存代次，旧请求即使在切换账号或写操作之后才返回，也不能回填新缓存。浏览器缓存只提高重复访问速度，所有修改仍由服务端实时授权和校验。

TestNG 和任务成员目录使用后台生成的目录索引。首屏只读取顶层的直接子目录及数量；展开目录时才读取它的直接子目录和用例，不预取折叠目录内的正文，也不下载整棵树。普通用例仍按原路径显示，任务中的普通用例按包路径、DDT 用例按 SR 分组；页面没有新增页码、上一页或下一页。单个展开目录的内容按需追加，沿用“加载更多”交互。后台存储和单次传输使用最多 100 项的块，这是读取边界，不是页面分页。

搜索覆盖整个项目层级或任务，结果、执行状态及“未加入任务”筛选由后台生成快照，筛选条件在输入事件中立即写入 URL，仅后台搜索请求延迟 300ms 合并输入，避免延迟的 URL 写入打断详情跳转。等待新筛选时保留已有目录显示并禁用批量选择，页面离开后取消待发请求。文件夹勾选仍作用于其整个子树，“全选当前结果”仍选择全部匹配用例，包含未展开目录中的用例。表格导入在整个项目层级精确匹配路径，不受当前展开范围或搜索限制；只有显式批量选择才收集完整的必要标识，正常浏览不加载这些标识。选择过程中若 generation 变化，停止并保留原选择，不能拼接不同代次。

展开目录遇到 generation 冲突时刷新目录索引，重新读取所需分支，不重下整份目录。折叠和卸载取消在途分支请求；取消响应不能填回缓存。任务快照修订号落后于本次编辑时等待后台追上，避免已删除成员重新出现或覆盖最新配置。24 MiB LRU 只保存访问过的分支，重新展开可命中缓存，退出登录或切换用户清空缓存。

## Lite / Full 与恢复

Lite 在同一个 SQLite 数据库保存 `read_model_snapshots` 和 `read_model_snapshot_parts`，不需要 Redis、NATS 或其他服务。Web 启动单独的读模型 worker thread，SQLite 同步聚合不会占用 HTTP 或 Runner 调度工作线程。

Full 使用共享 PostgreSQL 表；多个 Web 节点及独立 worker 可以同时工作，数据库条件领取和租约保证同一个查询只有一个有效发布者。时间沿用共享 PostgreSQL 校准时钟。Redis 不保存统计事实，也不是快照可用性的前提。

刷新租约为 120 秒，分块写入时续租。发布同时校验租约、期限和请求版本；构建过程中发生失效、节点退出或租约被其他节点接管后，旧结果不能覆盖新结果。所有分块写完后才发布新代次。失败保留上一代，最多自动尝试五次，之后需手动刷新或业务修改重新触发。

每次成功发布分片快照后，按本次分片数量分批回收旧代次，单批最多删除 500 个旧分片，避免大型目录每分钟刷新而清理速度跟不上。后台同时定期分批回收超过 24 小时无人访问的快照、过期租约及未发布/被替换的分块，并按最近访问顺序将非租约中的查询逐步收敛到最多 2,048 项。这个限制约束缓存条目，不限制任务用例数量。worker 异常退出最多重启五次；持续故障在服务端记录错误，页面保留旧数据并提示未完成。

## 升级与运维

SQLite 新迁移为 `0064_read_model_snapshots.sql`，PostgreSQL 为 `0063_read_model_snapshots.sql`。迁移只新增缓存表及索引，业务记录不被转换。上线前按原有流程备份数据库并执行迁移；失败时事务回滚，修复原因后重试。应用回滚到上一版本时可保留这些未使用的表。

快照可以重建。需要清理时，应先停止相关后台进程，再清空分块表和快照表；保留业务表。恢复数据库备份或重启后会复用尚存快照，并重新领取过期的刷新租约。不需要新增环境变量或离线运行依赖。

执行历史读取当前页批次元数据并合并后台计数；选择器仅查询元数据。详情的执行状态直接读取数据库，计数和轮次图表显示统计生成时间，初次未生成时显示“—”或准备提示，不能把零误当成最终结果。浏览器轮次表使用 `cached=1` 的分页接口：后台仅保存分页键和总数，请求按最多 500 个键读取当前记录；原有 JSON 明细接口在不超过 500 个成员且序列化响应不超过 2 MiB 时保留返回结构；超出上限返回 HTTP 413、`DETAIL_RESPONSE_TOO_LARGE`，不会向客户端传输百 MB 详情。这是旧版大集合调用方需要适配的响应限制，不限制任务本身的成员数量。

三个详情入口都支持 `?view=summary`。大批次使用已有 `/run-batches/{id}/cases` 分页；任务使用 `/case-suites/{id}/members`；JAR 来源使用 `/case-sources/{id}/classes`。后两者返回最多 100 个条目、`total` 和可选 `nextCursor`，下一次请求原样携带 `cursor`。游标绑定 generation，过期返回 409，调用方须从第一页重新读取。JAR 类目录也由后台准备，不在每次分页请求中解析完整 inspection。调度日志只读取批次元数据校验存在性，随后读取有界日志页，不读取完整 run/attempt 集合。

项目成员按用户游标分页，用户页只读取当页用户的系统及项目绑定。JAR 来源列表不读取完整 inspection；来源预览由后台生成，超过 100 个类时引导使用用例管理。Java 源码仅在展开时读取，使用当前不可变用例版本引用的源文件。

SQLite 原有读取后写入的业务事务统一在入口取得保留写锁，避免后台快照提交后触发 `SQLITE_BUSY_SNAPSHOT`；仍采用 WAL 与 busy timeout。PostgreSQL 重试统计明确物化候选集合，避免新建十万级批次的查询计划把空集合重复计算十万次。新增分页与反向引用索引分别为 SQLite `0065` / PostgreSQL `0064` 和 SQLite `0066` / PostgreSQL `0065`；都是可事务回滚的加法迁移，应用回滚可保留这些索引。

## 节点本地存储清单

存储管理使用节点本地可丢弃索引 `.cache/storage-inventory-v1.sqlite`，每代清单原子发布，常规有效期五分钟，扫描失败保留上一代并在 30 秒后允许重试。扫描按 200 项写入并让出事件循环，页面读取最多 500 项，避免每一页重新遍历文件系统和 MinIO。过滤条件与代次进入浏览器缓存键，手动扫描和删除会失效缓存。目录可以先查看，删除控件在当前筛选结果的分页加载完整后开放；删除成功直接修补当前树与汇总，不重新下载清单，保留展开状态及滚动位置。旧请求不能把已删除项目重新放回树中。

Full 第一页返回所属平台节点 ID，后续分页通过已登记的内部节点地址转发到所属节点；两端均验证访问权限，禁止重定向、转发循环及无限响应。节点不可达时显示明确错误，不能以另一节点的文件列表替换当前页。索引不参与删除资格判断，也不代表跨节点统一磁盘清单。删除本地索引后可从文件系统、对象存储和业务数据库重建，Lite 不连接外部服务。

统计缓存不能用于判断当前是否允许执行、删除、分析领取或编辑。源码、存储清单和大目录的首次读取仍需要实际 I/O；缓存的作用是将聚合移出页面请求并加速重复访问，不能承诺任意数据规模或故障条件下零等待。

分析认领列表先用项目、版本、领取人及搜索条件筛选紧凑分页键，再读取当前页的正文、证据和附件元数据，避免为排序携带全部认领详情。SQLite 与 PostgreSQL 使用同一游标、完成优先级和排序规则；这项查询调整不新增迁移。

本次扩展了目录查询协议，部署时同步升级所有平台节点和独立工作器，避免不同版本的后台投影工作器混用。回滚到不识别新查询类型的旧版时，先停止后台刷新工作器并清空快照及分片缓存表，再启动旧版；业务表无需转换，缓存会从业务事实重建。
