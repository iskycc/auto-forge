# DDT 管理与 ddt-insight 融合说明

AutoForge `1.1.0` 将 `iskycc/ddt-insight` 在提交 `705f552` 中的差异化数据驱动测试能力并入主平台。融合遵循一个原则：DDT 用例是新的用例资产形态，但身份、权限、项目层级、审计、对象存储、异步任务和运维事实仍由 AutoForge 的共享核心负责。

## 数据作用域与身份

每条 DDT 用例都绑定 `projectId + projectVersionId + testStageId`。`CaseID` 只在这个完整作用域内唯一；列表、详情、历史、模板、回收站、导入任务、导出和 `/api/v1/ddt/**` 全部在服务端重复校验这个层级，不能通过切换前端上下文读取或修改其他版本的数据。

管理接口读取使用 `case.read`，编辑、批量操作、模板、导入和回收站操作使用 `case.manage`。浏览器会话沿用同源 CSRF 保护；服务账号通过现有 `af_api_` 令牌和相同的项目权限访问 `/api/v1/ddt/**`。所有写操作进入 AutoForge 审计日志，记录友好的动作名、项目、版本、阶段和有界计数，不保存表格内容或令牌。

单条用例原始字段另提供 `/api/v1/public/ddt/projects/{projectId}/versions/{projectVersionId}/stages/{testStageId}` 下的匿名只读查询。调用者无需登录或 API Key，只要能访问平台网络并提供完整范围和 CaseID，即可读取该用例字段；范围 ID 用于定位数据，不作为访问凭据。该入口不公开管理元数据、执行类、修改历史、回收站、目录列表或写操作。

管理列表的 `query` 默认按 CaseID 任意片段匹配，忽略首尾空白和大小写，`%`、`_`、反斜杠按普通字符处理。
搜索覆盖当前项目、版本、阶段中的全部活动用例，继续使用有界游标读取，与 SR、来源和字段筛选取交集。
需要前缀语义的调用者可显式指定 `queryMatch=prefix`；`caseIds` 清单和公开单用例 API 仍按完整 CaseID 读取。

## 工作台切换与布局

DDT 的概览、用例、高级检索、导入任务、变更审核、字段模板、回收站和开放 API 通过 `ddtView`
保存当前子页。点击先经过未保存修改确认，再更新 URL，由同一同步入口提交选中状态；不提前修改本地
Tab，避免读取到旧 URL 时撤回刚才的切换。浏览器前进、后退和刷新继续保留子页定位及原有编辑保护。

子页内容直接显示，不重复执行整块透明度淡入。用例双栏按需挂载时在首次绘制前完成列表宽度和可用高度
测量；后续窗口、工具栏变化仍使用有界的 ResizeObserver 和帧合并，隐藏面板不覆盖已保存布局。
此规则由 Lite/Full 共用前端实现，不改变 API、数据存储、队列或 Runner 协议。

## 回收站按 SR 整理与清空

回收站按 SR 文件夹展示，每页最多显示 30 个分组，展开时才读取该 SR 的 60 条摘要；文件夹和用例分别使用游标翻页，不将全部回收记录加载到浏览器。同一规范化 SR 的不同大小写共用分组，空 SR 显示“未填写 SR”。页面保留单条恢复和永久删除，显示完整回收数量，支持手动刷新。

“清空回收站”在确认后清理当前项目、版本、测试阶段的全部回收记录，覆盖未展开的 SR 和其他分页。首次请求由平台时钟确定截止时间，后续批次复用该时间，期间新移入的记录保留到下一次明确清空。每批最多删除 200 条，页面显示已清理数量；失败提示完成数量，可再次确认后清理剩余记录，不回滚已完成的批次。切换页面会取消后续请求。

`GET /api/v1/ddt/recycle/groups` 提供 `items`、`totalCases`、`totalGroups` 和 `nextCursor`；现有回收列表 `GET /api/v1/ddt/recycle` 增加可选 `srNum` 精确分组查询。`DELETE /api/v1/ddt/recycle` 接受空对象或上一页返回的 `deletedBefore`，返回 `deletedCount`、`hasMore` 与 `deletedBefore`。路径均要求三层范围参数，读取要求 `case.read`，清空要求 `case.manage` 和原有同源校验，每批写入审计。

Lite/Full 使用共享应用规则；分组和摘要读取经过可中断的独立只读进程，清空在维护线程中以短事务执行，不占 Web 或 Runner 续租车道。PostgreSQL 跳过正在恢复/清除的行，遇到暂时无法推进的页面返回可重试错误。活动用例、任务与执行记录不在清理范围。无需数据库迁移、新配置、生产依赖或 Runner 协议变更。

## 导入覆盖后的修改历史刷新

表格覆盖原本已在 SQLite/PostgreSQL 的同一导入事务中保存 `import_overwrite`、修改前后快照、字段差异、操作者和来源。缺陷发生在工作台：后台导入完成只刷新列表和任务状态，已选用例的正文及历史仍保留旧快照，返回“用例”页后会继续显示旧值或“暂无修改历史”。

工作台现在在观察到导入终态后标记内容代次，当前用例可安全替换时重新读取正文与修改历史；隐藏的用例页待返回时再同步。正在编辑的草稿保留，取消编辑后读取最新内容，保存仍使用原有修订冲突保护。没有变化的重复导入、“跳过已有用例”与失败回滚继续不创建覆盖历史。

## 用例工作台布局

DDT XLSX 导出在普通用例的 `data` Sheet 和每个用户旅程 Step 内分别规划列名，使用与导入一致的
首尾空白清理、大小写不敏感去重规则。不同用例中的同名字段合并到一列，标识列固定为 `CaseID`、
`srNum`。同一行的同名字段存在不同值时，相关原始字段在整个 Sheet 内分别映射到唯一列名；后缀
分配会避让所有已有字段，保留空值、布尔值和数字的差异。此映射仅作用于导出内容，不修改持久数据；
全范围、SR 和勾选导出共用此实现，Lite/Full 行为一致。

### 按值高级检索

独立 `ddtView=search` 子标签使用鉴权的 `GET /api/v1/ddt/value-search`，参数包含完整三层范围、非空 `keyword`、
可选 `cursor` 和 1–20 的 `limit`；可选 `indexOffset`（0–19）启用分页统计，表示之前已匹配数量除以 20 的余数。原有 CaseID/字段条件筛选不变。
多个关键词使用重复参数（如 `keyword=钱包&keyword=支付`），兼容原有单关键词地址；不按分隔符拆词。
关键词最多 12 个、去除首尾空格后合计不超过 512 字符，限制扫描开销及 URL 长度；边界去除忽略大小写的重复条件。
条件取 OR 并集，同一个窗口只读取一次，字段值只遍历一次，同一用例或字段命中多个条件均只计数一次。
页面支持显式添加、移除条件，空白输入忽略；输入或增删条件不触发请求，不预加载用例列表、统计、导入或回收站，
只在提交搜索后串行读取分段结果。共享应用/领域实现仅遍历原始 JSON 的叶子值，Key 作为定位路径输出，
不通过序列化整段 JSON 做模糊匹配；字符串、数字、布尔值、null 和嵌套 Step 在 Lite/Full 语义一致。

SQLite/PostgreSQL 通过现有三层范围 + CaseID 唯一索引推进游标，每窗口最多 256 个候选、目标正文预算 2 MiB；
首条超过预算时仍完整读取该条，避免大字段永远漏检。只读取当前正文，不读取执行关联、历史或已回收记录。
每个工作片最多 16 个窗口，在窗口间让出执行权；约 1 秒或前台资源压力触发分段返回。结果最多 20 条，
每条返回前 8 个匹配字段及有界摘要，并从本次已读取正文提取 CaseName，不新增逐用例查询。
名称沿用 `ddtCaseCell` 的普通字段/首个 Step 规则，最多预览 1,024 字符（含省略号），空名称不返回；
分页统计使用相同的字段值匹配规则，每个用例只计数一次。每个统计片返回命中数及每 20 个命中的起始游标，
最多 4,096 个候选和 205 个页游标，不传回全部结果正文。浏览器累计完整总数和页索引后，按游标读取目标页；
翻页无需重新统计或进行深 OFFSET 扫描，最后一页按实际剩余数量读取。不新增数据库写入、迁移或缓存事实。

新工作类型 `search-ddt-values` 复用资源感知的维护工作线程，单线程最多接纳 2 个请求，取消通过 RPC 传递，
不会在 Web 线程退回同步扫描。当前台工作繁忙或线程不可用时明确返回可重试错误。客户端每次只有一个在途请求，
单请求 15 秒超时、一次统计最多 60 个分段且约 30 秒后暂停，可点击“继续统计”从游标恢复，不重复累加已处理片。
尚未完成时只显示已匹配数量，不将其标成最终总数；完成后展示总数、总页数及有界页码按钮，零结果为 0 条 / 0 页。
页面读取也限制分段次数与耗时，失败保留原页并可重试；统计与分页继续使用同一维护工作线程及资源准入限制。
缓存沿用会话内存的容量、过期和身份范围限制，以范围、完整关键词列表及搜索批次隔离统计与已读取页面；关键词列表使用 JSON 编码避免分隔符碰撞，新搜索生成新批次避免复用旧页。
全部关键词以重复 `ddtSearch` 参数与页码写入 URL，浏览器前进后退、重返标签复用缓存；主动提交重新统计当前数据，切换标签或范围取消在途检索。
统计是一次有界扫描的会话快照，不持有跨请求数据库事务；期间若其他用户编辑或导入用例，重新搜索更新总数及页边界。

结果的“查看用例”复用现有三层范围鉴权详情 GET，在只读弹窗中按需读取当前正文，不读取执行历史或重新加载列表。
弹窗支持普通字段、用户旅程 Step、加载失败重试和 Esc 关闭；关闭取消在途读取，恢复入口焦点，保留检索结果与滚动位置。
正文在弹窗内滚动，长字段名和值自动换行；初始显示 50 个字段和每字段前 8,192 字符，可显式继续显示，控制初始 DOM 体积。

### 按 SR 需求分类筛选

DDT 管理的“用例”页在“高级筛选”中支持选择一个或多个 SR 需求分类（如 Wallet、Payments），多个分类取并集，
再与 CaseID、业务分组和动态字段条件取交集。分类来自已有的 `SR → category → CaseDefinition`
关联，按分类 ID 精确筛选；不会按名称片段或用例正文推测分类，也不会因多个分类共用同一执行类而混入其他分类。
筛选使用当前项目、版本、阶段的权威 SR 关联，分类改名不改变选中结果，修改 SR 分类、移动 SR 或后续导入会在刷新后体现。

分类选项按需搜索、分页，每页最多 50 条；选中项可通过 ID 有界恢复名称。筛选条件使用重复
`ddtCategory` 参数保存到 URL，支持刷新和浏览器前进后退。用例 GET/POST 列表接受可选 `categoryId`
重复参数或 `categoryIds` 数组，导出也保留分类范围；最多同时选择 100 个分类，分页规则保持不变。

“选择全部筛选结果”串行按每页 200 条读取用例标识，不限于左侧已加载的 60 条，不把全部结果渲染成 DOM；
读取中可取消，修改条件、切换页面或作用域会取消旧读取，失败不应用部分结果。选好后可使用现有
“加入用例任务”新建任务或补充已有任务，单次沿用任务 API 的 100,000 条成员上限。Lite/Full 共用契约与关联规则，
查询复用既有范围、SR 和分类索引，无需迁移或 Runner/队列变更。

分类控件位于原有高级筛选浮层中，收起时显示已选分类数量，不增加导航区常驻筛选行。
1024×768 最小桌面下仍为用例列表保留至少 140px 高度；筛选浮层沿用既有高度和滚动边界。

采用左右分栏。左侧集中 CaseID 搜索、srNum 分组、高级字段筛选和可勾选的用例导航；右侧常驻
当前用例的来源、分组、修订、更新时间、执行类、字段卡片及历史。项目、版本与阶段沿用顶栏，
DDT 页不再重复展示 TestNG 的目录范围说明。列表可收起、拖动分隔线或用左右方向键调宽，双击
分隔线或按 Home 恢复默认宽度；列表内用 ↑/↓ 或 J/K 切换已加载用例。

共同约束。分隔线的无障碍数值同步实际宽度与当前上限。工作区通过 ResizeObserver 与窗口 resize

高度至少保留 320px，极矮窗口允许页面滚动；窗口变化不重新请求用例正文或统计数据。
高级筛选浮层按触发按钮下方的剩余空间限制高度，字段与匹配方式选项在浮层内滚动，避免小窗口裁切。

首次进入读取 60 条摘要，只加载当前用例的正文和历史；点击“加载更多”继续读取下一游标窗口。
超过 120 条摘要后导航采用固定行高可见窗口，仅挂载当前视口和前后缓冲行，保留已加载摘要、勾选、键盘切换及上一条/下一条导航。
加载更多每次只有一个在途请求，15 秒客户端超时；切换筛选、子页或范围取消旧请求，失败保留原列表和游标供重试，旧响应不覆盖新范围。
SQLite/PostgreSQL 的列表查询先固定最多 201 条摘要候选，再关联当前页的 SR、分类与执行类，不读取 JSON 正文。
列表及导出分页读取共享既有独立只读进程，每进程最多接纳两个读取，Full 设置 4 秒 SQL 查询期限，主进程设置 5 秒进程终止期限；
繁忙或超时返回可重试错误，不回退到 Web 线程执行。读取进程与 Runner 控制、调度车道分离，慢筛选不会阻塞续租。

未选择的用例不预取正文。列表和详情独立滚动，快速切换会取消旧详情请求，旧响应不得覆盖新的
选择。筛选条件写入 `ddtQuery`、`ddtGroup`、`ddtField`、`ddtOperator`、`ddtValue` URL 参数，
刷新与浏览器前进后退可以恢复筛选；有筛选的链接通过 `ddtView=cases` 直接进入用例视图。
现有浏览器摘要缓存与后台统计快照保持复用；统计请求独立完成，不阻塞列表读取或用例保存反馈。

普通字段以卡片展示，支持单字段复制、编辑及文本/数字/布尔/空值类型；整份 JSON 编辑保留，
便于新增或删除字段。用户旅程仅展示所选 Step，身份字段修改复用共享领域规则同步全部步骤。
保存继续提交 `expectedRevision`，并发冲突保留草稿并使用平台统一提示。点击其他用例、筛选、
DDT 功能页签或勾选批量操作前，未保存的编辑需明确放弃；保存期间禁止这些切换。勾选用例后，
右侧切换为所选范围的批量操作区，继续提供修改、导出、回收和加入任务。

Lite 动态字段筛选修正为 SQLite 的点号加带引号对象键路径，并以参数绑定传入；中文、点号、括号、
引号和反斜杠不会被当作嵌套路径。采用 [SQLite JSON 路径语法](https://www.sqlite.org/json1.html#path_arguments)，
通过同一筛选契约验证 SQLite/PostgreSQL 的字面字段匹配。

该调整不修改数据库 schema、API、Runner Protocol 或离线依赖，Lite/Full 使用同一页面和应用用例。

## 经确认不重复迁移的能力

以下功能不是遗漏，而是已经由 AutoForge 提供覆盖范围更完整的实现，因此不会复制第二套页面、表或身份事实：

- 本地用户、会话、LDAP、角色与权限：LDAP 配置和鉴权字段复刻 DDT Insight，复用统一身份/RBAC、LDAPS、锁定和会话撤销；Group 只作为用户资料，不映射权限。
- 审计：复用 Lite/Full 共享的不可变审计事件及项目权限过滤。
- 备份恢复：复用数据库与对象目录一致性备份、Full 依赖恢复和升级回滚手册。
- 系统诊断：复用 liveness/readiness、平台诊断、容量和依赖检查。
- 独立 API Key：复用服务账号/API Token 的权限范围、到期和撤销能力。

这避免了同一个人、权限或备份状态在两个子系统中产生冲突。若上游以后增加这些平台能力的差异行为，应先扩展 AutoForge 的共享端口，而不是恢复一套 DDT 专用实现。

## 导入、恢复与存储

### 跨版本继承

“DDT 工作台 → 继承用例”可选择同项目其他版本的测试阶段，将该阶段的全部活动 DDT 用例复制到
当前版本/阶段。目标用例使用新的内部 ID，从修订 1 开始，保留 CaseID、SR、普通字段和完整用户旅程；
来源显示所选版本与阶段。来源、目标之后独立编辑。目标已有的 CaseID 按大小写不敏感规则跳过，
不覆盖正文、修订或历史；重复点击或请求结果丢失后重试不会重复创建。回收站数据不参与继承。

执行类仍由目标版本/阶段的 SR 分类与关联解析，不复制来源分类、候选测试类、字段模板、修改/执行
历史或任务成员；目标未配置关联时仍须先关联执行类才能执行。用例公开 API 通过目标范围 URL 读取
新副本，Runner/Adapter 协议与现有 CaseID 执行方式不变。

管理接口 `POST /api/v1/ddt/cases/inherit` 的查询参数固定目标三层范围，请求正文包含
`sourceProjectVersionId`、`sourceTestStageId` 和可选 `cursor`；目标要求 `case.manage`，来源要求
`case.read`，服务端校验两端都属于同一个项目，拒绝从当前版本继承。每次响应返回
`inheritedCount`、`skippedCount` 和可选 `nextCursor`，客户端串行继续，不在一个请求中遍历全量。

Lite/Full 共用应用逻辑及维护工作线程，前台与执行工作有压力时返回可恢复的繁忙提示。每批最多
64 条、正文预算 2 MiB，单条超过预算时仍可独立推进；正文在数据库内复制，不经 Web 线程解析或传输。
SQLite 使用短 `BEGIN IMMEDIATE` 事务及有界异步退避，PostgreSQL 只锁当前批次来源行，并以目标
唯一键处理并发继承。每批独立提交，复制的是该批读取时的数据，不保持跨请求长事务。

界面显示新增/跳过数量，可在当前批次完成后暂停；连续处理约 30 秒也会暂停，点击“继续继承”
从当前游标恢复。错误显示在弹窗中并保留进度，完成使用右上角通知。关闭、刷新或切换页面后不会
继续发起新批次，已提交数据保留；再次选择来源重新开始时会跳过已有用例。响应丢失但已提交的批次
在重试中计入“已存在”。浏览器摘要缓存失效后重读，后台统计继续通过既有快照刷新，不现场全量计算。
本功能没有新增迁移、持久配置、离线依赖或 Runner 安装要求。

### 表格导入

列表与导入状态可并行读取；首次观察到某个导入任务进入终态时，工作台额外重读一次当前筛选下的
有界用例列表，再展示终态并停止轮询，避免“导入已成功、列表仍是提交前的空缓存”的竞态。
相同终态不重复触发这次重读，不增加统计计算或常驻轮询。

导入任务列表与进度轮询使用 `GET /api/v1/ddt/imports?view=summary`，只读取任务计数与状态，
不读取上传配置或完整文件清单。展开“逐文件结果”后才请求
`GET /api/v1/ddt/imports/:id/files`，默认每页 50 个、最多 100 个，按 `(createdAt, id)`
游标分页；收起会卸载明细并中止读取，翻页替换当前页，文件列表在卡片内滚动。展开中的当前页
随任务进度更新，收起时不轮询文件。Lite/Full 使用相同的契约和已有文件索引，按项目、版本、阶段
隔离且不暴露个人调试导入记录。旧的完整预检、导入工作器和读取接口保持兼容，无需数据库迁移。

上传边界为单文件 128 MiB、总计 512 MiB、ZIP 10,000 个目录项；单次请求的上传文件数量和单个 ZIP
内可导入表格数量由持久化平台配置分别控制，新安装默认均为 200，可配置范围均为 1–10,000。Web
请求入口、应用服务和隔离解析线程在每次新导入时读取当前配置，保存后无需重启；Lite 与 Full 共享
相同校验，Full 独立 worker 也从同一配置文件读取当前值。压缩包内容仍受单文件和总解压大小约束。
文件名只用于展示，ObjectStore 键由项目、任务、服务端 ID 和 SHA-256 构造。原始上传作为来源证据
保留，随项目备份；业务记录与对象清理不假设跨存储事务。

预检通过 Lite／Full 共用的隔离维护线程解析表格。Excel 文件压缩大小不代表解析内存：解压 XML、
单元格对象、二维取值及最终用例行会短暂共存。维护线程因此按普通线程最高四倍权重分配堆内存，
仍纳入原有 Web 进程 40% 的工作线程堆预算，不增加解析车道或放开并发；极低内存主机仍受原有
每线程 128 MiB 最小值约束，不能把此堆预算视为进程 RSS 或容器硬上限。
解析禁用不用于 DDT 数据的 HTML 展示副本，并在 Sheet 转成取值矩阵后释放其单元格对象；中文、
数字／日期格式、布尔、公式缓存值、重复列与用户旅程规则保持一致，不截断数据行或字段。
线程确因内存上限退出时，预检显示对应文件名和拆分表格／增加平台进程可用内存的提示，不能把该
文件当作有效文件确认导入；工作线程退出后自动按需重建。没有数据库迁移或新增运维配置。

### XLSX 预检的流式读取

v1.21.8 的内存预算调整仍保留了整本工作簿解析：说明等无关 Sheet 也会产生大量单元格对象。
压缩文件很小并不代表内存占用小。XLSX 预检和后台导入现在共用逐段解压／XML 解析实现，只读取
首个 data Sheet 及全部 step Sheet；先收集有效 Sheet 的字符串引用，再按需保留共享字符串，
不保存无关字符串、HTML 或样式对象。数字／日期仍通过原有格式化器取值，公式只读取缓存结果，
不会执行公式。重复列、CaseID 校验及用户旅程组装共用原实现，其他格式仍使用原读取器。

有效字段以有内容的表头／单元格为准，不让 dimension 元数据、远端空白样式或空字符串撑大矩阵；
字段内的空值仍补空，不丢弃有值的无表头列，而是按原规则报错。XML 文本脱离输入块后才保留，
避免短文本切片持续引用整段 XML；列冲突比较完成后，逐行释放已转换数组。ZIP 外层逐个解压表格，
不再同时保留全部表格的解压 Buffer，但最终用例行仍受实际可用内存约束。

XLSX 内部目录最多 10,000 项，声明／实际解压内容受 512 MiB 总预算保护；每块核对大小与 CRC，
拒绝路径越界、重复内部文件、加密、DTD 和损坏 XML。有效 Sheet 的任何解析或校验失败使整个文件
预检失败，不返回半份有效行。读取仅在内存流中进行，不创建临时文件或发起外部请求。
显式复用并锁定既有生产依赖 saxes 5.0.1（ISC，已随 ExcelJS 离线交付），没有新增外部服务、
数据库迁移或配置项，也没有放宽现有线程堆内存上限。
Full 需同步更新 Web 与独立 worker，不能只升级预检所在的 Web 而让后台正式导入继续使用旧读取器。

本轮以 8100 行、48 列有效数据和约 622 万个说明 Sheet 单元格构造了约 2.56 MiB 的 XLSX，
内部解压内容约 341 MiB；v1.21.8 的 592 MiB 维护堆可复现原中文内存错误，新读取器在 256 MiB
维护堆下逐单元格比对通过。Full／Lite 的 48／256 列共五组大表、114 项定向回归和最终 56 项
格式补测通过。真实 SQLite／PostgreSQL 导入、坏文件整体拒绝、生产 Lite 的两项导入／历史／
导出恢复 Playwright 均通过，已审查 1024×768／1536×960 浅深色截图。
历史场景原有 5 秒完成检查短于资源保护退让加队列轮询窗口，改为有界 30 秒等待，结果和内容
断言保持不变。没有访问用户私有文件，不把合成复现视为对其文件内容的确认；详细命令与边界见
`/var/tmp/autoforge-ddt-streaming-20261030/verification.md`。

### 平台全量导出回导的宽表空值展开

多 SR 全量导出保留所有 SR 的字段并集，但只写实际有值的单元格。即使 XML 已流式读取，若导入随后把每条用例扩成整张表的全部列，仍按“用例数 × 合并列数”创建空值数组和对象。平台自身导出的 8100 条用例、1024 组 SR 字段（共 2050 列）可以在 Full 12 GiB 资源模型下复现 v1.21.9 的解析线程内存错误；之前 48／256 列的密集表测试没有覆盖此边界。

生产导入现使用带版本号的内部表头描述及紧凑行：跨线程只传实际单元格与共享表头，不传完整空白矩阵。每个 Sheet 的全部有效列名仍保留，重复列自动处理和人工确认沿用原规则。有值的缺失表头仍整体拒绝，不能靠丢弃远端数据规避内存问题。

预检每次只规范化最多 64 条用例并查询既有数据，逐窗口累计新增、更新和未变更计数。正式导入预先校验所有行，再将不执行 I/O 的逐条解码器交给原仓储事务；SQLite／PostgreSQL 每处理一条用例才构造有效字段，保留原有整文件事务、冲突策略、状态、历史及失败回滚。个人调试导入也使用相同解码规则。

导入后的用例同样保持稀疏字段：缺失、空字符串、仅空白字符和 null 不作为参数入库，不能依据共享表头补空字符串。`0`、`false`、非空文本的首尾空白、前导零和长文本保留；旅程仅保留实际存在的 Step，逐步骤移除空字段，不补回明确缺失的步骤。表头仍供解析校验、重复列处理和预检使用，整列均空的新导入字段不会出现在之后的用例导出中。覆盖策略仍替换整条用例；表格清空某字段后，不会保留该字段的旧值。

上述导入优化本身不需要数据库迁移、运行配置、在线依赖或 Runner 协议变更；下述清空功能另有反查索引迁移。Full 升级须同步更新 Web 与所有独立 worker，避免预检和正式入库使用不同的内存行为。

### 稀疏字段与已有数据清空

单条正文查询已有 `(project_id, project_version_id, test_stage_id, case_id_normalized)` 联合唯一索引，索引由建表迁移创建、随每次写入同步维护，不存在导入结束后再排队补索引的过程。旧版本把多 SR 的字段并集还原成每条用例的大量空参数，详情同时为全部字段生成卡片，造成正文／历史膨胀和浏览器开销。

新导入在应用边界剔除空参数，预检、正式库和个人调试共用规则，普通表格与 ZIP／旅程一致。已有正文不在升级时整库重写；字段页默认隐藏空字段，仍可勾选查看，按字段名搜索，每页最多48个字段，长值每次展开8192字符。复制和编辑使用完整原值；这些展示操作不改写已有数据库或执行快照。

“DDT 管理 → 用例库 → 清空 DDT 用例”要求当前项目的 `case.manage` 与 `case_suite.manage`。弹窗核对活动用例、回收站、关联任务及成员数量，输入“清空DDT用例”后才提交。清理当前项目、版本、阶段的全部范围，不受搜索、SR、勾选或列表分页影响。永久删除活动 DDT、修改历史和回收站，先从每个关联任务移除当前范围的 DDT 成员、增加任务版本与 revision 并保存快照；任务、普通成员、其他阶段／版本的 DDT、已有批次和执行数据保留。SR 执行类关联、标签、模板和原始导入文件继续保留，方便重新导入。

确认时使用服务端 UTC 截止时间，只处理此前存在且未再次更新的记录。浏览器串行请求有界窗口：每次处理一个任务的范围成员，或至多100条用例／修改历史／回收站记录。原生 SQL 移除任务成员后，只构造剩余成员的配置快照，不读取全部 DDT 正文；所有清理写入在维护线程执行，避免阻塞 Web 与租约控制。每页事务同时保存审计并使读模型失效，Full 对候选行加锁，Lite 使用短写事务；有锁竞争或新增引用时明确报错，可以继续剩余数据。

“停止清理”在当前窗口结束后生效，已提交的删除不回退；网络失败、关闭页面或重启后可重新核对并清空剩余数据。重新导入会生成新用例记录，需要重新加入保留的任务；旧执行仍可从执行记录访问，不自动合并到新用例身份。清空是不可恢复的删除，操作前按平台流程备份。数据库内部页可复用，数据库文件的物理大小不保证立刻缩小，不在 Web 请求里执行全库 VACUUM。

SQLite0092／PostgreSQL0090只新增任务成员的 DDT 反查索引。没有新配置、外部服务或 Runner 协议，Full 需同步升级 Web 与独立 worker。Lite 的清理和审计都保存于 SQLite；Full 保存于 PostgreSQL，不以 Redis 或消息队列决定删除事实。

Lite 的预检、确认和导入状态保存在 SQLite，确认事务同时写入 SQLite 持久队列。Full 的确认事务同时写 PostgreSQL outbox，再由 relay 发送到 JetStream。工作器续租队列消息；若进程中断，重投可重新领取 `running` 任务，只处理 `valid/importing` 文件。单个文件的用例写入、覆盖历史、CaseID 结果和文件成功状态在同一数据库事务内完成，因此恢复不会把半个文件误报为成功。

表格列名去除首尾空白后按大小写不敏感规则判重。同名列先自动整理：整列均为空的列直接忽略，
全空组保留第一列；其余列逐行比较完整 Sheet，整列数据完全一致时保留第一列，其余重复列忽略。
空字符串和仅空白字符视为空列，`0`、`false`、后续行的值均算非空；非空列比较保留值类型、行顺序
和有意义的首尾空白，不用内容样例或非空数量代替相等判断。不同列名的数据不合并。
自动整理后的身份列仍使用 `CaseID`/`srNum` 规范名称；每个 ZIP 条目、Sheet 独立处理。

只有剩余同名列的数据不同时才需要人工确认。预检任务在 `uploads_json` 中保存文件、ZIP 条目、
Sheet、零基列位置、建议名称、整列非空数量和最多 8 个、单值最多 256 字符的非空内容样例。页面并排
展示冲突列，提供全部/单组建议改名和“仅保留此列”快捷操作，也允许逐列改名保留或删除整列；每组
至少保留一列，`CaseID`/`srNum` 仍须保留一个规范列名。ZIP 中每个表格独立产生有效、冲突或失败结果，
冲突不会吞掉同一压缩包中的有效/损坏条目，页面同时展示压缩包名和内部路径。处理请求直接读取
ObjectStore 中的原始文件并原子替换同一个预检任务的逐文件结果，不重复上传或创建遗留任务；选择
随任务保存。后台 Worker 再次解析同一份原始文件，先应用相同的自动整理，再应用显式手工选择；
自动忽略的副本不会因操作者删除其保留列而重新出现，旧任务中明确指定的保留、改名和删除继续生效。
因此预检结果不会与实际导入分叉，原始上传文件也不被修改。
内容样例只返回给当前有管理权限的导入操作者，不写审计日志。

重复列弹窗不再提供“一键删除空白冲突列”按钮，空列和相同数据已由解析器自动处理。
不同内容的冲突列仍可使用建议改名、“仅保留此列”、逐列删除和人工改名；仍需应用重新预检后确认后台导入。

预检的“处理重复列名”入口位于文件列表下方；解决弹窗的校验错误、请求失败和待应用方案也位于冲突
列表下方，靠近操作按钮。多组卡片在有界区域滚动，底部操作区保持可见。“仅保留此列”保留已输入的
普通列名称；身份列仍规范化为 `CaseID`/`srNum`。“暂不处理”后在同一个导入弹窗重新打开会保留草稿，
应用失败也保留选择以便重试；关闭整个导入弹窗前尚未应用的草稿不持久化。应用期间禁止改动或关闭，
避免客户端显示的方案与提交内容分叉。改名与其他列再次重名时同样先自动整理空列与相同数据，
只有数据不同时继续展示新冲突，全部解决后才允许确认。
重新预检不会写入用例，仍需操作者明确选择 CaseID 策略并确认后台导入。

## DDT 执行快照

平台和 Runner Protocol 中的 `adapter.caseId` 保留原始字符串；Runner 调用受管 CoTest Adapter 时，
使用 `--case-id-base64` 传递 UTF-8 字节的标准 Base64，Adapter 严格解码后再调用
`MM2DataProvider.setClassDataProvider(className, caseId)`。仅 ASCII 穿过 JVM 命令行入口，
因此中文 CaseID 不受执行机 `C` 等非 UTF-8 locale 影响。原有 `--case-id` CLI 仍兼容；
升级主平台后需使用执行机升级入口更新 Runner 与配套 Adapter，无需改任务、业务 JAR 或系统 locale。
不新增协议字段、数据文件、数据库迁移或运行配置；Lite/Full、调试、批跑和重跑共用该传输路径。

DDT 单用例快捷执行使用 `POST /api/v1/ddt/cases/:caseId/execute`，URL 显式携带项目、版本和阶段，
请求体复用普通单用例执行配置。入口要求 `run.create`，服务端重新读取当前 DDT 数据、SR 关联及可用
测试类，并沿用普通用例的来源、Runner 与 Adapter 预检。创建的 `single:<DDT id>` 批次保留 DDT 身份、
数据修订、CaseID 和执行类版本，不会转成一次裸 TestNG 类执行。Lite/Full 都通过调度工作线程完成
预检和批次持久化，不序列化或下发动态字段 JSON；Runner 与断线恢复继续使用已有执行协议。

列表眼睛和字段详情的“查看执行详情”打开共享用例详情组件。`/summary` 只读取元数据和关联类；
`/workspace`、`/executions`、`/failure-analyses` 都按当前 DDT 作用域鉴权，以 DDT 稳定 ID 查询有界
历史窗口，续读游标保留作用域。源码、方法和版本来自关联类，预览不提供修改共享执行类的操作。
预览与执行配置不加载动态字段正文，完整数据仅由字段编辑或实际执行按需读取。

DDT 数据本身不是 Java class。“用例管理 → DDT 管理 → SR 测试类关联”打开独立页面
`/cases/ddt-associations`。先在“配置测试类范围”中维护需要执行 DDT 的少量 TestNG 测试类，
在“配置需求分类”中维护分类名称及执行类，再按 SR 设置分类，形成 `SR → category → CaseDefinition`。候选范围、分类与关联都按 `projectId + projectVersionId + testStageId`
隔离；写操作需要 `case.manage`，查看需要 `case.read`。候选添加、分类保存与 SR 关联都复核同项目内已就绪、活跃的受管 JAR 来源、
启停和归档状态；仍被分类或旧客户端直接关联的 SR 使用的候选类不能移除。分类名称在作用域内唯一，正在被 SR 使用的分类不能删除。

平台保存分类的执行类引用和 SR 的分类引用，不允许逐 CaseID 覆盖。同 SR 的现有用例、后续导入、回收恢复与
修改 SR 的用例，在读取或创建执行快照时自动继承该 SR 的关联；修改不扇出更新整个 SR 的
DDT 用例，也不增加其数据修订号。分类和 SR 关联分别使用独立修订号防止并发覆盖，分类编辑、删除、范围移除与关联写入在同一
作用域内串行化。无关联、旧关联待确认或测试类不可用时，新执行会被预检拒绝。
分类支持名称搜索与游标读取，不批量更新 SR 或 DDT 记录。列表按 SR 前缀搜索，以游标按需读取最多 100 个 SR；只统计当前窗口的分组用例数量，浏览器
会话缓存避免反复进入时重复查询。候选列表也按需加载，TestNG 搜索最多返回 50 个匹配项，
需要时输入更具体类名缩小范围。搜索按完整类名（含包路径）或用例展示名进行不区分大小写的包含匹配，
不要求 JAR 被标记为目录对比使用的“权威来源”；新导入和重导后的当前定义均可搜索、加入和关联，
不会从历史 JAR 补充已替换的执行类。需求分类的执行类搜索仅查询已加入的候选范围；高级检索仍只匹配 DDT 数据的 Value。
没有引入 Redis、队列或新后台统计作为关联事实来源。

DDT 用例可与普通用例加入同一个任务，任务详情将普通用例按包路径、DDT 用例按 SR 分别展示。
平台保存的是 `CaseDefinition` 标识，不接受任意 JAR 路径；任务预检、任务详情和导出都读取
SR 的关联。同一次任务读取跨多个 SQL 窗口时，每个 SR 及共享的分类固定首次读取到的执行类，避免并发修改
导致同一批次混用该 SR 的新旧测试类；重复测试类 ID 会合并查询。批次一旦创建，后续关联变更不会改变既有执行记录、重试或诊断重跑的快照。

升级迁移为 SQLite `0068_ddt_sr_execution.sql` / PostgreSQL `0066_ddt_sr_execution.sql`，
新增候选范围、范围修订与 SR 映射表。迁移同时检查活动用例和回收站：同一作用域/SR 的非空
旧关联一致时自动继承，出现多个不同测试类时标为“旧关联待确认”，不擅自选择；已有候选类
自动进入范围，原始逐用例字段保留用于升级核对，但不再参与新执行或作为回退。无历史关联的
SR 保持未关联。升级前备份数据库；DDL/迁移数据在事务内，失败会回滚，可修复原因后重试。
需要降级旧程序时必须恢复升级前备份，因为旧程序不能识别新的 SR 配置；不要仅回退二进制。

分类升级使用 SQLite `0070_ddt_requirement_categories.sql` / PostgreSQL `0068_ddt_requirement_categories.sql`。
原有非空 SR 关联按执行类转换为可重命名的“历史分类”，未关联与历史冲突保持原状。迁移不修改用例数据、修订号或历史执行。
DDL 和转换在同一事务中；失败回滚后修复并重试。降级须恢复升级前数据库备份，旧程序不能解析分类引用。
公开日志的 `casePath`、`displayName` 分别来自选中执行快照的 `className`、`displayName`，DDT 后者为 CaseID，
不读取当前分类覆盖历史；`caseType` 为可选兼容新增字段，普通用例和 DDT 共用类路径展示。

`case_suite_ddt_items` 对 DDT 资产使用限制删除。回收操作会先检查任务成员关系，并以
`DDT_CASE_IN_USE` 拒绝仍在任务中的 CaseID；用户必须通过任务成员接口移除，使任务版本快照记录
这次范围变化后才能删除资产，不能依赖外键级联静默改写任务。

创建批次时，`ExecutionRun.caseDefinitionId` 标识 DDT 资产，`displayName` 保存原始 CaseID，
`executionCaseDefinitionId` 与 `caseVersion` 标识执行的 TestNG 类及版本。assignment 通过
`adapter.caseId` 下发 CaseID，Runner 使用独立参数 `--case-id` 交给 Adapter，后者调用
`MM2DataProvider.setClassDataProvider(className, caseId)`，不进行文件转换或数据下载。
执行规格同时保存 `adapter.ddtScope`（项目、版本、阶段）。Runner 使用当前身份的控制面入口
生成以 `/case` 结尾的公开 API URL，Adapter 在测试类初始化前调用
`MM2DataProvider.setDdtInsightUrl(String)`；不附带 CaseID 查询参数或 Runner 凭据。
范围来自执行类所属版本与阶段，跨版本继承时采用目标范围，不能使用原 JAR 来源的范围。
调试、用例管理立即执行、任务批跑和重跑共用此逻辑。测试类自行编码 CaseID 并获取数据；动态字段以 API
请求时的当前值为准，不再是批次创建时的数据快照。诊断重跑仍沿用 CaseID 和执行类身份。

仅含 DDT 的执行或混合批次要求 Runner 声明 `adapter:ddt-insight-url-v1` 与 `adapter:ddt-case-id-v1`；
预检和调度都会检查，旧 Runner 明确提示升级，升级同时安装配套 Adapter。普通 Adapter 用例不下发
DDT URL，也不加载 MM2DataProvider；混合批次逐用例区分，只有 DDT assignment 携带范围和 CaseId。
DDT 缺少该类、或者缺少 setter 时明确失败并提示更新全量依赖包。Runner 和 Adapter 忽略历史普通
执行中残留的 DDT URL。未启用 Adapter 的原生 TestNG 执行不加载 CoTest 类。
执行规格字段可选、持久于既有 assignment JSON；个人 DDT 数据另通过 SQLite 0073 / PostgreSQL 0071 迁移保存。历史 assignment 保留原规格。
升级 Runner 自动更新受管 Adapter；升级前已分配的 `class-data` 文件协议任务在新 Runner 上明确
拒绝，需结束或停止后重新发起。历史数据库列和输入读取契约保留以支持旧记录，新批次不写 JSON 正文。
Lite/Full 分别持久化于 SQLite/PostgreSQL，共享业务与协议语义，无新外部服务或公网依赖。DDT 调试的 `ddtScope.debug` 保存用户及只读访问标识，调试 URL 在阶段路径后增加 `/users/{userId}/debug/{accessKey}/case`，读取个人库并验证全部范围；DDT 用例管理立即执行和批跑不携带 `debug` 字段，读取正式库。见[调试工作台](../design/case-debug-workspace.md)。

## API 概览

以下管理请求都必须带 `projectId`、`projectVersionId`、`testStageId` 查询参数并通过鉴权：

- `GET /api/v1/ddt/dashboard|groups|cases|templates|recycle|imports`
- `GET/PATCH/DELETE /api/v1/ddt/cases/{CaseID}`
- `GET /api/v1/ddt/execution-classes`
- `POST /api/v1/ddt/cases/search|bulk-update|bulk-delete`
- `GET/POST /api/v1/ddt/execution-range`（候选范围查询／加入移除，写入携带 `expectedRevision`）
- `GET /api/v1/ddt/sr-mappings`（SR、分类与解析后的执行类；旧 `POST` 直关联接口保留兼容，写入后解除该 SR 的分类引用）
- `GET/POST /api/v1/ddt/requirement-categories`（分类游标列表、创建/编辑，编辑携带 `expectedRevision`）
- `POST /api/v1/ddt/requirement-categories/delete`（删除未使用分类）
- `POST /api/v1/ddt/sr-categories`（设置分类或传 `categoryId: null` 解除，携带 SR 的 `expectedRevision`）
- 原 `POST /api/v1/ddt/cases/execution-class` 返回 `DDT_SR_MAPPING_REQUIRED`，提示改用 SR 关联
- `GET /api/v1/ddt/cases/{CaseID}/history`
- `POST /api/v1/ddt/cases/{CaseID}/history/{historyId}/restore`
- `POST /api/v1/ddt/imports/preview`（`multipart/form-data` 的 `files`）
- `POST /api/v1/ddt/imports/{jobId}/resolve-columns`
- `POST /api/v1/ddt/imports/{jobId}/confirm|cancel`
- `GET /api/v1/ddt/imports/{jobId}/case-ids`
- `POST/PATCH/DELETE /api/v1/ddt/templates/{templateId?}`
- `POST/DELETE /api/v1/ddt/recycle/{recycleId}/restore?`
- `GET/POST /api/v1/ddt/export`
- `POST/DELETE /api/v1/case-suites/{suiteId}/ddt-cases`

API 响应继续使用 AutoForge 的稳定错误码、`requestId`、游标分页和显式 DTO；不会返回 ORM 行或对象存储凭据。

“按清单选择”使用 `POST /api/v1/ddt/cases/search` 的可选 `caseIds` 数组，每次最多 200 个、每个最多
512 字符，空数组返回空结果。该查询只要求 `case.read`，沿用同源与范围授权；请求体上限 512 KiB。
Lite/Full 均按范围及规范化 CaseID 索引精确查找，仅返回摘要，不加载用例正文。客户端顺序处理各批次，
完成后才应用选择，取消或失败不会应用部分结果，也不会因只读匹配清空浏览器缓存。输入文件复用普通用例
的首列读取器（32 MiB、首个工作表最多 100,001 行），但编号不使用 Java 类路径的斜杠规范化规则。

### 按清单从任务移除

在 DDT 管理页通过“按清单选择”上传表格或粘贴 CaseID，勾选匹配用例后，右侧操作区提供“从用例任务移除”。手动勾选、筛选结果和清单勾选使用同一入口，包含左侧尚未加载的已选用例。选择当前项目版本的目标任务，点击“预览匹配”，完成后显示任务内匹配数量与跳过数量，每类最多预览八条；“确认移除”只在完整预览且存在匹配时可用。更换任务清除预览，取消或匹配失败不写入；没有匹配时禁止提交。

移除范围绑定当前版本和测试阶段，以平台用例 ID 执行，避免误删其他阶段的同名 CaseID。普通成员、其他任务的相同成员、用例库及既有执行记录保留。只改变任务成员关系，并沿用既有任务版本快照和操作审计；不立即执行或取消批次。最终匹配／跳过计数指预览时的交集，重复提交相同用例为幂等操作。请求超时会明确提示任务可能已更新，可重试核对。

新增只读 `POST /api/v1/case-suites/{suiteId}/ddt-cases/matching`：输入 `projectVersionId`、`testStageId`、`caseIds`，每次最多 200 个 CaseID，请求体最多 512 KiB。项目从已授权任务推导，版本不一致明确拒绝；要求对应项目 `case_suite.manage` 并检查同源。响应为 `items: [{id, caseId}]` 和 `unmatchedCaseIds`，只查询轻量用例摘要与候选成员 ID，不读取完整任务、DDT 正文、日志或执行历史，也不生成任务版本。客户端串行收集完整结果后，调用原有 `DELETE /api/v1/case-suites/{suiteId}/ddt-cases`，以一次事务和一次版本快照完成移除，事务内部继续有界分批 SQL。整体沿用 100,000 条任务成员能力。

Lite 使用 SQLite 任务成员表和已有短写事务，Full 使用 PostgreSQL 对应实现；没有新增迁移、依赖或配置，不涉及队列、对象存储、缓存事实或 Runner Agent 协议。页面仅使用现有 Ant Design 和离线资源。

验证（2026-10-25）：45 项定向测试通过，包含真实 SQLite/PostgreSQL 的按阶段匹配、仅移除指定任务成员、用例正文和执行快照保留、重复提交不重复更新任务版本；应用测试确认不读取完整任务及 DDT 正文，客户端测试覆盖每批 200 条的分页、中断和失败。主要命令为 `AUTOFORGE_TEST_POSTGRES_URL=<一次性数据库> pnpm exec vitest run packages/db/test/suite-ddt-removal.integration.test.ts packages/application/test/match-suite-ddt-selection.test.ts packages/application/test/manage-case-suites.test.ts apps/web/src/lib/suite-ddt-removal-selection.test.ts apps/web/src/lib/ddt-case-selection.test.ts apps/web/src/components/ui-usage.test.ts --maxWorkers=1`。

Web 与测试 TypeScript、变更文件 Prettier/ESLint、Web 生产构建通过。生产 Lite 使用 `pnpm exec playwright test tests/e2e/ddt-management.spec.ts --grep 'DDT list selection removes|DDT selects existing cases from Excel or text' --workers=1` 分别验证新增移除和原有清单添加。新场景包含未加载用例、中文 CaseID、空任务、版本不一致拒绝、匿名 401、取消、匹配与移除失败后重试，以及普通成员、其他任务及其他阶段同名用例保留。首次新场景因夹具未切换项目上下文而在导入普通用例前失败，补齐上下文后单独复验通过；没有增加重试或放宽断言。

### 匿名用例查询

固定范围前缀为 `/api/v1/public/ddt/projects/{projectId}/versions/{projectVersionId}/stages/{testStageId}`，三个 ID 使用平台稳定 ID，项目或版本改名不改变已有地址。前缀下提供两个等价入口：

- `GET /case?caseId={CaseID}`
- `GET /cases/{CaseID}`

范围只读取路径参数，查询参数或浏览器选中范围不能覆盖它。输入在契约层校验，CaseID 去除首尾空白后长度为 1–512，查询沿用大小写不敏感匹配。中文、空格、`/`、`?`、`#`、`%` 等字符需 URL 编码；包含路径保留字符时优先使用查询参数形式。

成功响应直接返回 `DdtCaseData`，保留字段名、数字、布尔值、null 和用户旅程嵌套，不包裹 `data`、版本或管理信息。例如：

```json
{ "CaseID": "PAY-001", "srNum": "PAY", "amount": 12, "enabled": true, "note": null }
```

不存在、已回收或不属于路径范围的用例返回 HTTP 404 / `DDT_CASE_NOT_FOUND`，不会回退到其他范围。参数错误返回 400 / `VALIDATION_FAILED`，数据库繁忙沿用 503 / `PLATFORM_BUSY`；错误统一使用 `error.code`、`error.message`、`error.requestId`。两个入口只支持 GET、HEAD、OPTIONS；管理写操作仍在原鉴权入口执行。

响应使用 `Cache-Control: no-store, max-age=0`、`Access-Control-Allow-Origin: *`、`X-Response-Time`，成功和错误都可跨域读取。OPTIONS 无需建立平台服务。查询复用 Lite/Full 的三层范围与 CaseID 联合索引，单次只读一条权威记录，不触发表格解析、列表统计、会话更新或逐请求调用量落库。更新、导入覆盖、回收和恢复后，后续查询立即反映权威状态；已开始执行的批次仍使用自己的不可变快照。

“开放 API”子标签页地址为 `/cases?tab=ddt&ddtView=api`，首次进入不请求 DDT 列表、统计、模板、导入任务或回收站。在线验证显式省略浏览器凭据，15 秒超时，切换子页或范围时取消未完成请求；长响应只渲染前 24,000 个字符，仍可复制完整 JSON。地址与示例随当前范围和 CaseID 生成，已复制地址不会跟随之后的顶栏切换。

## 概览执行统计

DDT 概览的“近 7 日执行”展示当前项目、版本、阶段的 DDT 执行记录，按执行创建日期（UTC，自当天起向前六个完整日期）分组，截止后台统计开始时间。每天显示执行次数以及通过、不通过（含超时）、已终止和未完成的分布；空日期补零。每条 `ExecutionRun` 计一次，同一记录的重试 attempt 不重复累计，普通 TestNG 用例和公开日志诊断重跑不计入。回收站仍保留的 DDT 用例也参与历史统计，重复回收记录不会放大数量；清理回收站或执行记录后，相关历史数据不再参与后续快照。

统计复用共享后台读模型，数据库只返回七日聚合结果，不向 Web 加载执行明细、日志或用例 JSON。Lite 在读模型 worker thread 中计算并持久化到 SQLite；Full 在后台通过 PostgreSQL 保存同样的结果。统计采用应用注入的时钟，Full 沿用共享 PostgreSQL 校准时间。

浏览器直接显示快照及实际统计时间，不定时轮询 DDT 概览。重新进入页面可复用五分钟内的浏览器缓存，点击“刷新”读取最近已发布的后台快照，不要求当场重算；后台对最近有人访问的查询沿用至少 60 秒的刷新间隔，资源紧张时允许延后。导入进度的原有轮询保留。旧的创建日期 `timeline` 响应字段保留用于兼容，新图表使用新增的 `execution` 字段；新请求带 `statisticsVersion: 2` 使用独立快照键，避免升级后显示旧统计。部署时同步升级平台节点和后台工作器，无数据库迁移或 Runner/Adapter 变更。

## 全部用例导出

DDT 工作台提供“导出全部用例”，以当前项目、版本、阶段作为完整范围，忽略当前勾选、CaseID 搜索、分组和高级筛选；仅导出活动库，不包含回收站。
“导出当前范围”与勾选导出继续沿用原先 SR/分类或 CaseID 范围语义。管理 GET/POST `/api/v1/ddt/export` 仍要求 `case.read`，POST 仍验证同源；空选择对象表示完整范围，没有新增公开下载入口。

每个数据库读取窗口最多 64 条、目标 JSON 正文预算 2 MiB；超过预算的首条仍完整读取，避免遗漏大用例。
按 CaseID 游标前进，仅查询 JSON 和游标，不读取执行类、历史或执行记录。数据库读取之间释放事务，不持有跨请求长事务；导出反映各页读取时的活动数据，期间有并发编辑时可重新导出获取最新完整范围。

服务端按页暂存不可见的 JSON 快照，在全部分页共享字段别名规划后，从磁盘逐行生成 XLSX，不在内存保留全部正文或完整压缩文件；
同名不同值列、数值/布尔/空值、文本前导零与缺失旅程步骤保持兼容。每 32 行让出事件循环，导出格式与已有列宽、主题样式共用。
先完成文件再发送下载头；生成失败不返回部分 ZIP。临时文件在打开后立即删除目录项，仅由句柄持有，成功、失败、取消及进程退出都不会留下导出正文。
单元格内容超过 Excel 限制或含非法 XML 字符时明确指出 CaseID/字段并终止，不静默排除用例。界面显示准备状态，可取消，禁止重复并发提交；浏览器接收最终 XLSX 下载文件。

Lite 使用本地 SQLite 与平台数据目录下暂存文件；Full 使用 PostgreSQL 与发起导出的 Web 节点暂存目录，无 MinIO、Redis、NATS 正确性依赖，无新迁移、配置、离线依赖或 Runner/Agent 变更。

### 范围导出的空单元格膨胀保护

跨 SR 合并字段时，工作表保留所有列名，但不为每个用例创建整行字段并集的空单元格。只写实际非空字段，原值为 `0`、`false`、空格或公式形式的文本仍原样作为值保留；缺失、`null` 和空字符串在保留的列中仍表示空白。别名冲突处理、列宽、冻结表头、自动筛选和用户旅程缺失步骤标记沿用原规则。

旧实现同时构造完整列数组、为每个空单元格建立样式，生成量按“行数 × 合并字段数”增长。不同 SR 的字段差异大或表格中空值多时，少量勾选可以正常导出，但全量和当前范围导出会生成大量没有数据的 XML 与样式。当前实现按实际非空字段提交单元格；固定列数的执行结果和失败分析导出仍保留原有完整表格样式。

快照读回每次只读取 64 KiB，使用跨块 UTF-8 解码并在消费完本块后继续读取，不再由预读流积压未处理的行。取消或写入失败会关闭当前文件句柄，避免遗留预读流在清理后抛出未处理异常。

完整性回归同时覆盖分页文件与内存工作簿，使用独立 Excel 读取器核对字段、值及其类型；两万条异构用例逐条核对全部非空单元格。浏览器场景核对全量、当前范围、勾选和 SR 筛选下载，并将混合普通／旅程工作簿导入空项目、核对落库数据后再次导出。全空列仍保留表头，同名冲突列保留各自值；这项优化不修改源用例。
