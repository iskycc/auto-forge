# 执行异常诊断

“执行异常”是批次生命周期状态，说明至少一个用例最终因非正常原因结束，或轮次恢复失败。
TestNG 断言失败、测试配置失败和跳过属于正常测试结果，批次仍显示“执行完成”；尚在执行的
用例优先保持运行状态，用户终止最终显示“已终止”。较早的 Runner 异常在后续重试成功后不会
继续决定批次终态。未知或缺失失败结果码保守归为异常，保留原始原因供检查。

## 为什么各轮次看不到超时

轮次列表每个用例只显示该逻辑轮次最后一次尝试；同轮较早的故障可能已经恢复。排队超时在
产生 assignment/attempt 前就结束用例，既没有本次执行日志，也不计入该轮已执行数；此前
界面只显示“未执行”，现在改为“排队超时”与 `QUEUE_TIMEOUT`。轮次恢复失败还可能阻止下一次
尝试启动，已有尝试依然保留上一次测试结果。详情操作区的“查看异常原因”同时覆盖这些情况。

## 异常原因入口

执行记录列表中，将鼠标停在“执行异常”文字上或用键盘聚焦，可查看前三条终态原因，包括
轮次、用例、结果码和说明；“查看全部异常原因”打开同一诊断弹窗。悬浮时才发起读取，成功
结果在当前列表行的生命周期内复用；加载失败支持重试，不批量预取列表中所有任务的异常。
预览在数据库分页前排除已恢复的历史故障，避免它们挤占导致当前终态的原因。
键盘聚焦后可用 Escape 关闭预览；再次聚焦仍可打开，已加载的原因不会重复请求。

弹窗展示轮次、物理尝试编号、用例名称/类路径、异常类型、结果码、说明与发生时间。用例终态
原因、异常尝试和失败的 Jenkins 恢复步骤直接读取持久化记录，不依赖后台统计的刷新时机。
同一次终态与最后尝试原因一致时只显示一条，不重复展示；恢复步骤单独展示其错误说明。
“终态原因”表示当前批次判定依据，“历史异常”表示已经被后续尝试覆盖的证据。
历史失败记录的结果码为 null、空字符串或纯空白时统一显示 `UNKNOWN_RESULT`；说明缺失时
显示明确的兜底文字，仅规范诊断展示，不修改原始记录或异常判定。

弹窗按当前用例终态复核批次状态，使用同一领域聚合规则；发现不一致时显示当前状态及按
终态应有的状态，供检查历史兼容或异常数据，不自动改写权威记录。内网部署的具体批次必须
查看该部署保存的证据，源码复现场景不能替代生产原因确认。

## API 与双模式

`GET /api/v1/run-batches/{batchId}/exceptions` 默认每页 50 条，最多 100 条，用不透明游标续读。
可选 `scope=terminal` 只读取影响终态的记录，默认 `scope=all` 保留完整异常历史；列表预览
使用 `scope=terminal&limit=3`。筛选不会改变终态计数或状态一致性核对。
每条说明最多 8,192 字符，不读取 TestNG 大型报告、环境配置、凭据或完整日志。Lite/SQLite
与 Full/PostgreSQL 共用 SQL 与分类规则，分页读取现有表，无新增迁移、缓存、队列或对象。
Full 查询将排队超时恢复等路径保存的 PostgreSQL 时间表示与 ISO 时间统一为 UTC ISO，
记录、排序和游标比较使用同一格式，保留微秒精度，避免等价时间表示导致跨页遗漏或重复。
只在读取时规范时间，不改写历史记录、执行超时或状态判定。

登录用户需有批次所在项目的 `run.read`。永久匿名执行分享只能读取 token 绑定的同一批次，
不附带执行控制、独立日志或跨项目访问权限；响应禁止缓存。读取失败时可重试，关闭弹窗会
取消浏览器请求，表格在弹窗内部滚动，沿用 Ant Design 与全局深浅色主题。

## Excel 导出

异常弹框底部提供“导出 Excel”，导出当前批次全部异常记录，包含终态原因和历史异常，
不受弹框当前页影响。按钮在读取中、无记录或导出中禁用；下载失败保留原表格和页码，
显示原因并支持再次点击，关闭弹框会取消下载。

“异常原因”工作表包含轮次、步骤、尝试、用例名称、用例类路径、异常类型、原因码、
说明、判定影响、发生时间及 UTC 原值。“判定概览”保留批次编号、导出开始时的当前状态、
按终态应有状态、核对结果、非正常结束用例数、异常记录数、范围和时区。发生时间沿用
页面的平台时区；列头注明时区，UTC 原值独立保留。正文无额外缩进，按字段用途和首批
最多 100 条内容设置有上下限的列宽，沿用统一字体、表头、隔行底色、结果配色、筛选和
冻结列；异常说明保留诊断 API 提供的完整文本，最多 8,192 字符，按文本写入单元格。

`GET /api/v1/run-batches/{batchId}/exceptions/export` 返回 XLSX。可选 `time_zone` 必须为
有效 IANA 时区，省略时使用 UTC；弹框传入平台时区。登录身份要求同一项目的 `run.read`，
永久分享使用同一批次的 `access_token`，不可跨批次导出；响应使用 `private, no-store`。
先校验登录或批次分享身份，再严格校验选项，匿名无效参数不会绕过鉴权顺序。

Lite 和 Full 通过同一应用用例按游标每次读取最多 100 条，逐行提交流式工作簿，不在
服务端加载整个批次。权限和元数据在开始时校验，终态计数只读一次，后续页跳过聚合；
导出不持有跨网络传输的长事务。达到 Excel 单工作表行数限制时自动分表，未设置低容量
用例上限。后续页读取失败会中断下载，浏览器只在完整下载成功后保存文件，避免保存残缺
工作簿。无需数据库迁移、对象存储、缓存、消息队列或 Runner 协议变更。

## 轮次选中标记

执行详情及永久分享页的轮次列表，以勾选图标、浅色高亮行和左侧色条标出当前查看项，顶部
同时展示“当前查看”名称。总结、全部轮次、实际执行轮次和环境恢复行共用同一按钮，任一
时刻只有一项选中；切换环境恢复时不再让对应执行轮次的按钮也显示为选中。选择仍记录于
URL，刷新后可恢复，不新增表格列或改变结果统计。
