# Webhook 完成通知

Webhook 是项目级配置，任务只保存到端点的绑定关系。一个任务可以绑定多个端点，同一端点也可
被同项目多个任务复用；跨项目绑定会被仓储层拒绝。新建或重新启用配置、以及新建绑定，只对其
时间点之后进入终态的批次生效，避免升级或配置操作意外补发历史数据。

## 请求契约

- GET 不发送请求体，系统在已有查询参数后追加 `event`、`batchId`、`suiteId`、`status` 和
  `completedAt`。
- POST 使用有效 JSON 对象或数组模板，支持配置页列出的 `batch.*` 与 `summary.*` 变量。变量值
  在替换时按 JSON 字符串转义，最终请求体会再次解析校验。
- 地址只允许 HTTP/HTTPS 且不能内嵌账号密码。为支持隔离区内部服务，不禁止私网地址；管理员
  应仅配置可信接收端。系统不跟随重定向，请求十秒超时，只把 2xx 视为成功。

## 可靠性与双模式

终态 `run_batch_status_events` 是物化来源，`(webhook_id, batch_id)` 唯一约束保证同一端点和批次
只创建一条投递。投递记录保存名称、地址、方法与请求体模板快照，因此后续编辑不会改变已经
进入队列的请求。

Lite 使用同一 SQLite 数据库，以 `BEGIN IMMEDIATE` 原子领取到期记录；Full 使用 PostgreSQL
`FOR UPDATE SKIP LOCKED`，由独立 Worker 领取。两种模式都使用 30 秒租约，网络错误和非 2xx
响应最多尝试五次，间隔依次为 30 秒、2 分钟、10 分钟和 30 分钟。进程在发送期间退出时，租约
到期后可由下一进程继续。通知成功或失败只更新投递记录，不参与批次状态机。

删除端点会软删除配置并移除当前任务绑定，历史投递及诊断仍保留。当前版本不保存任意自定义
鉴权头；需要专有认证的接收端应通过可信的内部网关转换，避免长期秘密进入配置和审计路径。
