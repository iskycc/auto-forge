# 公开用例日志加载排查

用户反馈 Lite 批次执行期间，首次打开已完成用例的公开日志等待超过 20 秒。本次检查针对分享链接生成、公开页读取及日志文件读取路径，没有访问用户的生产数据库。

## 已确认的额外开销

旧公开页先调用 `getSummary`，随后调用 `getRerunSnapshot`；后者再次读取整批统计，还解析批次完整的 Adapter 环境映射、查询最近实际 assignment 和恢复规则。登录用户的重跑权限检查又调用 `getSummary`。因此读取一个用例日志会最多重复三次整批统计，并承担只有发起执行时才需要的配置查询。

Lite 的这些数据库查询在 Web 主线程同步执行。批次规模、重试数量、历史 assignment 和运行时 JSON 越大，读取一个已完成用例时的额外开销越大；首次访问也容易受到冷文件页和其他执行请求的影响。此路径已通过失败的应用回归测试复现。未取得生产查询计时，不能将用户报告的全部 20 秒精确归因于某一条 SQL。

旧日志正文读取还按每 16 块重复进行 attempt/批次查找、日志线程读取和水位读取。许多小日志块会放大往返次数，单次分页期限不能代表整次公开页的完成期限。

## 修正范围

- 增加应用仓储端口 `getAttemptLogSnapshot(batchId, executionRunId)`；SQLite/PostgreSQL 只按指定批次与用例读取展示字段和已固化的依赖更新时间。不读取完整用例集合、恢复密文或准备重跑环境轮换。
- 公开页与登录后的项目权限检查使用不含统计的批次元数据。元数据 SQL 排除大型 `adapter_runtime_json`，展示查询在数据库内仅提取依赖更新时间。
- 日志窗口最多读取 128 块；仓储的字节预算及公开页 512 KiB 上限继续生效。Full 所属日志节点沿用最多 32 块的协议窗口，主平台接受其游标继续读取，不要求协议升级。
- 分享凭据、同一用例历史/诊断重跑家族边界、项目权限、日志脱敏及存储方式沿用原契约。没有数据库迁移、配置项或新依赖，也没有调整页面布局与样式。

## 2026-10-19：首次诊断重跑与站外登录态

用户反馈同批次首次从公开日志提交 DDT 重跑需要几十秒，而后续提交明显加快。读取日志的优化没有消除提交重跑时的历史查询：查找上一次实际 Adapter IP 及执行机仍使用跨表 OR 条件关联全部 assignment / attempt，再排序选取最新记录。SQLite 回归测试的真实查询计划出现 `SCAN assignment` 及临时排序，历史记录较多时会增加读取量；冷文件页会放大首个请求的开销。未取得用户现场查询时序，不能将全部等待精确归因于这一条 SQL。

修正后先通过原用例 ID 和诊断家族索引得到相关 execution run，再通过 attempt 的 execution run 索引与 assignment 的唯一 attempt 索引读取历史。Lite/Full 使用同一 SQL 构造；保留按创建时间及 ID 选取最新历史的规则、旧执行规格的实际 IP 回退以及执行机轮换语义，不新增索引迁移、缓存或全量预热。

站外首次访问登录态问题已在真实 Chromium 中复现：`SameSite=Strict` 会话 Cookie 不随跨站首次导航发送，公开日志的服务端首屏因而按匿名渲染；旧页面没有后续登录态恢复。现仅在首屏缺少身份时调用一次已有的同源 `GET /api/v1/auth/session`，成功后刷新当前 Server Component 权限；保留 Strict/HttpOnly Cookie 和原有项目鉴权，不使用客户端权限推断直接开放执行按钮。检查期间显示加载状态，401 仍显示登录入口，网络或服务失败显示可重试按钮，离开页面会中止请求。会话查询返回 `private, no-store`，确认过程不续期或定时轮询。

该恢复组件由新旧公开日志页共用。任务日志仍不订阅 WebSocket；只有服务端判定为手动执行且拥有日志读取权限时才启用原有实时逻辑。

### 本次验证

- 修改前的 SQLite 查询计划回归稳定复现 `SCAN assignment`；修改后 assignment 使用 `assignments_attempt_uq`、attempt 使用 `run_attempts_run_round_number_idx`，只在目标用例家族内排序。10,000 条执行记录夹具包含更晚的无关用例历史，选取环境与执行机仍准确。
- 75 项定向测试通过，包含真实 SQLite/PostgreSQL 快照、实际环境和执行机历史轮换、当前版本依赖、应用重跑、权限、Cookie 安全与 Ant Design 使用约束；受影响文件 ESLint、数据库/测试类型、格式/许可证、E2E 矩阵及 Web 生产构建通过。
- 真实 Chromium 跨站导航验证首次请求没有会话 Cookie，旧构建一直显示登录入口；新构建在一次同源查询后自动恢复执行按钮，未手动刷新。新增加载中、503 后手动重试、401 匿名入口检查，匿名用户不能获得执行按钮。
- 中文 DDT 连续重跑及 API 阶段定位完整流程、在执行 501 用例批次的日志重跑与再次重跑流程通过。仅半个 CPU 的本地服务中，DDT 两次重跑提交的服务端响应为 34ms、29ms，普通用例为 39ms、24ms；这些是隔离夹具的实测，不代表现场大库耗时。
- 已实际查看 1024×768、1536×960 浅色/深色日志页，以及加载中、确认失败和匿名入口截图，无新增挤压、换行异常或越界。重负载检查与浏览器串行，临时服务结束后关闭。
