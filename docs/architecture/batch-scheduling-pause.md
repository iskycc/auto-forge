# 执行任务暂停与继续调度

任务的一个活动执行批次支持暂停／继续调度。“执行记录”列表、执行详情页提供同名按钮；任务公开执行页也提供控制，继续沿用原公开链接的登录和批次归属校验。暂停只作用于当前批次，不修改任务配置和下次执行。

## 行为与边界

- 暂停请求持久化后停止产生新 assignment。此前已经生成的 assignment（包括待领取）继续领取、执行、续租、上传并保存真实结果。页面在这些执行未结束时显示“暂停中”，排空后显示“已暂停”。
- 未执行和需要重试的用例保留原执行、轮次及重试预算。继续调度只派发剩余工作，不重新执行已经完成的用例，不重新创建批次。
- 可以在排空过程中提前继续。暂停后若全部工作已经完成且没有待重试用例，批次正常进入终态，不保持一个没有剩余工作的暂停批次。
- 暂停期间不裁决 queued 用例的排队超时；恢复后给予待调度用例至少一个完整的批次 `queueTimeoutMs` 窗口，不提前原定的 `scheduledFor`。用例后续重试或下一轮释放若有更晚期限，保留更晚期限。已下发 assignment 的领取、租约、执行和上传超时仍正常裁决，失败重试在暂停期间不会被再次派发。
- 未激活的下一轮和 Jenkins 恢复屏障等待继续调度后再激活。已经激活的 Jenkins 恢复步骤继续按原流程收尾，但不会绕过暂停门派发用例。
- 暂停是可恢复的调度门，不属于执行结果或生命周期终态。终止仍不可逆：暂停中的批次可被终止，终止请求或终态优先，不能通过继续调度重新打开。

## 接口、授权与并发

`POST /api/v1/run-batches/{batchId}/scheduling` 接收 `{"action":"pause"}` 或 `{"action":"resume"}`。必须登录、通过同源保护，并具有批次所属项目的 `run.cancel` 控制权限。跨项目不可见批次返回 404；已结束或正在终止返回 409 / `RUN_BATCH_NOT_ACTIVE`。重复相同操作返回 `changed:false`，不重复写入状态历史。

公开链接使用 `POST /api/v1/public/case-suites/{suiteId}/executions/{batchId}/scheduling?PublisherId=...`，要求有效浏览器登录及有效分享人，只允许控制该任务通过公开入口创建的批次；API Token 不能使用浏览器公开授权。标准页面和公开页面都记录操作人、动作、批次和请求编号的安全审计。

Lite 的 HTTP 入口将变更交给既有执行控制工作线程，使用短 SQLite 保留写事务；Full 复用异步 PostgreSQL 仓储，在与预留相同的批次行锁内更新。候选列表、调度快照、直接调度和最终 assignment 预留均检查暂停门；因此暂停提交前已计算但尚未提交的计划不能绕过暂停。恢复后主动发起一次调度，后台补槽及 Runner 领取仍可恢复未完成的派发，不依赖浏览器维持连接。

## 持久化与升级

SQLite 迁移 `0090_batch_scheduling_pause.sql`，PostgreSQL 迁移 `0088_batch_scheduling_pause.sql`，为 `run_batches` 增加两个可空 UTC 字段：`pause_requested_at`、`queue_resumed_at`。旧批次均为未暂停；不改写执行历史，不批量重写十万级 queued run 的期限。主数据库保存权威暂停门，不依赖 Redis、NATS 或进程缓存；Web／worker 重启后继续读取。

Full 的所有 Web 和 worker 必须同步升级，旧节点不知道暂停门，会继续派发。执行机协议和 Agent 无需改动，无新增运行依赖。迁移是可事务回滚的加法变更，升级前按原流程备份主数据库；DDL 中断回滚后可以重试。回退旧应用前先继续调度或终止全部暂停批次，不能让旧调度器接管仍需暂停的任务；列可保留。

## 验证记录（2026-10-30）

251 项定向回归通过，包含真实 SQLite／PostgreSQL 的调度、完成、重试、跨天恢复派发、轮次及 Jenkins 屏障、原有补槽、权限和两种数据库的迁移升级／失败回滚。Web、服务端、工作线程与测试类型检查，Web／Full worker 生产构建，格式／许可证、受影响 ESLint、E2E 覆盖登记和部署包检查通过。

最终生产构建的两项 Lite Playwright 场景通过：在实际生成分配后暂停，已有分配可继续领取并完成，等待集合不新增派发；排空后保留暂停，继续后只领取剩余用例，原有终止收尾不受影响。公开执行场景使用无项目权限的登录访客，验证授权、暂停／继续、另一浏览器状态同步及原有操作人记录。实际查看了 1024×768、1536×960 的列表、深浅色详情和公开页截图，未见新增错位或溢出。

证据位于 `/var/tmp/autoforge-batch-pause-20261030/`，最终浏览器结果为 `e2e-final.log`。最初的浏览器前置条件未保证已生成分配，随后又误用不含计数的元数据摘要接口；修正为确认实际分配并读取小批次完整详情后，在全新测试数据上重跑通过。没有放宽产品保护、断言或浏览器重试。浏览器场景使用 Runner 协议夹具，不运行真实 JVM；完整 Full 集群、故障注入和离线验收未在本次执行。
