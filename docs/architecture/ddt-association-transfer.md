# SR 测试类关联配置导入导出

入口：**用例管理 → DDT 管理 → SR 测试类关联**。使用“导入配置”“导出配置”“下载模板”。Lite 与 Full 使用同一服务、校验和接口，按当前项目、版本、测试阶段隔离。它与按项目／版本共享的 **SR 标签**是两项独立功能。

## 工作表

首行是表头，保留工作表名称。导出包含以下四个配置 Sheet，另附“说明”Sheet。

| Sheet | 必填表头 | 含义 |
| --- | --- | --- |
| 候选测试类 | 测试类路径 | 候选范围，包含尚未被分类使用的类 |
| 分类执行类 | 需求分类、测试类路径 | 全部分类与执行类，包括尚未绑定 SR 的分类 |
| SR需求分类 | SR、需求分类 | SR 的分类关联；分类留空表示解除该 SR 的现有关联 |
| SR直接关联 | SR、测试类路径 | 兼容历史直接关联；类路径留空表示解除该 SR 的现有关联 |

每个 Sheet 的最后一列“异常说明”用于指出来源不可用测试类、孤立分类或历史冲突。导出不静默过滤问题行；导入前需要修复配置并清空说明。同一 SR 不能同时出现在两个 SR Sheet，不允许同一 Sheet 重复定义同一配置。

通过完整测试类路径、分类名和 SR 名称匹配目标，不使用来源平台内部 ID。先把对应 TestNG JAR 与 DDT 用例导入目标阶段，再导入关联文件；不能凭关联文件创建不存在的测试类或 SR。导出不包含 JAR、用例正文或独立 SR 标签。

## 导入行为

1. 选择 `.xlsx` 文件，点击“预览校验”。文件解析在有内存预算的工作线程执行；最多 16 MiB 压缩文件、256 MiB 实际解压、500,000 行配置和 64 MiB 有效文本。大配置可拆分；不将表格放进主 HTTP 线程同步解析。
2. 预览列出各类行数，最多 20 行样本与 100 项定位问题。未知 SR／类、错误表头、公式、重复配置、额外列、来源异常说明都会阻止导入；固定文本如前导零、中文或以 `=` 开头的普通字符串保留为文本。
3. 确认时再次解析并核对文件和目标配置指纹。发生变化返回新预览，需重新确认，不会使用旧预览覆盖刚更新的关联。
4. 先加入需要的候选测试类，再保存分类，最后绑定 SR。按名称**合并覆盖文件中列出的配置**，未列出的既有配置保留；空白 SR 关联列表示解除关联，不表示删除 SR 或其用例。候选范围不会因文件中缺少某个类而自动移除。
5. 逐项使用既有事务和修订条件保存，显示实际进度。取消、并发修订冲突或连接中断时，已保存的变更保留；错误说明已处理数量和位置。重新预览后幂等导入，已一致的项会显示复用。跨整个文件的导入不是单个长事务，不能宣称失败时整份回滚。

导出使用流式 Excel 生成和有界仓储分页，生成完毕后复核源配置指纹；期间变化则拒绝下载并提示重新导出，避免提供混合修订。超过 Excel 可表示的单元格／行数时明确报错。正常导出包含全部四类配置，不受页面搜索或“仅显示未关联 SR”筛选影响。

## API 与权限

- `GET /api/v1/ddt/association-config/export?projectId=...&projectVersionId=...&testStageId=...`，`template=1` 下载空模板；需要当前项目 `case.read`。
- 同一路径的 `/import?action=preview` 使用 multipart 字段 `file`；需要 `case.manage` 和同源保护。
- `/import?action=import&fingerprint=<预览指纹>` 确认导入，仍上传同一文件；返回 NDJSON 进度流。HTTP 200 只表示流已开启，必须收到 `completed` 事件才算导入完成；`failed` 或断流按部分完成处理。

导入开始、完成及中断记录授权审计。没有新增数据库迁移或生产依赖；需要同步升级 Full Web 与独立 worker，确保解析协议一致。
